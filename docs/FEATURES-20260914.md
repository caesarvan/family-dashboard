# 日程视图、采购与资产基线

## 展示与数据口径

- 今日是初始视图；本周从周一到周日；前后 3 天包含当天共 7 天。日期统一北京时间，跨午夜按每日实际交集统计，结束时间不包含在下一个日期内。
- 日程数量覆盖全部可见日历；忙碌时长是侧重成员与共同安排的时间并集，全天安排单独标记。并不声称覆盖未选择的工作日历。
- 个人设备记住本账号的视图；每台电视独立保存在 devices.calendar_view。手机更新设置时递增 revision，电视下一轮刷新应用。电视全程只读，超出三项自动分页、长日程自动滚动。
- 采购 budget/actual 单位为整数分，未知为 null。photoIds 最多三项。勾选不会产生财务交易；采购汇总与荷包核对各自保留含义。
- 财务基线仅导入已经批准的来源版本，保存数据日期、来源摘要、完整度。不同日期的人民币已记录小计不等于实时完整资产/负债；不把缺失房产估值、未确认转入余额、未归属收入或未换算外币当作零后计算净资产。
- 用户同意共享资产及负债汇总。账户、收入、消费摘要仅本人 GET /api/finance-baseline/private 读取。共享接口两次应用严格字段白名单；本月私有收支与公共荷包不会被导入过程覆盖。

## 运维

Pillow 解码后重新输出不带 EXIF/GPS 的 JPEG，最长边 1600。浏览器原始文件最多 20 MB，发送前压缩。服务器仅接受 JPEG/PNG/WebP、输入最多 5 MB、400 万像素，单进程仅允许一次解码；忙时返回可重试提示。所有采购图片最多 500 张且累计 200 MB。

图片存储在 SQLite photos 表，photo_refs 与实体同事务维护。未保存图片仅上传者可查看，附加到采购后可由家庭成员与配对电视读取。解绑最后一项引用后收回共享权限；超过 24 小时的无引用图片在下一次上传时清理。图片 API 仍需登录和写入 CSRF，GET 不缓存。Nginx 请求上限 8 MB，Flask 除图片上传外保持原 600 KB 限制。

SQLite 在线备份同时覆盖照片与财务基线，现有 14 份备份策略不变。若照片达到上限，单份数据库可增至约 200 MB，14 份照片备份约 2.8 GB，需持续保留磁盘余量。源财务文件与本次导入 JSON 均不打入发布包、不进入 static。

导入脚本接受标准输入 `{private,shared}`，可使用容器内 `python -m finance_baseline --database /data/household.sqlite3`。先在线备份；通过安全标准输入或受保护临时文件传递 JSON，不在终端回显。导入验证 owner、来源摘要、币种、日期、逐项汇总及完整度；相同有效内容重复导入不修改数据或 revision。只更新 finance_baselines 与共享状态版本，不改其他实体或公共/个人月度财务。导入结果仅输出状态与记录数。

## 验证入口

- `python -m pytest -q`：原有授权、同步、CRUD 回归，以及图片、私有财务隔离和两台电视偏好。
- `node --test tests/test_calendar_views.js`：时区、日期边界、重叠时长及轮播覆盖。
- `python tests/browser_features_check.py`：临时数据库 + 真实 Flask + Edge，测试上传保存、三方隐私、日程切换和 720p/1080p/4K 三种视图排版。
- `python tests/browser_calendar_check.py`：静态虚构日程，包括每天 10 项长标题的电视自动展示。
- `python tests/shopping_ui_check.py`：虚构 API 下的金额、失败草稿保留与图片交互。
