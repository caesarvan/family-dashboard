# 电视显示设置：操作、接口与隐私

**已于 2026-09-15 09:47:39 发布。** 本文记录电视卡片顺序、显示开关、主题和密度的扩展契约，保留既有配对、侧重成员和日程视图。实际组合验收见 [README](../README.md) 与 [VALIDATION](VALIDATION.md)；临时浏览器不替代实体电视、公网、遥控器或长期常亮验证。

2026-09-17 设备会话加固为本地候选，尚未发布：配对批准、列表读取、设置保存和撤销重新核对真实成员会话，配对码只允许一次批准；接口与既有 55 张业务表保持不变。本文首段日期记录此前显示设置发布，不代表本候选已上线。

手机与电脑负责设置，电视保持只读。两块屏幕分别保存自己的配置；同一家庭的两位成员均可管理家庭中的电视，不按首次配对者划分设备所有权。电视设置与成员自己的“主题与显示”“首页卡片布局”分别保存。

## 1. 操作路径

1. 在手机或电脑登录正确的家庭，从“连接中心 → 管理显示设备”或“设置 → 管理电视”打开设备列表。
2. 没有设备时，先在电视打开 `/tv`，在手机点击“连接第一块电视”，输入电视显示的配对码。已有设备直接点击相应电视的“显示设置”。配对步骤见 [使用手册第 8 节](USER-GUIDE.md#8-为两块电视分别配对)。
3. 核对电视名称、侧重成员和日程范围，用每张卡片的上／下移按钮调整顺序，勾选要显示的卡片，再选主题和密度。至少保留一张卡片；右侧 16:9 预览只画示意内容，不读取个人财务。隐藏不会删除事项或财务记录。
4. 检查草稿后点击“保存到这台电视”。编辑器读回服务器配置后才提示保存成功；电视下次成功轮询共享状态时应用设置。正常前台轮询间隔约 10 秒，网络断开、浏览器后台或电视休眠可能延迟。“恢复默认布局与外观”只重置布局草稿，保留电视名称、侧重成员和日程范围，仍须保存。
5. 两台电视分别操作。例如一台侧重成员一、以本周日程为主，另一台侧重成员二、优先显示待办和采购。某台电视的设置不会覆盖另一台，也不会修改成员手机或电脑的首页布局。

“本周”为周一至周日；“前后 3 天”含今天共七天。现有看板按 `Asia/Shanghai` 分天和显示时间，本增量不切换旅行目的地时区。“侧重成员”影响现有日程和清单的优先显示，不授权访问该成员的私有账本或投资。

若另一位成员已经保存同台电视的设置，旧版本保存返回 409。点击“读取最新设置”不会替换草稿，再选择“采用最新设置”或“用最新版本保留我的草稿”；保留草稿后仍需再次明确保存，会整体替换该台电视的显示设置。网络失败不能据此认定写入没有发生；重新读取核对。返回电视列表时，未保存修改需要明确放弃，不能因返回就算已保存。设备已撤销或配对过期时，需要重新配对，不能用旧设备 ID 恢复访问。

编辑器按原成员／家庭／CSRF、原弹窗节点和草稿快照约束异步响应，读取和保存前后核对会话。最终 68 项专项已验证原表单与身份保护，范围见 [验收记录](VALIDATION.md)；电视演示使用虚构数据，不能保存为真实设备设置。

## 2. 数据模型与默认值

仅在已有 `devices` 表新增 `display_layout` JSON 文本列，不新增业务表。设备行继续保存配对状态、截止时间、名称、侧重成员、日程视图和 `revision`。该版本不新建独立的电视布局表，也不复用私有 `member_dashboard_layout` 或 `member_preferences`。

对外字段名为 `layout`：

```json
{
  "order": ["calendar", "finance", "tasks", "shopping", "trips"],
  "hidden": [],
  "theme": "forest",
  "density": "comfortable"
}
```

| 字段 | 约束 | 默认值 |
|---|---|---|
| `order` | 五个已知卡片键的完整排列，每项恰好一次；不能省略、重复或添加自定义键 | 上方顺序 |
| `hidden` | 已知卡片键的唯一子集，最多四项，至少一张可见 | `[]` |
| `theme` | `forest`、`light` 或 `ocean`；电视编辑器显示为森林、晴日、海岸 | `forest` |
| `density` | `comfortable` 或 `compact`，分别对应舒适、紧凑 | `comfortable` |

五个键对应日程安排、家庭财务、共同待办、采购清单、下一趟旅行。隐藏的卡片仍保留在 `order` 中，重新显示时使用其保存位置；服务端将 `hidden` 按 `order` 的顺序规范化。`layout` 是完整对象：显式提交时四个字段都必须提供，不允许额外字段；不能只提交 `{"theme":"light"}` 进行嵌套合并。

旧设备的 `display_layout` 默认原文为 `{}`，读取时得到完整默认布局；存量无效 JSON 也只回退显示值，不修改原行。省略 PATCH 的 `layout` 精确保留存储原文，因此旧版客户端仅改名称、侧重成员或日程视图，不会把新布局重置。新请求仍严格校验，不会把非法布局静默改成默认值后保存。首次配对继续使用原请求字段；`POST /api/pair/approve` 忽略额外 `layout`，保留默认布局，不会按该字段自定义或因它额外报错。先完成配对，再通过显示设置修改布局。

## 3. 身份与请求约定

使用既有 `/api/devices`、`/api/devices/<id>` 和 `/api/state`，不新增 HTTP 路由。设备管理要求当前家庭的有效成员会话。配对批准、PATCH／DELETE 均要求 JSON、有效 `X-CSRF-Token`，并遵循现有同源校验。候选实现对三个写接口在取得 SQLite 写锁后和提交前核对真实会话的 ID、成员、认证版本、到期／撤销状态与家庭；GET 列表在读取快照内及释放快照后核对会话，失败不返回设备列表。成员不能用请求中的 `owner` 或家庭 ID 选择其他人的身份或数据库。

电视通过既有配对凭据成为 `tv` 角色，只能读取允许的共享接口。电视页面发送 `X-Display-Mode: tv`，防止同一浏览器残留的成员登录被当作电视管理权限。访问 `/tv` 本身不会赋予成员写权限。

所有下列 ID、名称、日期和版本都是虚构示例，不是生产记录或凭据。

### POST `/api/pair/approve`

沿用 `code`、可选 `name`／`focus`／`calendarView`，成功仍返回 `{"ok":true}`。在同一写事务中读取并有条件消耗尚未到期、未批准的配对码，批准与审计一起提交。两个成员并发批准同一码至多一个成功；已消耗或到期的码仍返回 400，不能用旧码更改首次批准的设备配置。批准不接收布局写入，后续显示设置使用 PATCH。

### GET `/api/devices`

返回当前家庭尚未到期、已经批准的设备数组。没有设备时为 `[]`，不返回未批准的配对请求。已有字段保持，新增规范化 `layout`；不返回配对秘密、秘密散列或 Cookie。

```json
[
  {
    "id": "demo-tv-01",
    "name": "示例客厅电视",
    "focus": "member1",
    "calendarView": "week",
    "revision": 4,
    "created_at": "2026-09-15T08:00:00+08:00",
    "layout": {
      "order": ["calendar", "tasks", "shopping", "finance", "trips"],
      "hidden": ["finance"],
      "theme": "forest",
      "density": "compact"
    }
  }
]
```

`focus` 沿用现有成员／共同选项，`calendarView` 为 `today`、`week` 或 `around`。`revision` 是整台设备配置的并发版本，不是独立布局版本；不要把 `created_at` 当作布局更新时间。

### PATCH `/api/devices/<id>`

提交 GET 读到的 `revision`，必须是大于等于 1 的整数，字符串或布尔值均不接受。名称、侧重成员、日程视图继续可选；本增量新增可选 `layout`。显式提供布局时整体替换四个字段，其余未提供的设备字段保留。

```json
{
  "revision": 4,
  "layout": {
    "order": ["tasks", "calendar", "shopping", "trips", "finance"],
    "hidden": ["finance"],
    "theme": "ocean",
    "density": "compact"
  }
}
```

兼容旧客户端的名称修改：

```json
{"revision": 4, "name": "示例书房电视"}
```

成功响应沿用：

```json
{"ok": true}
```

随后 GET 设备列表读回新版本和配置。一次成功修改在同一事务内更新设备、递增设备 `revision`，写入 `update_device` 审计并增加共享 `settings.meta` 版本。电视下次读取 `/api/state` 时据此重绘。布局保存不创建日程、待办、采购、旅行或云端同步任务。

### GET `/api/state` 的 `display`

有效电视请求的共享状态增加自己的 `display.layout`，仍保留侧重成员与日程范围。下例只展示响应中的 `display`，完整响应还有现有共享实体、公共财务、共享资产负债摘要与同步状态。

```json
{
  "display": {
    "calendarView": "week",
    "focus": "member1",
    "layout": {
      "order": ["tasks", "calendar", "shopping", "trips", "finance"],
      "hidden": ["finance"],
      "theme": "ocean",
      "density": "compact"
    }
  }
}
```

`layout` 只在有效 `tv` 角色的这段响应中返回；成员请求的 `display` 不含该字段。它不代表成员自己的首页偏好，也不是其他电视的布局列表。客户端应以实际 `tv` 身份和服务器返回设置显示，不能从手机的本地偏好推断电视配置。

电视的 `display` 与用于重绘的顶层 `revision` 在同一个户内 SQLite 读取快照内获取。接口会在该快照内重新核对设备批准状态与有效期，不直接使用请求鉴权阶段较早读到的布局，避免返回旧布局却配上新版本号。若鉴权后、读取前已经撤销设备，则拒绝返回共享内容。此约定不表示第三方同步摘要或各家云服务属于同一个事务快照。

### DELETE `/api/devices/<id>`

沿用现有撤销接口：成员提交 JSON `{}` 并携带 CSRF。删除配对设备后，原电视凭据不能再通过服务器验证，下一次共享状态读取返回 401；重新显示需要新的配对流程。本增量不改成员登录设备 `/api/sessions` 的撤销规则。

### 错误与恢复

| 状态 | 含义与处理 |
|---|---|
| 400 | 新布局不完整、包含未知／重复卡片、全部隐藏，或版本类型／主题／密度／其他设备字段无效；修正草稿再保存 |
| 401 | 没有有效成员／电视身份，或配对已撤销／到期；管理端重新登录，电视重新配对 |
| 403 | 电视调用成员管理接口、CSRF 不符或来源不允许；不降级绕过 |
| 404 | 当前家庭没有该有效设备，或 PATCH 时配对已过期；重新读取列表 |
| 409 | 设备版本已经改变，或并发修改使条件更新失败；重新读取并明确处理冲突 |
| 415 | 管理写请求不是 JSON |
| 503／网络失败 | 请求或读回暂不可用；不宣称保存成功，恢复连接后核对最新列表 |

错误响应沿用 `{"error":"可读说明"}`，不保证上表情形的提示文案永远相同。跨户设备 ID 在当前户查询不命中，不泄露另一家庭的设备内容；撤销接口保持既有幂等语义，不凭响应判断别户是否存在同名 ID。

## 4. 隐私与数据副本

**隐藏卡片只是显示设置，不是服务器数据权限。** `/api/state` 仍按既有规则返回整份允许的家庭共享状态，不因 `hidden` 删除其中相应字段。因此不能用“隐藏家庭财务”代替撤销不受信任电视的访问。

电视可看到公共资金和双方已明确共享的资产／负债汇总，以及本家庭共享日程标题、地点、待办、采购与旅行。它不能访问个人消费明细、私有账户、投资持仓、个人来源快照、授权令牌或成员会话列表。侧重某位成员、切换主题或改变密度不会扩大此权限。

卡片排序和主题只接受固定值，不支持外部页面、脚本、图片 URL 或任意组件。设备名称等文本仍经过现有输出转义；布局不是用于上传或执行自定义代码的入口。

个人 ZIP 的白名单不读取 `devices`，因此不包含电视布局、配对凭据或设备秘密散列；`includeShared: true` 也不会附带这张认证设备表。成员自己的首页布局和偏好仍按原有个人副本契约导出。完整管理员 SQLite 备份包含 `devices` 及新列，恢复须遵循 [部署与恢复](DEPLOYMENT.md) 和 [成员会话恢复约束](MEMBER-SESSIONS.md#发布回滚与恢复)，不能把个人 ZIP 当作设备恢复备份。

布局修改不会刷新配对有效期，也不会改变既有云账户授权、共享基线或其他设备。撤销在服务器阻止后续访问，不能远程抹去电视此前已经显示或缓存的共享内容；离线屏幕可能继续显示最后一次成功读取的内容。

## 5. 兼容、并发与维护检查

本版本的 `initialize()` 使用 `BEGIN IMMEDIATE` 保护设备兼容列的检查与补列，旧设备的 ID、秘密散列、批准状态、到期时间和既有设置保持。此处不意味着整个应用所有模块初始化共用一个事务；并发初始化的实际结果仍需看专项测试。部署继续先停旧写进程、备份、串行预热，再启动新服务。

设备修改在 `BEGIN IMMEDIATE` 内读取当前有效设备，再以整行 `revision`、批准状态和到期时间作条件更新。两成员同时修改同台电视，只能由当前版本成功；过期版本不能覆盖名称、侧重或布局。批准、更新和撤销均与审计／meta 递增一起提交；异常完整回滚，撤销失败也保留原播放状态与照片许可。等待写锁期间的成员撤销、认证版本变化，以及提交前的会话到期均拒绝写入。PATCH 没有插入设备的路径，不能重新创建已撤销行。

新列兼容现有读取者并不等于任意版本可直接接管新数据库。完整回滚还需核对成员会话及 OAuth 等既有迁移，按相配恢复组操作，不单凭此列为可选字段就跳过回滚审查。

| 检查范围 | 契约与验证边界 |
|---|---|
| 旧库与默认值 | 补列不丢设备；旧设备显示默认布局；重复初始化和两连接竞争不重复补列 |
| 布局校验 | 完整排列、未知／重复／漏项、全部隐藏、类型错误和主题／密度枚举；坏请求不修改行或 meta |
| 更新兼容 | 省略 layout 保留原值；显式四字段替换；旧 revision 409；同台并发最多一个成功；鉴权后配置变化时 display／meta 同快照读取 |
| 权限与生命周期 | 两成员可改本户设备；TV／匿名拒绝管理；跨户不可访问；撤销或过期后旧凭据失效 |
| 只读呈现 | 五卡片顺序、隐藏、主题和密度按设备应用；成员个人偏好与另一台屏幕保持独立；隐藏不冒充 API 过滤 |
| 编辑异步 | 保存前核对原身份／家庭／CSRF；迟到列表、成功或错误不能接管新表单；409 与读回失败明确可恢复 |
| 副本与业务 | ZIP 不含设备表；共享内容和私有财务权限不扩大；布局保存不触发第三方调用或业务记录创建 |
| 实体与运行 | 两台 50／75 英寸电视、真实分辨率、遥控器、休眠唤醒和长期常亮另行验收 |

本次本地候选实际执行 `test_device_sessions.py`、`test_tv_display.py`、`test_app.py`、`test_media_playback.py`、`test_member_sessions.py`：196 项通过，其中 30 项新增会话与配对专项。使用临时真实 SQLite、成员登录、双连接写锁竞争、并发批准与审计触发器异常；未调用真实云或测试实体电视。接口成功仍须客户端读回核对，网络失败或后续身份校验失败不能证明此前提交未发生。

后端布局白名单和默认读取位于 [tv_display.py](../tv_display.py)，路由与事务在 [app.py](../app.py)。前端 [tv-display.js](../static/tv-display.js) 提供 `window.TVDisplay.openDevice(id)` 进入编辑器，`window.TVDisplay.applyBoard()` 在电视共享看板重绘后应用布局；它不替代成员登录、配对或共享状态接口。

最终组合已完成 Windows/Linux 960 项后端收集和受影响浏览器验证，其中新电视专项 68 项；配对 35 项、成员首页布局 11 项，工作台另有 59 条页面/视口记录。上述代码和测试均在冻结源码核对；服务器已验证旧设备行/旧列保留、新列默认值及内部资源。真实设备和外部平台仍单独验收，未以真实配对码、财务输入或新增云写作为测试。精确结果见 [VALIDATION](VALIDATION.md)。
