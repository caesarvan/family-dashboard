# 成员相册视频

视频读取繁忙时，详情页保留当前位置，显示「视频正在读取，请稍后点击播放重试」。只有再次点击才重新读取，不会自动重复下载、跳到其他媒体或要求重新授权。客户端仅识别固定 `503 / video_busy / Retry-After: 1` 契约，错误正文最多读取 1024 字节，不展示服务端原始错误内容；每次重试仍完整核对身份与媒体权限。

本批是成员界面候选，包含普通相册与只读旅行相册，尚未部署。后端视频导入、加密缓存和播放接口需与对应已审分支组合；本提交不增加依赖、不改电视播放器或服务端策略。

## 使用

从相册进入 Google Photos 选择，仍只处理本次明确选择的内容。视频与照片一样先显示封面与处理结果；勾选「保留此视频」，同意持久保存照片或视频展示副本后，才确认保存到私密相册。源视频最多 100 MiB／十分钟，超限或不支持会给出原因，不截断冒充成功。

已保存的视频在卡片显示时长与有无声音；打开详情后点击「播放视频」，完成读取和权限核对后，使用浏览器原生播放控制。未确认内容只显示 JPEG 封面，不提前下载播放。普通相册原有说明、旅行关联、私密／共享、逐电视许可及移除操作保持。旅行相册只供回看，不增加管理权限。原生 App 暂只展示封面并提示从手机或电脑浏览器播放；未引入原生视频依赖。

保存继续使用原 import revision、媒体 ID 集合和同一个 `confirmRequestId`。网络结果不明不会自动重发、建立新回执或宣称保存成功；确认后仍默认私人，家庭共享和电视展示须另行明确选择。Google 原始照片和视频保留。

## 接口与停止播放

`Photo` 增加可选 `mediaType: photo | video`，缺省视为旧照片。视频必须带整数 `durationMs`（1～600250）、布尔 `hasAudio` 和精确同源 `/api/media/items/{id}/video`。`previewUrl` 保持 JPEG 原路径。旅行相册仅额外投影四个已验证视频字段，仍剥除来源账户和文件名。

`MemberVideoPlayer` 只在明确点击后用 `PhotoReadFence` 读取：`/me → 当前原 ID 详情 → 完整 MP4 → 当前原 ID 详情 → /me`。前后详情必须保持同一 ID、revision、视频类型与路径，完整身份包括家庭、成员、auth version 和 CSRF。两次核对通过后才创建 Blob URL。服务端视频 GET 无 revision 查询参数，后端内部仍须双重核对 revision、cache key 与 ACL。

fetch 限同源、禁止重定向、`no-store`，不使用 Range；必须为完整 200／`video/mp4`。逐块累计最多 64 MiB，有 Content-Length 时同时核对实际长度；不接受 HTML、部分响应、空体或截断体。单次读取最多 120 秒，身份／详情请求沿 20 秒超时，可取消。

播放时每五秒重新读取当前权限与版本，失败、撤权或版本变化停止，不能从旧 Blob 恢复。离线、页面隐藏、页面卸载、身份变化或父页面禁用时，中断在途读取、暂停视频、清除 src 并 revoke Blob；迟到结果不能重新创建播放地址。React 移除 DOM ref 时先暂停元素，避免仅回收 URL 而残留声音。恢复在线后仍需本人重新播放。轮询发现远端变化存在间隔及请求耗时，不能声称撤权能即时收回已交付的像素。

## 组合与验证

发布组合需要单一服务端负责人增加窄 CSP `media-src 'self' blob:`；本分支不修改 CSP。浏览器视频必须与实际后端视频 DTO、加密存储及授权接口组合验证，不将本地组件测试当作真实 Google 媒体或电视播放验收。

定向 `frontend/tests/memberVideo.test.mjs` 使用真实组件处理器及原 `PhotoReadFence`，仅替换网络传输和 UI 渲染环境。覆盖旧照片兼容、四字段旅行投影、完整流边界、同确认回执、明确点击、身份和版本前后变化、播放中撤权、隐藏／离线／卸载释放以及原生提示；相邻原照片和旅行相册测试保持各自范围。作者报告保留两组 TypeScript 检查和各轮原始日志，不替代新 Expo 导出、实际浏览器解码或设备验证。
