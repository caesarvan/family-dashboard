## A：家庭旅行协作

**目标链：** AI 或文件输入 → 保存行程 → 地图 → 准备任务与成员分工 → 采购 → 指定日历 → 改期协调 → 实际状态。

1. 从家庭助理进入旅行简报，在旅行计划手动新建，或点「导入旅行」选择／粘贴 JSON；核对日期、预算、准备及采购后预览并确认。
2. 在详情维护行程分段和旅行地点；地点默认私人且为已计划，只有本人明确确认才能成为已到访。
3. 从详情进入「同步到日历」，选本人来源并核对写权限；需要联动改期时使用「调整日期」逐项预览。
4. 返回原旅行核对准备、采购和日历状态；“已加入同步”与“外部已确认”须分别记录。

结构化 JSON 文件导入已迁入 Expo「旅行 → 导入旅行」，经典入口仍保留。R2 12 组真实临时浏览器与实际 Linux 287 通过／1 精确跳过分别记录，见[导入发布验收](EXPO-TRIP-IMPORT-ACCEPTANCE.md#expo-trip-import-release)。

**已有验证：** 旅行保存、准备／采购分工、地图往返、分段编辑和日期协调已有独立真实临时 API／数据库／浏览器验证，
包括并发修改、响应丢失、原请求恢复和保存后重读。指定模型已有真实请求证据，云发布采用合成提供方验证。
证据：[旅行简报](EXPO-TRAVEL-ACCEPTANCE.md)、[地点与日历](EXPO-TRIP-COORDINATION-ACCEPTANCE.md)、
[改期](JOURNEY-RESCHEDULE-ACCEPTANCE.md)、[分段编辑](EXPO-JOURNEY-SEGMENTS-ACCEPTANCE.md)。

**仍未验收：** 同一趟本人旅行从在线 AI／输入到真实云日历创建、改期及最终状态的完整链。
已有云来源读取不证明授予写权限；人工预订／取消标记也不证明航司或酒店操作成功。
下一次需在本人允许的环境中选定旅行和目标日历，保留外部事件标识、实际改期结果及失败恢复记录。
缺写授权的步骤保持未验收，手动计划和本地任务仍可使用。

## B：财务导入与对账

**目标链：** 账单及订单 → 解析预览 → 校验去重 → 保存 → 订单／退款关联 → 预算 → 同文件重传 → 首次来源追溯。

1. 在「家庭资金 → 导入账单」选来源和文件；按需选工作表、金额列，或对通用表格手动指定日期／金额／标题／币种四列；先处理错误行与冲突，再明确确认。
2. 到实际入账月份打开交易详情，核对原币金额和首次来源；明确关联订单、付款、退款或重复记录。
3. 查看同币种月预算，再导入同一文件核对不重复记账；个人明细默认不共享，也不会自动改公共余额。

**已有验证：** Expo 财务 21 组真实临时浏览器覆盖合成文件到预算、持久回执、重启、权限及迟到响应。
来源报告、来源更新、持仓和手动资产／负债账户亦已分别发布；其独立结果不是上述整条链的新增通过数。
证据：[财务操作与验证](EXPO-FINANCE.md)、[来源报告](EXPO-BASELINE-ACCEPTANCE.md)、
[来源更新](EXPO-FINANCE-SOURCE-ACCEPTANCE.md)、[手动资产账户](EXPO-FINANCE-ACCOUNTS-ACCEPTANCE.md)。

**仍未验收：** 按具体平台的真实脱敏账单／订单核对行数、金额、退款和重复规则。
通用来源四列手动映射已发布，R2 六组本地流程与服务器 496 通过／1 项精确 Windows 跳过分别记录，见[本批验收](FINANCE-COLUMN-MAPPING-ACCEPTANCE.md)；它不等于任意字段映射或整条 B 链已验收。第三方机构连接及持续自动刷新仍未实现。本人账户分析与明确更新的 ECB 参考汇率已发布，趋势、资金进出／汇率影响／估值残差的范围见[本批验收](FINANCE-ANALYSIS-ACCEPTANCE.md)；该残差不是交易收益，本轮也不替代 B 的真实平台文件验收。
下一次先选一个支持格式的脱敏平台样本，记录预览、入账、再次导入和来源追溯结果；格式不支持时明确保留缺口。
资产日期仍是估值／来源覆盖日期。分析趋势使用同一明确选中的账户集合，并标出沿用估值与金额／汇率缺口，不称完整历史净资产。

## C：旅行相册与电视回顾

**目标链：** 实际可用来源 → 授权媒体 → 建议旅行 → 本人确认要展示的内容 → 关联地点地图 → 电视播放 → 私密及撤销检查。

1. 在家庭相册从 Google Photos 选择并预览，明确保存副本；本人照片详情可「查看旅行建议」并明确确认关联，未知时间或无匹配仍可手动关联。
2. 核对旅行和地点；从足迹地图查看关联旅行、照片，或在旅行详情打开只读回顾。
3. 只有决定展示时才设置家庭共享、勾选具体电视并明确许可，再从「电视与播放」控制已配对设备。
4. 改回私密或撤销许可后，核对后续读取和播放受限；配对本身不授予相册访问权。

**已有验证：** 本人 Google Photos 曾实际完成 5／5 预览保存；地图相册、许可／撤销和 Expo 电视控制有独立临时环境证据。
单趟回顾 R2 的 10 组通过、12 图可见区域已核查，范围仅当前行程、本人可见地点和授权照片。
证据：[媒体交付](MEDIA-DELIVERY.md)、[地图](EXPO-MAP.md)、[旅行回顾](EXPO-TRIP-RECAP-ACCEPTANCE.md)、[电视](EXPO-TV-ACCEPTANCE.md)。

**仍未验收：** 本人同一批照片从旅行关联、明确选择到实体电视播放并撤权的完整链。
用户当前无实体电视可测，保留该缺口，不重复索要设备；临时电视身份／浏览器不能替代物理屏幕验收。
一个已授权来源和手工选择可构成首个闭环，不必先实现自动精选；自动精选、那年今日、路线、视频、iCloud／NAS仍是另外的未完能力。
旅行建议不自动共享、许可电视、推断拍摄地点或认定到访。

## D：多用户隔离与协作

**目标链：** 两家庭分别登录 → 跨户读取失败 → 同户按权限协作 → 私有数据不自动共享 → 撤权后服务端访问受限。

1. 使用各自家庭入口登录；在同户成员间明确共享任务／计划或选定对象，财务和私人媒体保持本人可见。
2. 用另一家庭及本户另一成员分别核对对象、下载和后台结果；仅看页面隐藏不足以证明隔离。
3. 管理员可在「更多 → 家庭与成员」明确调整另一人的角色或撤销其当前浏览器会话；本人登录设备、来源及对象许可仍使用各自入口，再核对后续服务端请求及旧页面迟到响应。

**已有验证：** 每户独立数据库和签名上下文；以下两位固定成员验证为早期版本。后续个人账户、邀请加入／退出与多家庭切换已在 [R3 成员发布](MEMBERSHIPS-RELEASE-R3.md) 激活，原四组真实临时浏览器及冷恢复分轮证据分别保留。地图、媒体、库存和个人财务已有分模块双户／双成员验证。
现有两位成员初始化为共同管理员，基础角色和管理会话已经激活；邀请创建新家庭已有实现，不等于加入已有家庭的通用成员系统。
另有同一临时环境的独立 D 连续链实际 6／6：两家庭同 ID 的私有账户、照片、地点、PDF → 明确共享 → 撤销两个目标会话 → 旧 cookie 的 18 次读／2 次写均 401、迟到图片不回显 → 重新登录后数据保留。3 张图经 Root 实际视查，仅覆盖可见视口；该脚本不在成员发布包内，不与成员 7 组或服务器数量累加。
证据：[成员发布验收](EXPO-HOUSEHOLD-MEMBERS-ACCEPTANCE.md#household-members-release)、[家庭隔离连续链](HOUSEHOLD-ISOLATION-CHAIN.md)、[家庭空间](PLATFORM.md#多家庭隔离)、[成员会话](MEMBER-SESSIONS.md)。

**仍未验收：** 真实本人注册、邀请加入／退出及跨家庭连续操作，另有外部设备验证缺口。通用用户／成员关系及切换已实现并发布；独立集中链使用合成数据和媒体，不能代替本人实际环境。
成员功能不再作为实现缺口；已有微软绑定和电视缺失均不阻止内部协作验证。已有请求的事务与撤销边界按模块记录，不承诺所有在途请求都被取消。

## 下一份验收记录应包含什么

- 同一个场景、所用版本、合成或真实来源、操作者和设备范围；不记录凭据、私人文件内容或完整财务数据。
- 每一步的实际保存／重读、权限与恢复结果；外部步骤附可核对结果，不用“队列受理”代替云端成功。
- 未完成步骤及原因，保留失败原件；更新对应集中验收页后再改变本索引的结论。
- 展示与入口已经可用，不代表所有目标完成；完整后续范围仍以 [产品计划](PRODUCT-PLAN.md) 为准。
