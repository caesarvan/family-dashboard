# 本人手动资产账户浏览器验收

脚本 [browser_expo_finance_accounts_check.py](../tests/browser_expo_finance_accounts_check.py) 在
`5de5e999711a71709307c36a114593c6aba3a1e3` 的已审 API、UI 与接线组合上编写。
脚本经非作者审查后已执行 R1／R2 两轮：R1 功能通过但桌面备注标签重叠；
修正后 R2 的 12 流程与 12 图通过，详见 [完整验收](EXPO-FINANCE-ACCOUNTS-ACCEPTANCE.md)。

实际验收包含 12 个独立流程，每组使用自己的真实临时 Flask、SQLite、HTTPS loopback 和 Edge：

1. UI 创建未知／明确零账户，刷新、重启后端、同成员另一浏览器读取；其他财务表不变。
2. 日期估值、未来记录排除、同日纠正、未知不回退旧金额，实际 51 条历史第二页。
3. 明确归档／恢复、当前状态筛选、原历史保留及逐币种已知净额／全未知提示。
4. 真实 409 保留草稿，读取最新后分别采用／保留，再明确保存；冲突和选择阶段零业务写。
5. 提交成功后丢响应，精确 GET 或原编号原请求重试；新会话历史回执不能覆盖当前资料。
6. 请求未到服务器，`found:false` 保持未知；核对列表后二次确认结束，不自动创建替代账户。
7. 明确保存成功后丢当前 GET，旧详情／操作失效，手工读取恢复且不重复写入。
8. 真实伴侣、第二家庭、配对电视和匿名边界；电视不挂载成员面板。
9. 已提交响应交付前切换真实成员 cookie，旧资料／草稿不进入新身份，原本人仍可查回执。
10. 模拟隐藏与浏览器离线隐藏私密内容，保留同身份草稿，恢复时变版必须核对。
11. 全局导航保护草稿／未知；明确返回保留账本月份和不透明编号，重新进入只读恢复。
12. 320／390／1280／1920 四宽，浅色编辑和深色紧凑列表／详情共 12 张稳定截图，
    长文本、列表分页搜索、实际触控尺寸与键盘单次保存。

辅助数据通过真实 API 写入，未知和冲突通过丢弃／延迟真实 HTTP 或独立真实写入制造，
不替换成功业务 DTO、不改 DOM 业务内容。继承现有 finance `BaseRun`，不修改公共 fixture。
每组独立关闭浏览器上下文、服务和临时目录；一组失败仍继续其他组，任何失败、外网请求、
页面错误或清理失败都使整轮失败。失败截图／ARIA／异常堆栈 与所有轮次原件保留，不将部分成功相加。

运行参数为 `--source-root`、`--expected-head`、`--bundle`、`--expected-build-evidence`。
使用主仓虚拟环境 Python `-B -X utf8`。执行前后核源码全部 tracked 文件、导出与构建输入、
脚本／finance fixture SHA、HEAD／tree／干净状态；结果写本分支 ignored `test-results/`。
截图仅覆盖滚动后可见区域，需独立视觉查看；不外推全部内层滚动、实体设备、真实本人财务、
银行连接或长期使用。55→58 迁移、导出接线、部署与服务器保护由独立专项验收，脚本不执行这些阶段。
