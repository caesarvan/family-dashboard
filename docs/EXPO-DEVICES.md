# Expo 电视与播放

本轮源码候选，尚未上线。新增 `/app/devices`，从「更多 → 电视与播放」或相册页进入；保留真实电视浏览器 `/tv`。当前部署身份仍以根 README 为准。

## 家庭中的操作

1. 在电视浏览器打开本站 `/tv`。它显示短期配对码；手机在「电视与播放」输入该码，给屏幕命名并选择侧重成员与日程范围。
2. 两块电视各自保存名称、侧重成员、今日／本周／前后 3 天，以及卡片顺序、显示开关、密度和电视主题。至少保留一张卡片；设置不会改写家庭事项或成员手机布局。
3. 在相册保存照片，明确设置家庭共享，再单独允许指定电视展示。开始播放不会自动增加照片许可。
4. 在指定设备内开始照片播放，暂停／继续、前后切换、调整间隔或返回家庭看板。界面读回服务器状态；照片只从该设备已有有效许可中选择。
5. 不再使用的电视可在确认后撤销。该设备后续服务器请求被拒绝；已经交付的图像字节不能远程收回。正常电视网页继续按短期显示授权轮询并清除失效图像，见 [播放契约](MEDIA-PLAYBACK.md)。

控制界面沿用当前 [Expo 官网风格](EXPO-SITE-STYLE.md)，使用 React Native Paper 的标准表单和按钮。电视主题选项控制电视自身，独立于手机控制页的白黑主题。

## API 与持久化

复用既有接口，不新增表或外部服务：

| 操作 | 接口 | 写入约束 |
| --- | --- | --- |
| 读取配对设备 | `GET /api/devices` | 仅当前家庭真实成员；不返回配对 secret |
| 批准电视 | `POST /api/pair/approve` | 提交电视码、名称、侧重成员和日程范围；有效配对码只批准一次 |
| 显示设置 | `PATCH /api/devices/<id>` | 提交当前设备 `revision`；显式 `layout` 为完整四字段对象 |
| 撤销电视 | `DELETE /api/devices/<id>` | 明确确认；服务端检查本家庭权限 |
| 播放读回／控制 | `GET`／`PUT /api/media-playback/devices/<id>` | 独立播放 `revision`；动作名称与间隔限制见播放契约 |

配置和播放使用不同版本。设备详细 DTO、默认值与经典页面兼容约定见 [电视显示设置](TV-DISPLAY.md)；照片共享和逐设备许可见 [相册界面](EXPO-PHOTOS.md)。

冲突或响应丢失后先读取当前状态，不自动把未知动作换成新版本再次执行。编辑、写入或结果未确认时，界面保护当前操作；明确保存、放弃或核对后才能离开。草稿仅在当前页面内存中保留，不能当作浏览器被强制关闭后的持久草稿。切换身份时清空原家庭设备信息，迟到响应不能恢复旧数据。

## 验证与边界

本轮须完成固定源码的后端事务和权限回归、真实临时 Flask／SQLite／Edge 的双屏配对及控制、身份与网络故障恢复、手机和桌面布局验证。实际执行计数、截图和部署身份在验收后补充，当前不以计划代替成功记录。

合成 Google Photos 数据不算真实账号接入；浏览器模拟电视不算实体设备。用户此前 Google Photos 实际保存成功的结果保留，但不代表此次配对、许可或播放链路已由本人验证。视频、跨来源精选回顾、实体遥控器和长期常亮行为仍需后续实现或验收。
