# 资产分析参考汇率

本批模块已随固定 source `f25357f` 于 2026-09-19 16:20:25（北京时间）发布；组合、实际 Linux、该镜像公共 ECB 读取与生产审计证据见[集中验收](FINANCE-ANALYSIS-ACCEPTANCE.md#finance-analysis-release)。`finance_fx.py` 只处理公共参考汇率，不读取、上传或修改账户、持仓、原币估值和交易。调用入口、本人权限、刷新确认与回执见 [分析 API](FINANCE-ANALYSIS-API.md)。

## 来源与用途

服务器只读取固定 ECB HTTPS 数据接口的日频 `EXR/D..EUR.SP00.A` 序列，查询参数仅为日期和 CSV 格式；不带用户账号、账户币种列表或金额。拒绝跳转和非 CSV 响应，验证 EUR 基准、币种、单位、频率、状态和日期。金额使用 `Decimal` 精确计算，不使用二进制浮点数。

[ECB 官方参考汇率说明](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)明确以欧元为基准，通常工作日更新，仅供参考。因此本模块是报告估值参考，不代表银行结算价、可成交报价或实际投资收益；不进行兑换和投资交易。

读取报告只使用已保存的数据。需要更新时由本人点击刷新，网络请求在数据库事务外完成，保存由 API 在重新核对会话后的一次事务中进行。失败保留已有缓存和原始账户数据。无常驻后台刷新任务，不假称实时行情。

## 换算与覆盖

- 每个账户保留原币金额，报告金额按 `原币整数分 × 目标币每欧元 / 原币每欧元`，最后一次四舍五入到整数分；负数中点同样远离零。账户沿用既有两位小数存储合同，包括 JPY，不暗改历史金额单位。
- 两个币种必须使用同一观测日期；按报告日向前最多七天选择最近完整币种对。EUR 作为该日的基准 1。缺少币种、日期或超过七天时返回缺口，不以零、未来值或不同日期拼出的汇率代替。
- 同币种采用恒等换算，不需要外部数据，`rateDate=null`。报告日、账户原估值日、汇率日分别保留，不能把沿用的旧估值写成当天真实余额。
- 请求最多覆盖 373 个自然日，供最多 366 天的分析区间加七天向前查找。单次响应最多 5 MB、20,000 行；累计最多 400,000 个报价版本，容量满时仍允许刷新已有版本。

## 持久化合同

新增一张 `finance_fx_rates` 表和日期／币种索引。字段为 `version`、`rate_date`、`currency`、`units_per_eur`、`source_url`、`body_sha256`、`fetched_at`、`last_checked_at`。版本是来源、观测日、币种和规范化数值的 SHA-256。首次来源地址、响应摘要和下载时间保留；再次读取同值只推进核对时间，修正报价新增版本，旧版本不删除。较晚到达但下载时间更早的响应不会取代新的观测。

这张表是家庭库中的公共数据缓存，不含账户归属；私有分析报告由上层 API 校验身份。缓存不提供浏览器直接写入入口。`init_fx_schema(con)` 和 `save_fx_batch(con, batch)` 都不提交事务，后者要求调用者已开启授权事务；调用者同时保存操作回执并负责提交或回滚。它与分析模块四张表一起由专用 61→66 表迁移发布，不能单独在生产启动时随意升级旧库。

内部函数：

| 函数 | 合同 |
| --- | --- |
| `fetch_ecb_rates(start, end)` | 返回验证后的公共批次，网络或解析失败抛出含安全消息的 `FxError`，不写数据库。 |
| `save_fx_batch(con, batch)` | 一次验证完整批次后写入，返回插入、已有版本及总行数。 |
| `load_fx_rates(con, start, end)` | 每个日期／币种返回最近核对的版本及来源信息。 |
| `resolve_fx_quote(rates, as_of, source_currency, target_currency, max_age_days=7)` | 返回相同日期的报价和观测明细，缺失返回 `None`。 |
| `convert_cents(amount, source_rate, target_rate)` | 有符号整数分精确换算，返回整数；不接受浮点金额。 |
