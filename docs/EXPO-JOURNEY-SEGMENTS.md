# Expo 详细行程编辑

本轮独立源码候选，尚未组合浏览器验收或发布。从已保存旅行的「行程分段」进入，以现有 Paper 浅深主题、内容密度和 Expo 白灰黑层级编辑城市、航班、住宿与活动。没有新数据库、预订服务或第三方依赖。

## 使用步骤

1. 旧日期行程先填写旅行参考时区及每座城市的 IANA 时区，点击「明确升级为详细行程」。旧段保留为「原日期段」，不会被推定为航班或住宿。此时仍未保存；确认升级保存后不能降回旧结构。
2. 按行程顺序维护城市和分段。城市最多 20 座、分段最多 100 段，每页 5 项；一次展开一段编辑，支持前后移动和明确移出草稿。总日期、金额、出行成员、准备与采购在本页不编辑。
3. 航班两端分别填写当地时间和时区；住宿使用入住／退房日期，退房日不计晚数，未知入住／退房时刻留空。活动可以选择明确时段或仅知道日期，全天结束日期不含当天。切换活动时间方式会清空原时间，不补猜测值。
4. 「已预订」「人工标记取消」只是本人填写的计划标记，不会联系航司或酒店。「允许在调整旅行日期时选择联动」只保存规则，此处不自动平移日期。
5. 点击「预览详细行程」，核对城市前后日期、规范化当地时刻、UTC 偏移及 UTC 时刻、衔接提醒和移出影响。不存在的夏令时时刻需修改；重复时刻须明确选择服务器给出的偏移后重新预览。
6. 若当前日程和本页计划都改过同一组内容，逐项选择「保留当前日程」或「使用本页计划」，再预览。日期、时间、时区作为一组处理；被保留的单独日程值会在确认区显示，不能把计划时间当作实际日程时间。
7. 「确认保存详细行程」才提交。保存后重新读取当前旅行；回执只代表原操作成功。返回详情继续核对实际日历发布状态，未新增云日历绑定或预订取消操作。

移出分段会解除既有日程的旅行关联并保留独立记录，不删除已完成记录、照片或资料。移除城市会解除该城市与保留分段的关联，不自动改变分段时间；至少保留一座城市。

## 失败与恢复

- 普通输入修改会作废旧预览；超过预览有效期必须重新预览。刷新最新内容不会自动保存。
- 旅行或关联实体变动时保留草稿，明确选择采用最新，或保留本页城市／分段／参考时区并采用最新金额、成员与清单，再预览确认。不会静默换用新版本提交旧草稿。
- 保存结果未知时保留原预览和幂等编号，只允许「核对行程保存结果」或「按原行程请求重试」。查询 404 不能证明未写入；既有未知请求收到普通冲突或过期错误也不自动换编号。核对前禁止内部返回和父级导航。
- 已确认保存而当前详情读取失败时，不恢复旧可操作内容。显示历史回执与「读取当前行程」，fresh GET 成功后才可继续编辑。
- 同身份后台、离线或焦点丢失会隐藏内容、取消读取，但保留内存草稿与未知意图；恢复后先核对身份与当前数据。真正成员／家庭／会话变化清除原页面，迟到响应不能重新打开内容。无 localStorage、URL 草稿或持久化预览凭据。
- 仅未保存草稿可以通过二次确认放弃后返回。用户关闭浏览器会失去内存意图，页面有离开提醒；这不是跨设备草稿或操作恢复库。

## 开发接缝

`components/JourneySegmentsPanel.tsx` 默认 props 为 `{ journeyId, onBack, onPendingChange? }`；`JourneySegmentFields.tsx` 仅负责局部字段与显示。导航由独立接线维护，`onPendingChange` 同步报告编辑、请求与未知结果，后台不丢失草稿锁。按钮设置最小 44px 操作高度，长文字允许换行；实际视觉范围需后续浏览器验证。

模型独立位于 `lib/journeySegments.ts`。复用 `GET /api/journeys/templates`、`GET /api/journeys/<id>`、`POST /api/journeys/preview`、`POST /api/journeys/apply` 与 `GET /api/journeys/operations/<key>`。每个请求前后完整核对成员、家庭、认证代次及 CSRF，并以页面 epoch／AbortSignal 丢弃旧任务。

新编辑要求 `supportedSchemaVersions` 包含 2 且 `templates.capabilities.editSourceSnapshot === true`。预览必传原 `journeyId/revision/expectedEntities`，后者覆盖详情中全部关联实体的版本；预览前 fresh GET 只检查原快照，不替旧草稿偷换新 map。服务器快照与 apply 锁内 CAS 分别保护读取到预览、预览到提交两段竞争；旧服务缺能力时禁用编辑提交，不降级发送。

未知意图只在通过前置身份核验、实际尝试 apply 时安装。明确拒绝必须来自写端点，且后置身份核验成功；后置 `/me` 失败、非法回执或网络中断保留原意图。成功回执核对旅程、原 trip、预期 revision 和操作编号，再单独读取当前详情；不会把历史回执当最新计划。
