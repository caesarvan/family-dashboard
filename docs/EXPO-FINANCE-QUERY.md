# Expo 助理：查询预算与支出

已于2026-09-19 19:42:01（北京时间）上线，19:42:33独立只读审计通过；固定运行身份和分段证据见[集中验收](ASSISTANT-FINANCE-QUERY-ACCEPTANCE.md#assistant-finance-query-release)。查询只读取当前有权查看的数据，不记账、不改预算，也不执行付款或转账。

## 从哪里进入

1. 打开「更多 → 家庭助理」，点快捷项「查询支出」，或在「告诉助理你的需求」中输入财务问题，再点「查询」。默认使用本地规则，不要求配置模型。
2. 进入「预算与支出」后，核对结果中的本人／共享范围、月份、分类及币种。可以修改「财务问题」后重新点「查询」。没有写明范围或月份时，结果会明确说明采用本人、北京时间本月。
3. 按需点「查看本人账本」「查看月预算」或「查看共同资金」，进入既有财务页面。该入口只携带财务页签及适用月份；返回后点「返回查询」，会按原查询范围重新读取，且不会再次调用模型。
4. 点「返回助理」回到原问题。刷新页面或退出登录后，不依赖浏览器缓存恢复私人问题或结果。

| 可以这样问 | 结果范围 |
|---|---|
| `本月花了多少` | 本人本月已记录支出与退款后净支出 |
| `上月预算还剩多少` | 本人上月各币种预算；跨年时使用实际上一月份 |
| `查询本人 2026-08 CNY 餐饮 支出与预算` | 明确月份、原币和分类的支出与预算 |
| `查询 2026-08 共享消费` | 已明确共享的消费汇总，不含伴侣私账 |
| `查询公共荷包` | 已手工确认的人民币当前快照，不是历史月账 |

只写「八月支出多少」、一次要求多个月份或多个范围，会要求补充；不会猜年份。「伴侣本月花了多少钱」不会读取对方私账。「查本月支出并把预算改成100元」不会忽略修改要求后执行其中一部分。明确搜索、创建旅行和新建待办仍使用原有入口。

结构化旅行需求写明「旅行名称：…」「出发日期：…」「返程日期：…」时，家庭总预算、采购预算和「检查护照／查看签证」等准备事项不会将其误分到财务查询；点「整理并预览」进入旅行简报。「旅行预算还剩多少」「查上月旅行花费」仍进入查询；旅行草案另附明确的财务查询时保留整段原文，由服务端核对混合请求。这项入口修正须随新构建验收发布，不能从文首的既有上线记录推断已部署。

## 如何读金额

消费、退款和净支出按原币分别显示，不换汇，也不把人民币和美元相加。退款按退款发生月计入；分类退款沿已确认关联分摊。确认重复、订单和转账不作为消费相加，订单本身不能证明实际付款或退款。

月预算逐项显示预算、已记录净支出和剩余金额。「全部」预算与分类预算分别核对，不能相加；剩余金额仅扣除已记录净支出，尚未导入的消费仍可能影响实际可用额度。没有预算显示「尚未设置预算」，不制造零额度。

没有可汇总记录不等于没有支出。只有订单或待核对付款时，覆盖说明会给出对应数量；有记录的零值、没有记录和未知金额分开呈现。公共快照未经确认时显示「待核对／尚未核对」，不把初始默认金额当成实际余额。「共同长期储蓄」单列，不与旅行准备金相加。

## 可选模型与失败恢复

已配置模型时，可明确勾选「使用已配置的 AI 整理」，帮助理解本地规则尚不能确定的口语，例如「帮我瞧瞧上个月餐饮方面用了多少钱」。勾选表示允许模型；本地已经能明确解释的问题仍直接在本地处理，不为同一答案额外调用模型。

模型只接收本次问题、系统日期、固定可用选项及从问题中提取的原文证据，不附加账本、预算金额、余额、真实分类目录、账户或家庭资料。问题中自行输入的文字属于本次发送内容。服务器仍校验范围和日期并计算金额，不采用模型生成的金额，也不让模型绕过歧义、修改要求或权限限制。

模型未配置、超时或返回格式错误时，保留问题并显示错误；可重试，或关闭 AI 后改用明确的本地表达。没有自动换供应商或后台重试模型。离线、离开前台或暂时无法核对身份时，财务内容隐藏；恢复后先核对身份，再按原范围进行本地刷新。成员、家庭或权限变化会清除旧问题和结果，迟到响应不能重新显示上一身份的财务。

接口、精确字段和金额口径见[后端合同](ASSISTANT-FINANCE-QUERY.md)。本地合成记录和临时浏览器验证不等于本人线上财务验收；A–D 本人完整验收仍为 **0/4**，实体电视未验收，电视身份不能进入本人查询。
