# 视频读取内存保护候选

基于视频后端 `c2b3598`，本改动尚未发布，不包含 AES-GCM、镜像资源调整或 Linux 峰值验收。64 MiB 展示副本上限保持；对象生命周期测试不等于实际内存占用证明。

成员及电视的视频 GET 共用一个**进程级**许可，所有家庭子应用也共用。先按原会话及媒体权限检查，再尝试非阻塞取得许可；繁忙返回 `503`、`code: video_busy`、`Retry-After: 1`，允许稍后重新 GET。未授权请求仍按原权限错误拒绝，不用繁忙状态代替核权。不等待、不在等待期间保持数据库事务，照片预览、列表及健康检查不使用该许可。

取得许可后再次核对当前身份、权限、revision 和视频 key，随后读取密文；解密及摘要验证后释放局部密文引用，再按原规则重新核验身份、ACL、revision 和缓存 key。失败不发旧视频，异常路径释放许可。成功响应持有许可至 WSGI `close`，包括服务端因断连而关闭迭代器的路径；响应遗失时由弱引用 finalizer 兜底。关闭与 finalizer 幂等，不在路由 `return` 时提前释放。不会引入公开文件、流式未认证明文或长期解密缓存；已发送字节无法追回，不能把末次核权描述为整个网络传输期间持续撤权。

后台仍串行处理。视频净化返回后立即丢弃原下载对象，再核权、加密并原子提交 SQLite，避免在提交阶段继续持有最多 100 MiB 的源片。照片路径保持原样，网络／转码／提交前后原 lease 和授权保护均保留。

定向测试使用真实临时 Flask、SQLite、媒体加密与 WSGI 响应生命周期，小型合成展示字节作为已处理输出。覆盖并发、跨家庭与电视的同一许可、繁忙后恢复、正常关闭、断连关闭、HEAD、垃圾回收、异常、两次核权期间撤权，以及 worker 在真实提交前释放下载对象。合成输出不冒充 FFmpeg 或 Google 验证。本批不修改部署线程数；多进程部署时每个进程各有一个许可，仍须单独核算容器总峰值。现有 tmpfs、解码子进程、SQLite 与响应缓冲的 Linux 实际峰值另验。

本地执行分两轮：新增 16 项首轮 15 通过，1 项因测试在同线程嵌套客户端请求、污染 Flask 请求上下文，实际安全拒绝为 401 而非预期 404。改为独立请求线程后，仅复验该项、补强的 4 种释放路径，以及补上响应关闭的两条原视频集成流程，7 项全部通过。合计 18 个唯一用例、23 次执行；原集成两项使用真实 FFmpeg，Google transport 仍为模拟。首轮失败与两轮原件均保留在 ignored `test-results/media-video-memory-r1`、`media-video-memory-r2`，不称一次全量或生产验证。

独审在 `3573bdd` 发现失败路径的异常栈仍可持有已解密的大缓冲，而许可已释放。后续窄修在失败上交前清除本调用的 `raw/blob/cache/response` 引用，并清除已结束内层异常帧中的局部引用（包含 chained exception）；保留异常身份、类型、消息和栈位置，运行中的调用者帧及调用者拥有的对象不被清理。成功响应仍只在关闭／finalizer 时释放许可。

增量 R3 仅新增 4 项真实临时 Flask/SQLite/Fernet 检查，全部通过：1 MiB 可认证但长度不符的缓存，在实际错误处理器中检查许可和栈；解密的嵌套异常；响应构造失败；关闭回调注册失败。检查视频及其内层异常栈不再持有大字节／缓存行／响应缓冲，随后保留异常对象并重新读取成功。原 18 项证据保持，没有重跑；本次对象引用检查仍不是 Linux 峰值或生产验收。
