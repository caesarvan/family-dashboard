# 视频版本的五服务启停组件

`deploy/media_video_service_lifecycle.py` 为发布控制器提供四服务到五服务的明确生命周期。它是待审查组件，没有生产激活命令，也不会自行安装源码、执行迁移或回退。现有四服务控制器不能直接用于新版本；两镜像构建成功也不代表此组件已在生产验证。

组件固定现有四服务 Compose 与候选五服务 Compose 的摘要，使用本机 Docker Unix endpoint、明确项目名、目录与 Compose 文件。父应用镜像固定为当前日历隐私版本；候选 app 与 decoder 必须提供不同的完整镜像 ID。容器名称、Compose 标签、镜像、挂载、内存和健康状态均核验，项目中额外容器会阻止继续。报告仅包含服务 ID、镜像及环境摘要，原环境不进入返回结果。

## 启停顺序

父版本先核对四服务，关闭 web 与 sync，等待 media 最多 1200 秒退出，最后停止 app。五服务版本在 media 排空后才停止 decoder（30 秒），然后停止 app。每步都重新核对容器 ID，检查实际退出码、OOM 和运行状态，最后证明数据卷与 socket 卷均无运行者。这个顺序避免处理中途失去 decoder。

迁移完成后，仅启动 app：所有启动命令使用 `--no-deps --no-build --pull never`，不会顺带启动后台任务。app 健康核验后再次停止，调用者必须完成真实停止态数据检查，并提供已核验的迁移与保全收据；两份收据必须验证通过，家庭/数据库数量、计划、源码身份和完整逻辑摘要一致。随后按 app → decoder → sync/media → web 开放服务。此组件只核对收据关联，收据原件与 SHA、备份、迁移和完整组检查由外层发布控制器负责。

decoder 要求无网络、UID 10001、只读、768 MiB 无 swap、1 CPU/128 pids/128 descriptors、cap-drop 与禁止提权，仅可挂私有 socket 卷和有界解码临时盘。运行环境必须与 decoder 镜像的环境完全一致，不能增加应用凭据或挂载数据库。media 相对父版本仅允许新增固定的 `MEDIA_VIDEO_SOCKET` 环境设置；app/sync 的环境内容保持逐键一致。

Compose 部分启动后失败时，组件仍尝试记录确切候选容器 ID。失败清理只对已记录且身份仍一致的 ID 发出 stop，不以宽泛选择器停止其他项目。media 未能正面确认停止时保留 decoder，明确报告排空未确认；仍尝试停止其他已记录的应用与公开入口。剩余项目进程或数据/socket 卷使用者会使清理报告为未完整停止，禁止据此恢复旧应用。组件不会删除 socket、卷、容器、原数据或自动启动旧应用。

## 外层控制器仍须完成

- 获取发布锁，检查不可重放的新计划、独立审查与全部真实验证原件。
- 核对源码、配置、两个镜像及实际生产父身份；保全旧源码、配置和镜像。
- 停止备份定时器与所有写者，完成全部家庭和平台的完整库组备份、71→73 迁移及 app-only 保全。
- 核验 socket 卷首次创建或停止态无遗留 socket，保持原卷，不自动删除陈旧 socket。
- 安装已绑定源码、设置经审镜像，使用本组件分阶段启动；失败保持停止态并准备完整库组恢复。
- 核对 HTTPS、所有运行文件与备份恢复状态，完成独立生产审计。

本组件测试使用真实固定 Compose 文件和记录型 Docker 替身，验证顺序、身份变化拒绝、权限配置、保全门禁与失败清理；不是 Docker、Linux 资源、真实迁移或生产启停证据。配套 Linux 迁移/IPC 工具与本组件分别审查，后续完整控制器仍须独立演练。
