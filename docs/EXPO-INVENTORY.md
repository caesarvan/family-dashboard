# Expo 家庭物品

`frontend/src/screens/InventoryScreen.tsx` 使用 React Native／Paper 与[当前 Expo 官网样式](EXPO-SITE-STYLE.md)，调用既有[库存 API](INVENTORY-API.md)。`frontend/src/lib/inventory.ts` 定义安全投影、数量和日期输入规则、回执校验及完整会话边界。此模块不修改数据库、金融、采购完成状态或云服务。

## 日常操作

1. 在“家庭物品”新增物品，填写名称、单位、规格与存放位置。默认仅本人可见；明确选“与家庭共享”后，同家庭成员才能查看和记录实物变化。只有拥有者能改物品信息、共享范围和归档。
2. 选择“添加采购批次”，记录计划、已下单、运输中、结束或取消；或选择“登记家中已有”，补录已有批次。保存批次不会增加库存，随后点“收货”登记核对过的实物数量，同一批可分次收货。
3. 批次的“更多实物操作”包含使用、报损、退回和更正。更正填写带符号的变化量，不是最终总量。除收货以外，必须填写原因；所有动作都需勾选已核对实物后明确确认。
4. “查看变动历史”保留原记录，可为允许撤销的记录追加相反变化，不删除历史。退回不代表已退款，不重新增加待收数量；实物变化不写财务账。
5. 采购关联、下单日期、预计到货、保修、售后和备注可按需维护。共享成员的编辑字段严格取自服务端 `editableFields`，不会把隐藏或无权编辑的字段重新提交。

列表可以搜索名称、规格、位置，并按全部、我的、已共享筛选。“已共享”也包含本人共享物品。物品／批次／变动历史分别按 24／12／12 条分页；这些分页不是历史快照，刷新会读取最新内容。拥有者可在库存为零、所有批次关闭或取消后明确归档。补货线只提供提醒，不自动下单。

## 交互与权限契约

- `InventoryScreen` 默认导出，接受 `ScreenProps` 与可选 `inventoryRequest?: { key: number; id?: string }`。新的 key 打开指定物品，必定重新 GET 详情；未带 ID 返回列表。已有编辑或待核对操作不会被外部打开请求替换。
- 主要无障碍标签：`搜索物品`、`查看物品 {title}`、`打开批次 {24hex id}`、`本次数量`、`操作原因`、`我已核对实际物品和数量`、`确认实物变动`、`撤销这条记录 {24hex id}`、`确认撤销原记录`。显示文本使用易懂的物品／批次标题，技术 ID 只用于稳定的可访问操作标识。
- 单选与实物确认使用 Paper TouchableRipple／Icon／Text 组成单一交互控件，显式提供网页 `aria-checked/aria-disabled` 和原生 `accessibilityState`；同一个受控布尔值决定图标和读屏状态，装饰内容不再重复生成交互角色。网页支持空格切换确认、选择单选，方向键在同组可用选项间移动；不修改 Paper 或 React Native Web 依赖。
- 读写均在 I/O 前后读取 `/me`，核对 role、家庭、成员、auth_version 与 CSRF。失败响应也复核会话。写入使用复核得到的 CSRF，不接受助手搜索结果或旧 props 的数量／版本作为写入依据。
- 仅显示服务端投影的现有、在途、计划、累计收货、已退回与待收数量。批次写入同时携带当前物品和批次 revision。详情和批次来源不一致则拒绝展示和写入。
- 真正离开此路由、关闭页面或身份变化时清空详情、草稿和回执。暂时进入后台时只隐藏私密内容、丢弃旧异步接收，保留同一身份的内存草稿和原操作；恢复后必须先验证完整会话及当前物品／批次访问权限，才重新显示。不会自动更换草稿版本或重发操作。后台期间完成但未收到的写入仍需用原回执核对。电视身份直接拒读，不请求库存。
- 空闲可见时每 15 秒只读核对权限和内容；编辑／提交／待核对时暂停。401／403 清空整个工作区并重取登录状态；对象 404／410 清空详情、列表和草稿，不保留旧共享快照。
- 没有 localStorage、IndexedDB、文件草稿或离线写入队列。用户离开前会在表单中看到未保存内容的保留范围。

## 失败恢复

一次明确保存生成一个 32 位小写 hex requestId，原路径、方法、完整载荷和双版本只保留于本页内存。在写入或结果待核对期间，表单、筛选和目标切换锁定。

网络／服务端失败或回执无法验证时，点击“核对并重试本次操作”先查询原 `/operations/:requestId`。存在回执就采用当前安全投影，不重复写入；404 时重新检查原物品／批次的权限，然后才重发完全相同的原请求。归档 410 或撤权 404 清空，不用新编号复活旧操作。

明确 400／409 保留输入，要求“重新核对并修改草稿”。重新读取当前版本和字段权限后才解除锁定，实物确认复选框清空，用户再次核对和确认；新的明确意图产生新请求编号。没有自动覆盖或自动重试。已取得成功回执后的列表刷新失败不把成功写入变回未知结果。

## 验证边界

本候选先进行 TypeScript 类型检查和纯会话／输入契约检查，再由集成人合入后使用独立物理依赖构建。浏览器应验证真实 Flask／SQLite 上的分次收货、使用／退回／撤销、结果丢失回执恢复、并发修改后的草稿重核、共享字段权限和撤权，以及手机／桌面布局。提交或类型检查不代表已发布；真实业务浏览器、构建身份和生产记录由集成人在本轮验收中单独记录。
