# 家庭助理：服务端模型适配

本模块为既有家庭助理增加指定 NVIDIA 入口的文本 JSON 适配。模型仍只生成待核对建议；本地概览、搜索、清单草案及旅行表单继续可用。生成建议不会创建任务、采购、旅行或云端日历。原来的成员鉴权、CSRF、家庭隔离、旅行事实核对、预览与明确确认继续决定能否执行。

本文描述实现契约，不表示这份应用候选已上线，也不表示所有模型、工具调用或外部平台已经验收。

## 服务端配置

| 配置名 | 内容与边界 |
|---|---|
| `ASSISTANT_PROVIDER` | `nvidia`、`openai` 或 `local`；可省略，选择规则见下方 |
| `NVIDIA_API_KEY` | 服务端密钥；不能进入源码、前端、导出、截图或日志 |
| `NVIDIA_MODEL` | 实际服务目录提供且已验证所需协议的精确模型 ID；没有默认值 |
| `OPENAI_API_KEY`、`OPENAI_MODEL` | 保留旧显式配置的兼容路径；这次没有验证旧服务的真实可用性 |

部署人员通过现有服务端环境注入机制提供配置；Python 应用不自动加载 `.env` 文件。不得把密钥放进静态文件或通过浏览器输入模型配置。此模块不读取某个开发者机器上的固定路径，也不提供任意 endpoint/base URL。

下列只说明键名，不能直接作为有效配置使用：

```text
ASSISTANT_PROVIDER=nvidia
NVIDIA_API_KEY=<通过现有服务端秘密配置注入>
NVIDIA_MODEL=<实际验证的精确模型ID>
```

选择规则：

1. 明确设置 `nvidia` 或 `openai` 时，只使用相应服务的密钥和模型；缺失、空值、非法类型或控制字符均视为未配置。未知 provider 也不可用。
2. 明确设置 `local` 时，不允许模型请求，保留本地流程。
3. provider 未设置或为空时，只要存在 `NVIDIA_API_KEY` 或 `NVIDIA_MODEL` 中任何一个配置键，就选择 NVIDIA。即使只是空值或半套配置，也不会转用旧 OpenAI 密钥。
4. 没有任何 NVIDIA 配置键时，兼容已有 OpenAI 配置。失败之后从不更换提供方、密钥或模型，也没有后台自动重试。

配置可从进程环境读取，或通过既有 `create_app(config)` 显式传入；配置对象覆盖环境。创建及重新加载子家庭时，三项新增 AI 配置与旧配置一起经白名单传入，不能依赖子应用偶然继承宿主环境。

前端继续只获得已有 `modelConfigured` 布尔值，既有 `mode: local|model` 和 `useModel` 语义保持。布尔值表示选定服务所需配置齐全，不代表实时健康探测、模型权限或请求成功；响应不返回服务端密钥、模型配置或远端错误细节。

## 请求与响应边界

NVIDIA 固定使用 `https://inference-api.nvidia.com/v1/chat/completions`。只发送已验证的基本字段：`model`、两条 `system`/`user` 消息、`max_tokens`、`temperature: 0`、`stream: false`。清单草案最多请求 1800 输出 token，旅行简报最多请求 2500。没有启用 `tools`、`response_format`、Responses 或自动工具执行能力。

用户文字放在 JSON 数据中，不能替换系统指令。默认仅发送本次请求和当天日期；用户明确选择附带家庭上下文时，仍只发送原有允许的近期共享日程/任务字段。个人账单、账户、财务、令牌、日程备注等不会因增加提供方而进入上下文。旅行简报只发送该次用户文字。

使用系统默认 TLS 验证，拒绝 HTTP 重定向；不接受与预期 endpoint 不一致的响应地址。所有响应都须先通过有界读取，再检查外层对象与模型 JSON 内容。NVIDIA 响应仅接受一条 choice、`finish_reason: stop`、assistant 消息、字符串 content，以及没有拒绝或工具调用的结果。空 choices、截断、过滤、工具调用、非字符串内容、非对象 JSON、非有限数字和无效编码都会失败，不能作为草案或已执行结果。

响应读取上限为 250,000 字节。socket timeout 为 30 秒；分块读取同时检查从请求开始计时的 30 秒 monotonic deadline，防止持续滴流无限占用请求。已经阻塞的一次读取仍可能等待最多一次 socket timeout，因此这不是硬实时 30 秒取消，不启用后台线程继续请求。

解析后的外层与内层内容都检查当前服务密钥的完整回显，包括 Unicode 转义后的字符串、对象键和嵌套值；命中即返回固定错误。此项不代表能够识别任意改写、拆分或编码的秘密。应用不把密钥放进模型 prompt；远端错误 body、headers 和异常消息从不透传或打印。

旧 OpenAI Responses 路径仅保留原有兼容功能，不用于 NVIDIA 失败回退。本次部署与测试不得据此声称旧服务已完成真实调用验收。

## 失败与恢复

| 情况 | 应用响应 | 用户可执行的恢复 |
|---|---|---|
| provider 未知、所选配置不完整或 `local` | 503，`modelConfigured=false` | 继续本地/手工流程，由管理员核对配置 |
| 远端 401/403 | 503，固定授权错误 | 继续本地流程，由管理员核对服务连接 |
| 远端 429 | 503，固定繁忙提示 | 稍后在原流程明确重试；不透传 Retry-After 或远端 body |
| 请求/读取超时 | 504，固定超时提示 | 保留用户文字并稍后重试或手工整理 |
| 网络、重定向、5xx、格式/大小/密钥回显异常 | 502，固定不可用/内容错误 | 明确重试或继续本地流程 |

已配置服务的临时失败不把 `modelConfigured` 改为 false，也不假装已切回本地生成成功。模型草案请求不创建业务事项；创建仍由原确认接口执行。同一已确认计划的重试使用原计划 ID 和原确认语义，不会因为服务适配增加第二次写入。已完成操作的状态由既有接口和回执核验，不依据模型措辞判断。

## 验证范围与交接

专用测试为 `tests/test_assistant_nvidia_provider.py`，使用合成响应与临时 Flask/SQLite：配置选择和部分配置禁止回退、请求字段、重定向、读取界限、密钥回显、畸形 JSON、限流/超时、无秘密错误、原预览确认幂等、旅行事实核对、个人数据上下文白名单、成员/CSRF/TV 权限和子家庭配置传递。原 `test_home_assistant.py`、`test_assistant_journey_brief.py`、`test_household_spaces.py` 是受影响回归；具体命令、计数与日志在本次交付记录中。

指定服务的独立协议探针已于 2026-09-16 验证 `/v1/models` 返回 170 个模型 ID，并验证 `us/azure/openai/gpt-4o-mini` 的基本非流式 JSON 回复、字符串 content 和 `finish_reason: stop`。这些是该时点的协议证据，不能证明工具调用、所有模型、生产应用配置或完整家庭流程已通过。适配任务本身不读取真实密钥、不调用外站；模型名称应由部署时的实际证据确认。

此改动没有新路由、表、迁移、依赖或新增前端模块。`app.py` 仅增加 AI 环境配置读取；`household_spaces.py` 仅扩充子应用 AI 配置白名单；`static/home-assistant.js` 只把原固定 OpenAI 告知改为“已配置的 AI 服务”，保持原手动勾选及上下文授权。集成人仍须按照固定提交审查、受影响组合验证与现有源码发布流程接入；Git 合入不代表已经部署。
