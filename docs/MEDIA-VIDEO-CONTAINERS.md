# 视频隔离容器候选

本配置尚未部署。必须先完成完整 Linux IPC、worker 100 MiB 输入、成员 64 MiB 响应及资源峰值验证，再把它纳入新版本的迁移、停写、备份、恢复和发布工具；旧四服务的发布流程不能直接用于本候选。

## 运行分工

应用镜像只增加视频缓存、播放进度、协议客户端和处理器的 Python 模块，不安装 FFmpeg。`media` worker 继续持有账户授权并下载用户明确选择的源文件，再通过 `MEDIA_VIDEO_SOCKET` 发送有界字节；配置了 socket 后失败不会回退到本地解码。任务只在原授权与版本核验通过后保存。

`decoder` 镜像独立从已固定的 Python 基础镜像构建，只安装 Pillow 12.3.0、FFmpeg `7:7.1.5-0+deb13u1` 并复制四个媒体处理模块。它不加载 `.env`、家庭库、云端令牌、完整应用源码或原平台 URL，不连接网络，也没有对外端口。

新的 `decoder-socket` 命名卷只挂载到 worker 和 decoder。两个镜像都预建 UID/GID 10001、0700 的同名目录，使空卷不依赖容器创建先后完成权限初始化；socket 为 0600。应用、同步和代理服务均不挂载该卷。Compose 的依赖顺序会等 decoder 健康后启动 worker。

容器根文件系统只读，删除所有 capabilities，禁止提权；候选上限为 1 CPU、768 MiB 内存且不使用 swap、128 进程与128文件描述符。处理临时目录是384 MiB、0700、noexec/nosuid/nodev 的 tmpfs，其占用计入容器内存，不能将两个上限相加理解为可用内存。768 MiB 尚非完整 IPC 的已验证预算；不得在失败后自动扩大资源限制。

## 停止与恢复

worker 最长按现有 1200 秒视频任务 lease 排空当前步骤，随后 decoder 才停止；正常 SIGTERM 会终止解码子进程并清理临时目录及自身 socket。decoder 健康检查只核对私有 socket 的存在、类型和权限，不是视频解码成功证明。

服务默认拒绝现存 socket。正常退出会删除自己的 socket；OOM／SIGKILL 或主机异常后，命名卷中可能留有旧 socket，此时服务会明确启动失败。恢复时先确认该版本的 worker、decoder 已停止，核对目标为本项目专用 socket 卷中由 UID 10001 拥有的0600 socket，且没有活动服务，再处理该单个陈旧 socket。不要删除家庭数据卷、复用其它项目的 socket 卷，或绕开服务的路径权限检查。处理完成后重新启动并检查服务健康与一条真实视频导入；本候选没有自动删除陈旧路径。

发布需要同时绑定应用镜像和 decoder 镜像、精确工具摘要、五服务配置、71→73数据库升级，以及回退时的完整库组备份。启动失败或迁移失败保留原证据；不能仅回滚镜像就宣称数据结构已回退。实体电视与真实 Google 账号的视频验收分别记录。
