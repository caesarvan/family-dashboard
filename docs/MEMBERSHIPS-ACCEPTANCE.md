# 个人账户与家庭成员：候选验收

本批仍是开发候选，尚未激活生产。线上身份继续以 [最近一次发布](EXPO-ASSISTANT-TRIP-SEARCH-ACCEPTANCE.md#expo-assistant-trip-search-release) 为准。实体电视按用户反馈暂缓；浏览器检查不替代实机验收。

## 本批交付

个人账户独立登录、注册资格验证、绑定已有家庭身份；家庭邀请、加入、管理员移除、本人退出、重新加入及多家庭切换。原私人数据保留原 owner，绑定不会自动共享或合并账户。移除及个人退出同时限制派生会话和后台任务的后续操作，最后一位有效管理员不可退出。

前端使用现有 React Native / Expo、Paper 组件及 Expo 设计系统。入口为「我的家庭账户」与「家庭与成员」，显示明确的加载、权限失效和结果待核对状态；邀请令牌只在首次成功回复显示。结果未知时读取原操作，不自动重新提交。故障恢复与正常家庭权限分别核验。

## 上线顺序与恢复边界

本批户内从 58 表增至 61 表，平台从 2 表增至 9 表，并增加成员会话字段及迁移标记。不得复用先前 58→58 无 DDL 发布流程。

1. 固定审查通过的组合源码、真实前端导出和完整包；逐项核对哈希及既有部署配置。
2. 构建继承固定已上线父镜像的候选，使用无网络、无生产数据或凭据的容器执行精确测试集合。记录唯一允许的平台专属跳过；失败、额外跳过和未选择不能当作通过。
3. 用两户合成旧数据实际演练备份、迁移、重启和原数据保全。通过独立审查后，将受验组合合入 main。
4. stage 只读核对线上身份；activate 停全部写进程和定时备份，保存旧程序、配置、镜像及整组备份，逐库验证再执行一次迁移。
5. 新 app 启动并停下后再次只读核对迁移结果，再启动其余服务。正常 TLS 读回、匿名访问拒绝、运行文件和服务身份核验完成后，才记录为已上线。

若迁移后失败，保留失败证据并停止候选写入，不自动启动旧程序。旧代码不认识被移除的成员状态，不能单独退回旧镜像；恢复需对应版本及发布前整组数据库，并先保全升级后新数据。真实家庭操作、云授权及实体电视验收分别记录。
