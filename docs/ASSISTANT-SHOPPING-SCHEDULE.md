## 使用流程

在家庭助理整理旅行时，可以写“采购：转换插头 | 负责人：我 | 数量：两只 | 预算：100元 | 截止：出发前3天 | 优先级：高”。不使用模型时支持这种明确字段格式；使用模型时仍以用户原句核对，模型不能自行决定截止日或紧急程度。

采购草案中可以选择不设截止、固定日期或距出发天数，编辑低/普通/高优先级。负数代表出发前。没有截止日期可以继续；信息不明确时保留原句和提示，供本人确认。返程后截止会提示核对，允许保留。预算留空与明确零预算仍有区别。

点击“核对并继续编辑”只产生可编辑旅行草案，随后仍须预览并明确保存。相对天数仅在当前草案随出发日计算，传给旅行计划的是明确日期；不会把相对关系存成后台自动改期规则。保存后的采购日期只有在旅行改期流程明确选中该项时才调整。

## 数据与接口

`POST /api/assistant/journey-brief` 的 `brief.shopping[]` 新增：

| 字段 | 格式与含义 |
| --- | --- |
| `due` | 空串或 2000–2100 年合法 `YYYY-MM-DD` |
| `dueOffsetDays` | `null` 或 -730 至 366 的整数，不能与非空 `due` 并存 |
| `priority` | `low` / `normal` / `high`，未明确时为 `normal` |

旧响应缺少新增字段时，前端显示无截止/普通优先级；非法值拒绝进入草案。`journeyBriefPlan` 将采购相对天数计算为绝对 `due`，向 `/api/journeys/preview` 传递 `due` 与 `priority`，不传采购 `dueOffsetDays`。预览响应交接到编辑器时保留新字段。

截止与优先级必须有完整本项原句支持。否定、约数、相互矛盾的要求、截断否定、其他事项的信息不能作为确定值；付款、收货或下单日期也不能直接当作采购截止日。明确写出的优先级才有效，“很急”等文字保留给本人判断。缺省普通是产品默认，不是模型推断。

只向指定模型提交当前请求文本，不自动附加家庭数据或成员 ID。服务端按调用时的当前家庭成员核对负责人；既有家庭隔离、会话校验、身份切换、离线隐藏、延迟响应丢弃与明确保存流程继续生效。本接口只整理草案，不自动创建采购、下单、付款或写入第三方清单。
