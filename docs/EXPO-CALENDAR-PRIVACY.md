# 本地日程的可见范围

本批为独立前端候选，须与后端统一 ACL 组合后完成真实浏览器验证；提交不代表上线。

## 使用方式

新增普通本地安排的负责人默认当前登录成员，不跟随日程侧重；可见范围默认选择“仅自己”：其他成员和电视不可见。选择“家庭共享”后，家庭成员和电视可以看到，成员仍可共同编辑。只有服务器记录的创建者能够更改这类新日程的可见范围。负责人和日程侧重只影响安排、排序或工作量统计，不授予访问权限。

原有未标记日程继续家庭共享，不推定创建者，也不自动变成私人。云日历以及原有旅行派生日程沿用原共享行为，本批不修改云端权限。手动日程即使关联旅行，只要服务端仍返回有效的新隐私字段，其创建者仍可修改范围；带 `travelTiming` 的受管日程继续走旅行入口。

日程列表和首页使用同一个 EventRow 标注“仅自己”或“家庭共享”。这只是当前服务端授权结果的说明，不以负责人、侧重或客户端筛选替代权限。

## 数据合同

`CalendarEvent` 增加可选 `visibility: 'private' | 'shared'`、`createdBy: string`。后者是当前家庭内稳定成员 ID，前端从不提交或自行生成。POST 发送明确 visibility，默认 private；PATCH 保留原 ID/revision，只在本人可改变范围时发送 visibility，其他协作编辑省略该字段。旧记录两字段均缺省视为共享；损坏或不完整的隐私元数据阻止保存并要求重新读取。

400/403 使用服务端说明；409 保留标题、可见范围及其他草稿，等待用户核对原版本。404 隐藏旧详情，并要求关闭重读；之后即使同 ID 再次出现在状态中，也不会复活已隐藏的旧编辑快照。网络中断或 5xx 不能证明未提交，编辑器冻结输入和保存，不自动发第二次写入。已收到成功响应但后续身份读取失败时同样冻结，恢复后要求关闭核对。

## 身份和离线恢复

编辑器记录打开时的完整 identityKey，根页面在渲染阶段拒绝跨身份使用旧 item，不等待 effect 才清理。当前已授权状态中消失的日程立即隐藏。缓存只留在当前组件内存，不写浏览器持久存储。

家庭状态提供 `stateVerified`：首次读取、已知身份变化、身份/状态读取失败、切到后台或离线后为 false；仅在稳定的 `/me → /state → /me` 核对完成后为 true。普通成功的后台刷新不先置 false，避免周期性闪烁。失败时保持原状态对象，日程页、首页日程卡和日程编辑器隐藏内容，其他原有模块行为不变。日程卡的数量、工作量及标题同时隐藏。成功核对同一身份后，原草稿恢复；若身份改变，旧草稿不能渲染或提交。

前端并不承诺能在服务端撤权发生的瞬间提前知道变化；收到新的不可见结果或身份不确定时即执行隐藏。后端必须对每次读取、搜索、详情和写入统一核权。

## 验证边界

`frontend/tests/calendarPrivacy.test.mjs` 使用真实 TSX 处理函数、真实 provider hook 与合成 DTO/传输，覆盖新建默认范围、创建者切换、协作/旧记录兼容、原 ID/revision、409 草稿、未知提交冻结、身份变化、撤共享后旧快照、身份读取失败及恢复。测试替代 Paper/native 宿主，不等于浏览器、服务端数据库或真实账户验证。

本地只复用既有依赖运行两组 TypeScript 与定向 Node；不运行 npm 安装、完整应用构建、真实浏览器、云服务、SSH 或生产操作。日程冲突界面是另一条已审分支，与本批的 CalendarScreen/HomeScreen 交集由集成人解决，不在作者分支复制覆盖。
