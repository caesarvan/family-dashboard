## 家庭使用流程

1. 保存旅行后，在「准备」卡片点「同步到主清单」。此处使用已保存的原准备事项，不再创建另一份本地待办。
2. 选择本人已授权清单，或账户拥有者明确开放的家庭主清单，勾选本次要同步的原事项。不会默认勾选全部事项。
3. 预览完整标题、负责人、截止日期、完成状态、备注及目标账户/清单，再明确确认。看板负责人保留；不代表 Microsoft To Do 或 Google Tasks 原生指派。
4. 下面显示真实同步进度。等待同步、权限不足、暂停和云端冲突分别显示；只有最新内容确认后才显示「云端已确认」。本地后续修改待同步时会明确提示。
5. 需要时暂停、恢复或重试。两边内容冲突时，先比较，再明确选择「采用云端内容」或「确认以本地更新云端」。采用云端仍保留原任务、负责人及旅行关联。
6. 原清单断开后，只能选择服务器允许的原目标重新预览；不能把已有任务悄悄换到另一账户或清单。重连预览明确显示保留云端原任务。
7. 返回原旅行，重新读取本地完成进度。需要绑定账户时打开「管理账户与清单」；完成授权后重新进入原旅行查看同步。

选择或预览失败会保留当前本人选择。请求已发出但结果未知时，先点「核对当前状态」：若所有原任务已经连接原目标，显示已找到连接，并继续查看云端实际进度；否则仍保持未知，不自动提交。完成一次状态读取后，可明确使用原预览再核对确认，或确认保留当前状态并重新选择。管理操作丢回执也先读取实际进度，不自动重复操作。

选择、预览、提交及未知结果期间使用旅行既有导航保护；返回按钮明确取消本页选择。后台或离线时隐藏内容，同一身份返回后重新读取；身份改变清除草稿和凭证。页面刷新不持久保存本页草稿或预览，重新进入须读取实际状态；不能从刷新推断写入已取消。

## 实现接缝

| 文件 | 职责 |
| --- | --- |
| `frontend/src/lib/taskPublish.ts` | 验证真实待办 DTO、精确任务/目标选择、状态文案、可管理操作、原清单重连和未知确认的只读核对 |
| `frontend/src/screens/JourneyTasksPanel.tsx` | 独立 Expo 面板，复用 `PlaceFence` 完整身份前后核验，前后台/离线遮蔽，选择与预览保留，明确确认及冲突处理 |
| `frontend/src/screens/TripsScreen.tsx` | 从原准备卡片打开面板，返回原旅行，复用既有旅行操作导航锁；不修改后端实体或自行调用 provider |

来源 DTO 是 `id/name/provider/accountName/accountOwner/primary/writeAuthorized`，与日历来源不同，没有日历面板的 `accountId`。旅行状态按 `journeyId` 读取，只接受当前旅行任务和对应发布记录；预览必须与本次明确选中的完整任务集合、原目标一致。列表每页 12 项，预览完整显示本次选中内容。按钮沿用 Paper 与现有主题，触控内容高度至少 44，选择控件使用既有 `SelectionRow`。

发布状态 `published` 结合 `localChangesPending` 判断当前内容；`true` 为待同步，`null` 为待核对。`canManage=false` 的项目只显示状态。断开或删除不会提供盲目重建按钮。重试创建是否只能查找原任务仍由现有后端持久状态决定，前端不重置首次发送标记。

`GET /api/task-publish/state?journeyId=...` 每 10 秒读取一次本地状态，后台暂停；不直接请求第三方。状态读取期间禁用暂停／恢复等修改操作，回到前台先重新读取，避免用旧状态发出操作。`POST /preview` 不写入队列；`POST /confirm` 明确连接选中任务。冲突预览经已有后端读取远端，用户的两种明确决定继续用 `/publications/<id>/conflict-confirm`。详细权限、持续同步及删除/重连规则以 [TASK-PUBLISH](TASK-PUBLISH.md) 为准。
