# Expo 跨来源重复照片提示

这是前端候选，尚未组合后端、构建、浏览器验收或部署。接口按后端 `e436b6804fabfbd999eb51980336c0a2fd520f35` 的 `docs/MEDIA-DUPLICATE-HINTS.md` 实现；前端基线为 `fd4497ba28cc64c8761ff8d4be0de7d3326313ab`。

## 使用路径

1. 相册打开本人已保存的静态照片，在原详情里点击「查找重复照片」。有未保存或待核对的修改时先处理原草稿，不自动丢弃。
2. 在详情内查看「展示副本一致，原图未核验」、来源、缩略图和本次检查数量。每页 20 张，上一页／下一页分别明确发起读取；「重新查找重复照片」回到第一页。
3. 点击「打开原照片」进入其原 ID 的既有详情，可以沿原 revision 编辑。点击「返回重复提示」重新读取原目标及原页码；修改尚未保存时沿现有离开确认，可以取消离开保留草稿。返回时目标已移除则提示错误，不恢复旧快照。

只比较不同来源的净化展示 JPEG。不是原图、视觉近似或视频重复判断；没有结果也不能证明原图不同。`capped` 或 `unverifiable > 0` 时明确显示「仅检查了部分已保存照片」，不把 `total` 当作全库重复数。本功能不删除、合并、上传、分享或授予电视权限。

## 接缝与失效处理

- `photoDuplicates.ts` 检查目标 ID／revision、固定依据与标签、分页和覆盖范围、本人静态照片及原预览路径。只接受原 Photo DTO，Google 与设备上传来源保持区别，不把 NULL Google 账户当成本地许可。
- `PhotoDuplicateHints.tsx` 是原详情里的轻量面板，没有新弹窗或自动加载 effect。`testID=photo-duplicate-hints`；结果行是 `photo-duplicate-<原ID>`；打开按钮的 accessible name 为 `打开原照片 <caption|displayFilename|ID>`。
- `PhotosScreen` 使用原成员／家庭／会话 `PhotoReadFence`、前后台 epoch 与原编辑草稿门禁。读取前后核对原照片元数据及来源投影，原版本或来源变化时拒绝安装结果；打开详情还核对结果原 ID／revision／source，不复制为新照片。所有新增请求使用现有同源有界 transport（20 秒、1 MB JSON）并在隐藏／离线时中止。
- 已显示提示沿现有 5 秒轮询核对最多一页的原照片元数据和账户负向失效信号；没有再次全库扫描。照片移除／版本变化、账户显示不可用、请求失败时清提示；成员变化清私人状态，隐藏／离线清提示但保留既有编辑草稿。恢复后不会自动重新扫描。
- `/accounts` 的 photos／needsReauth 只用于额外清除信号，不能证明完整服务端授权或实时有效性（例如服务端 client secret 配置变化不完整投影在账户 DTO）。结果代表本次明确扫描时的后端检查；完整来源授权始终由 duplicates 接口及原详情／预览服务端执行，不显示“实时核验通过”。
- 返回仅记原目标 ID 和页码；不会缓存还原旧详情或重放保存。未修改 Google 入口、设备上传确认或既有电视授权操作。

## 本轮验证边界

定向 Node 检查覆盖 DTO／分页／部分覆盖、原预览路径、源与版本变更、真实 PhotoReadFence 身份变化、实际 TSX 在合成 React／native／transport 环境中的显式扫描、原 ID 编辑返回、草稿保留和离线迟到响应；完整 frontend 类型检查通过。首轮 UI 测试树对 undefined 子节点递归导致 4 项测试适配失败，修正后只重跑这 4 项通过；首轮 8 项合同检查保留。冻结前按真实后端校正云账户为 32 位十六进制（媒体为 24 位），并加入错误账户形状拒绝；第三轮 12/12 与完整类型检查通过，旧失败原件保留。

这些合成 transport 检查不代替真实 Flask／SQLite、Edge 浏览器、生产、Google 实际账户或实体电视验收。后端需要由集成人合入已审提交，并对组合做正式构建与浏览器检查。
