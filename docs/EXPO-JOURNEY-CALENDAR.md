# Expo 旅行日历同步

本页记录从 `f48c02dc51b6610a1f2af20a3b8dbc44286efda7` 开始的源码候选，尚未部署；实际安装身份以 [README](../README.md) 为准。沿用 [日历发布 API](CALENDAR-PUBLISH.md)，不新增依赖、路由或表。共享视觉遵循 [Expo 官网风格](EXPO-SITE-STYLE.md)。

## 操作

旅行详情的「同步到日历」打开同页工作区。选择本人已经连接的日历，预览所有日程及完整标题、时间、地点和备注，再点击「确认加入同步」。日程较多时按 12 项分页；入队只表示请求已接收，远端已完成须看「云端已确认」。即使原发布已完成，只要本地内容又改变，就显示「本地有新修改，等待云端确认」。

缺少写入授权时可以先入队，随后点击相应账户的「开启日历写入」，由本人在 Microsoft／Google 完成授权。回到看板后，从原旅行重新打开同步状态。授权返回地址沿用现有账户页，暂不提供跨 OAuth 自动返回旅行；不会携带旅行草稿或私人内容到 URL。没有来源时可进入账户连接设置。

日程发布不会添加参与者或发送邀请。停止同步保留云端事项；冲突、旅行时间语义变化须先对照本地与云端，再明确确认。已暂停但仍需时间复核的记录不能直接恢复或重试。本地删除不会自动删除远端。

提交响应丢失时显示结果未知，只允许刷新读取当前进度，不自动再提交。原操作可能已完成；应核对后返回旅行再决定下一步，不把排队状态当作失败。当前页面不提供跨刷新持久化操作记录，队列以服务端状态为准。401 也可能发生在提交后，重新登录后先读原旅行的进度；不能认为请求一定没执行。

## 组件与边界

- `JourneyCalendarPanel({journeyId,onBack,onConnections})` 由旅行详情接入；内部读取 `useHousehold` 的完整身份，按身份及旅行重新挂载。
- `lib/calendarPublish.ts` 提供响应白名单检查、已确认与待同步区分、动作条件和全天排他结束日期显示。时间保留服务端明确偏移，不随浏览器时区悄悄变化。
- 每次请求前后使用已有 `PlaceFence` 核对 household／member／auth_version／CSRF。失去焦点、后台和断网时隐藏私人日历数据；返回时重新读取。页面每十秒只读刷新，任何写入仍须用户操作。
- OAuth 仅接受已有 `openSyncProvider` 严格验证的提供商地址与本站回调，不打开服务端返回的任意 URL。读权限不等于写权限；实际日历编辑权仍由 worker 请求提供商确认。
- 已确认队列属于持续同步授权；退出家庭登录不等于停止过去明确授权的 worker 操作。后端当前会话修正另见 [会话边界](CALENDAR-SESSION.md)，在组合源码中接入。

Node 十一项纯逻辑测试通过，覆盖不同旅行/来源、重复 ID、缺失授权字段、旧成功但有新修改、暂停复核、非法覆盖预览、全天日期及无效回执。作者独立安装锁定依赖，完整 TypeScript 检查通过。源码接线、真实临时浏览器组合、四宽视觉与正常 TLS 部署须另外记录；这些检查不代表本人真实 Microsoft／Google 写入已验收。
