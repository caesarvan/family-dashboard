# Expo 首页卡片布局

**已于 2026-09-17 14:56:51（北京时间）发布，14:57:27 正常 TLS 读回通过。** 首页布局复用原本人布局 API，保持独立电视设置和数据权限；完整运行身份、R2 本地验收与服务器原件见 [本轮验收](EXPO-HOME-LAYOUT-ACCEPTANCE.md#expo-home-layout-release)。

## 使用方法

1. 使用成员账户打开新版首页，选择「安排首页」。
2. 在「安排我的首页」中，用「上移」「下移」调整日程、共同资金、待办、采购和旅行的顺序。
3. 勾选或取消显示；首页至少保留一张卡片。隐藏只改变首页，数据和导航入口仍保留。
4. 「恢复默认布局」只修改当前草稿；确认后点击「保存首页布局」。
5. 看到保存成功后返回首页。同一账户的手机和电脑会读取这份布局，伴侣和电视仍使用各自设置。
6. 不想保存时选择「放弃修改并返回」，再点「确认放弃修改」。

编辑器沿用 Expo 风格的白底、浅灰圆角卡片和黑色主按钮；上下移动与显示选择均支持键盘，无需拖拽。
当前版本暂不支持的未来卡片不会被删掉；编辑器显示其数量，服务器保留其设置。

## 冲突、断线与身份变化

| 情况 | 页面行为与下一步 |
| --- | --- |
| 其他设备先保存，返回 409 | 草稿保留。点「查看最新首页布局」，核对后选择「采用当前布局」或「保留我的修改」。保留后若仍有差异，需要再次明确保存。 |
| 发起 PUT 前，身份检查网络失败 | 尚未尝试保存，不标记未知写；保留草稿，允许明确重试。 |
| 已尝试 PUT，但响应或后置身份核对失败 | 保留原提交意图，显示结果尚未确定。点「核对首页保存结果」只执行读取，不自动重发 PUT。 |
| 未知结果读回 | 展示刚读取的顺序、显示状态与版本；本人明确选择采用当前布局或保留修改后才结束核对。当前内容与草稿一致不代表取得了本次请求的回执。 |
| 同一身份下离线、后台或失去页面焦点 | 隐藏布局并取消异步请求，草稿与未决意图仅保留在内存，未保存状态的导航保护继续生效。恢复后先核对身份并 GET；版本未变恢复草稿，版本变化则显式选择保留哪一版。 |
| 成员、家庭、认证版本或 CSRF 改变 | 清除旧身份的布局与意图；迟到响应不能重新显示旧数据。 |

草稿未保存、请求进行中或结果尚未核对时，首页编辑器与根导航共同阻止误离开；浏览器离开页面也会触发提示。
草稿及未决意图不写入 URL 或本地存储。强制刷新、关闭浏览器或退出身份后不提供跨会话恢复回执。

## API 与数据约定

复用现有接口，不新增路由、表、依赖或迁移：

| 请求 | 返回／提交 |
| --- | --- |
| `GET /api/dashboard-layout` | 本人的 `{revision, order, hidden}`；尚未保存时 `revision: 0`。 |
| `PUT /api/dashboard-layout` | 只接受 `{revision, order, hidden}`，需要有效成员会话、同源 JSON 和 CSRF。成功返回规范化布局及版本。 |

当前已知 key：`calendar`、`finance`、`tasks`、`shopping`、`trips`。
客户端要求五种已知卡片完整、顺序不重复、至少一种显示；GET 中的未来 key 保留在读取结果中。
PUT 只提交当前已知 key；服务器在同一写事务内保留原有未来 key 及其隐藏状态，不允许旧客户端新建未知 key。

保存采用 revision 比较：版本不匹配返回 409，不覆盖；有效无变化保存不增加 revision，实际变化增加一次。
接口没有 requestId 或操作回执查询。未知保存的恢复只能读取当前布局，不能把匹配状态解释为原请求执行证明。
布局归属来自当前成员及签名家庭，不接受 `owner` 参数；匿名及电视身份不可读写成员布局。

后端候选在 `BEGIN IMMEDIATE` 后和提交前核对真实成员会话，失效则回滚，包括审计记录。
GET 在读取事务内检查身份，并在释放快照后再次核对，以观察并发撤权。
本批没有改变 `/api/preferences` 的主题、密度和默认日程范围协议，也没有为该接口增加 CAS。

## 开发与接线

| 文件 | 职责 |
| --- | --- |
| `frontend/src/screens/HomeLayoutPanel.tsx` | 内存草稿、冲突／未知结果核对、生命周期隐藏、放弃确认。 |
| `frontend/src/lib/homeLayout.ts` | DTO 投影、已知卡片操作、版本重核对、请求及前后身份保护。 |
| `frontend/src/screens/HomeScreen.tsx` | 「安排首页」入口；已有首页继续按服务器布局渲染。 |
| `frontend/src/screens/HouseholdApp.tsx`、`lib/types.ts` | `onHomeLayoutPending` 接入 `home-layout` 来源导航锁，按当前身份及首页路由约束；不清除设备或改期的锁。 |
| `frontend/src/lib/household.tsx` | 按完整身份及单调 revision 安装布局；已确认保存立即更新首页，迟到的旧刷新不能回退顺序。 |
| `dashboard_preferences.py` | 本人布局 CAS、未来 key 保全、事务内与读取后会话检查。 |

关键可访问名称：`在首页显示：共同资金`、`上移：共同资金`、`下移：共同资金`；其他卡片使用对应名称。
固定 testID：`home-layout-panel`、`home-layout-card-{key}`、`home-layout-unknown`、`home-layout-review`。
顶部返回控件的可访问名称为「关闭首页布局」；底部使用「返回首页」或「放弃修改并返回」。
请求前后核对成员、家庭、认证版本和 CSRF，同时检查当前页面 generation；只有 PUT 自身明确拒绝且后置身份检查成功，才按确定拒绝处理。
前台恢复、未知结果核对及冲突读取不自动保存，也不自动用新 revision 覆盖。
只有真实身份变化、明确放弃或组件卸载才清除草稿；普通后台和断网不视为放弃修改。
