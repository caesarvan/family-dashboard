## 使用与兼容

新建本地日程默认仅创建者可见，明确选择家庭共享后才向家庭成员及已配对电视显示。负责人 `owner` 表示谁参与安排，与权限无关；把负责人改为伴侣也不会移交私人内容。共享日程仍可由家庭成员协作编辑／删除，只有创建者能收回共享。私密日程只有创建者可读写，电视永远不能读取。

旧记录没有隐私字段，维持原家庭共享行为，不推断历史创建者、不自动收回已授权范围；旧记录不可通过填写创建者或切换私密来占有。已明确选择的云来源及旅行生成日程保持既有共享／只读或旅行编辑规则。未选择的云来源不会因本批自动同步。

## DTO 与写入

原 `CalendarEvent` 增加可选字段：`visibility: 'private' | 'shared'`、`createdBy: string`。新记录两者都有；旧共享、云镜像和旅行派生日程可继续两者都无。创建者是服务端当前有效家庭成员 ID，不是负责人或外部账户 ID。

| 请求 | 合同 |
| --- | --- |
| POST `/api/items/events` | 缺省 visibility 为 private；明确 shared 才分享。客户端不得提供 createdBy，服务器从会话生成。原返回 id/revision 不变，后续从 state 读取。 |
| PATCH `/api/items/events/:id` | 使用原 revision；省略隐私字段保留。createdBy 不能改变，原相同值兼容；仅创建者可改变 visibility。旧无字段对象不接受新增隐私字段。 |
| DELETE `/api/items/events/:id` | 沿同一读权限及原 revision；隐藏或不存在的 ID 返回 404。电视写入仍 403。 |
| POST `/api/calendar/import` | 新导入默认 private，可明确 visibility；createdBy 由会话生成。同 UID／归属／开始时间重复导入保留原创建者及可见范围，不能覆盖另一人的私密记录；批量失败回滚整次导入。旧共享导入记录保持旧策略。 |

错误码：400 `invalid_calendar_privacy`（非法范围／伪造创建者）；403 `calendar_privacy_forbidden`（无权改变共享范围／旧对象没有可核对创建者）；404 `calendar_event_unavailable`（不可访问）。原版本冲突仍 409，原会话、CSRF、Origin 与成员撤权机制保持。

仅缺少两个字段的旧对象兼容共享；只有一个字段或损坏的隐私元数据不会降级为共享。服务端拒绝以不完整元数据读写；没有自动修复或静默认领。

## 统一访问路径

`calendar_privacy.py` 提供同一对象策略：state 的日程投影、普通 CRUD／ICS、助理 records／搜索／brief／显式上下文读取、个人导出及电视均使用该规则。侧重和时间重叠计算只是显示，不能代替服务端权限；客户端失去原对象后应隐藏旧详情。

个人导出新增 `personal.calendarEvents`，仅含本人当前私密日程；勾选共同记录才包含 `shared.entities.events` 中当前共享记录。两处保留 id/revision 和隐私字段，不包含同步凭证。summary 计数使用同一策略；ZIP 生成后再核对当前日程快照，共享撤回、删除或更新时拒绝交付旧 ZIP。助理搜索在旧快照释放后重读日程，过滤已收回内容与计数。

## 验证与边界

定向测试使用真实临时 Flask／SQLite、合成两成员和已配对电视，阻断网络。覆盖私密默认、负责人非 ACL、伪造创建者、明确共享／收回／旧版本冲突、旧共享及云／旅行兼容、损坏字段、助理和导出、ICS 重导；实际结果与失败原件由作者交付记录固定。

本批不实现云日历“仅同步给自己”的新来源模式、不转换旧数据、不向原服务商写入，也不改变已经授权的家庭云来源。后续前端组合、真实浏览器及生产发布见文首验收；本人 A–D 完整验收仍另验。
