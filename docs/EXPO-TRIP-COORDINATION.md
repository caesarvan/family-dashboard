# Expo 旅行、地点与日历

这是本轮源码候选的使用与接线说明，尚未部署；当前安装版本见 [README](../README.md)。界面使用现有 React Native／Paper 组件及 [Expo 官网视觉规范](EXPO-SITE-STYLE.md)，不新增依赖、页面路由或数据表。

## 使用路径

1. 在旅行详情点「旅行地点」，选择一个目的地，核对名称、日期与可见范围后保存。默认是私人、已计划、隐藏坐标；经纬度可以留空。保存前的建议和取消操作不会创建地点。
2. 点「在地图查看这个地点」，进入按旅行筛选且选中该地点的地图。从地图可以查看关联旅行或旅行照片，并返回原筛选、页码和地点。地图正在编辑或保存结果未确定时，返回按钮与其他导航一起禁用；先完成核对或取消编辑。
3. 在旅行详情点「同步到日历」，明确选择本人来源、预览，再确认加入同步。队列受理与云端确认分别显示；存在冲突或时间语义变化时，先比较再明确决定。完整规则见 [日历面板](EXPO-JOURNEY-CALENDAR.md)。

普通旅行日期修改会更新关联本地日程，由已经授权的日历队列继续同步。准备事项截止日期、地图地点日期目前不会自动移动，仍需分别核对；本轮不宣称已经完成所有跨模块日期协调。地图地点不是实时地理编码，也不会因旅行结束自动变成“已到访”。

## 接口与接手

- `TripsScreen` 在当前页面管理子面板；仅保存旅行 ID、基础旅行 ID 和经过 `safeMapView` 清洗的筛选信息。返回旅行时重新读取记录，不使用地图传来的私人数据快照。
- `JourneyPlacesPanel({journeyId,onOpenMap,onBack})` 沿用 [地点 API](JOURNEY-PLACES.md)。旅行版本检查在实际保存事务中执行；重复请求先核对原回执，不能通过重试重复创建。
- `JourneyCalendarPanel({journeyId,onBack,onConnections})` 沿用 [日历发布 API](CALENDAR-PUBLISH.md)。缺少写权限时进入现有账户授权流程；OAuth 返回后需要从原旅行重新打开同步状态。
- `MapScreen` 新增可选 `onBack`，在内部使用相同编辑／未知提交锁控制返回；现有 `MapWorkspace` 调用不必传此参数。照片仍复用 `TripPhotosScreen({journeyId,onBack,...ScreenProps})`。
- 当前路由失去焦点或完整身份改变时清除子面板位置；各子组件独立重新验证身份和访问权限。页面刷新不恢复未保存的草稿或未知提交凭证。
