# Expo 页面与视觉接缝

本轮按用户最新要求参考 [Expo 官网](https://expo.dev/) 当前界面：白色画布、近黑文字、黑色胶囊按钮、浅灰大圆角区块和清楚的标题层级；登录页也去除天空渐变。标准交互继续使用 React Native Paper，输入框保留 8px 圆角；字体使用 Inter 优先的系统回退，中文不依赖远程字体。实页依据及具体尺寸见 [官网风格](EXPO-SITE-STYLE.md)，其优先级高于较早生成的 `expo/DESIGN.md` 视觉描述。

用户已明确不继续旧主题风格。Expo 不再按已保存的 forest/ocean 值套用旧配色，也不再提供旧主题菜单；服务端值保留供经典页和电视使用，不进行用户数据迁移。现有三种主题的历史验收不是本轮视觉验收。

## 页面与操作

- `/app`、`/app/calendar`、`/app/tasks`、`/app/shopping`：已实现日常功能。
- `/app/trips`、`/app/photos`、`/app/assistant`：本轮组合相应模块的真实操作，不再把主入口跳转经典页。
- `/app/connections`（2026-09-17 03:01已发布）：本人账户授权、日历／清单来源选择、共享预览、逐来源同步状态、失效同步清理和断开确认。更多页的「账户与自动同步」及顶部「连接与账户」均进入此路由，详情见 [账户界面](EXPO-ACCOUNTS.md)。
- `/app/finance`：保留资金概要；个人账本及详细财务管理仍在经典页。
- `/app/inventory` 已接入家庭物品；更多菜单与采购页的“查看家中物品”进入新版。助理命中库存后只传受限 ID 和一次请求标识，详情重新核对身份、权限与当前版本，不使用搜索快照直接写入。
- `/app/map` 已实现足迹地图、地点管理和旅行相册入口，使用原地点／旅行／媒体接口。从地图打开旅行或只读相册时，URL 仍为 `/app/map`；可返回原筛选、页码和选中地点。上下文只保留在当前完整会话的内存中，返回后重新读取数据；刷新整页回到地图，不把照片或私人地点写入 URL。详见 [Expo 地图](EXPO-MAP.md)。
- 视口宽度达到 1040px 时使用顶部横向导航，直接进入首页、日程、待办、采购、旅行、相册和助理；更多菜单收纳资金、家庭物品、地图与设置。窄屏保留五个常用底导航，二级页面顶部可一步返回更多。
- 首页和顶部“计划旅行”用受限内部 query 携带一次请求标识及可选旅行 ID，跨路由后由旅行页打开表单或详情；URL 本身不触发保存。
- Google Photos 授权成功固定返回 `/app/photos`；普通 Microsoft／Google 绑定成功或固定错误返回 `/app/connections`。页面在导航根就绪后消费并清除固定 `auth/reason`；真实账户状态重新读取，回调标记不证明绑定已完成。未登录时固定错误在登录页提示。只转发允许的状态，不转发 code、state、token、任意 next 或服务商原始错误。

详细财务、家庭／成员、设备与布局管理，以及旅行的高级分段／资料／云操作继续保留经典入口。地图与家庭物品的主入口已经接入 Expo；普通相册与地图中的只读旅行相册用途不同，后者不提供导入和编辑。

## 边界

所有业务写入沿用服务端身份、CSRF、revision 和对应模块的幂等确认。屏幕按完整 session signature 重新挂载，账户变化时清空草稿；模块仍自行检查读请求的身份和代次。签名只作内存比较，不保存到浏览器存储或页面文字。

日历／清单授权只接受 HTTPS、无用户名密码、默认端口的固定 Microsoft 或 Google 授权端点；Microsoft 为 `login.microsoftonline.com/common/oauth2/v2.0/authorize`，Google 为 `accounts.google.com/o/oauth2/v2/auth`，并核对返回本站对应回调、PKCE 和必要字段，单页跳转。相册授权沿用 Google 固定端点，选片只允许 `photos.google.com`，另开带 `noopener,noreferrer` 的页面保留原状态页。函数返回值只表示 URL 校验通过，不证明本人完成授权或浏览器允许打开标签。

原生 iOS/Android 的账户 Cookie 流程及安装包未在此阶段验收；同源 Expo Web 是实际交付目标。具体安装身份以 README、HANDOFF 和独立发布证据为准。
