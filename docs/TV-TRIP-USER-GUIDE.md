# 电视单趟旅行回顾：使用说明

**已上线。** 2026-09-21发布的单趟回顾可在[家庭看板](https://home.caesarcharles.world/)使用。生产77/9、源码 `d4346d3`；上线与读回、构建和分轮浏览器的不同证据见[本批验收](TV-TRIP-ACCEPTANCE.md#tv-trip-release)。实体电视兼容与本人完整场景仍待验；接口以 [TV-TRIP-PLAYBACK](TV-TRIP-PLAYBACK.md)为准。

## 在电视开始一趟回顾

1. 电视浏览器打开[电视配对页](https://home.caesarcharles.world/tv)；手机成员在「设备与布局」批准这台电视。已配对设备可直接使用。
2. 打开已保存旅行 → 旅行回顾 →「在电视回顾」。选择一台电视，再选择属于这趟旅行的一条已共享路线，或「不显示路线」。路线可以分页选择。
3. 点击「核对电视内容」，查看旅行标题、日期、获准媒体数量及路线。媒体必须已家庭共享且明确授予这台电视；此步骤不会新增共享或电视许可。
4. 点击「开始电视回顾」。之后可「暂停回顾」「继续回顾」、调整照片间隔、切换媒体，或「返回家庭看板」。两台电视分别选择与控制，不会同时开始。

有可展示路线而没有媒体时也可以开始，此时隐藏上一项／下一项；只有标题且无路线、无媒体不能开始。没选路线就不推断路线。照片和路线同属旅行，不表示照片拍于当前站点；照片按实际展示时长推进，视频沿现有实际播放结束事件推进。

电视路线每页8站、约15秒自动换页；暂停回顾也暂停路线翻页。地图只画服务端给出的相邻允许线段，不跨过不可用站位或隐藏坐标。路线最多100站，页码说明当前覆盖；不连接外部底图或导航服务。

## 结果不明时

先点「核对原开始结果」，查询原 requestId 的本人回执及电视当前状态。读取时 `found:false` 不证明先前请求失败，也不表示旧请求不会稍后完成。

- 页面内仍保有原确认载荷时，「重试本次开始」会先查回执，再严格复用原 requestId／token；不会自动重试。
- 刷新仅保留成员身份、设备ID、requestId；重新进入回顾入口会先核身份，再查原回执。浏览器不保存 token、旅行／路线 DTO 或坐标。
- 若刷新后仍无回执，先读当前电视状态，再由用户明确「重新预览」。这只结束本地旧恢复标识，不取消服务器旧请求；刷新丢失路线选择后默认不显示路线，需重新选择／核对。只有再次点击「开始电视回顾」才会提交新请求，原 revision CAS 防止两个未提交预览互相覆盖。

身份核验失败时隐藏内容并提示重新核对；身份变化清除旧内容及匹配的恢复标识，迟到响应不能重新装入旧数据。不要以换一个 requestId 代替核对未知结果。

## 隐私与失效

路线及地点必须当前仍共享且属于原旅行，作者发起也不会显示私密点或扩大坐标精度。媒体沿原逐台许可和来源授权核验，不会因为选中了旅行而获得额外许可。

路线撤共享、删除或转移后清掉原路线，仍获准的同旅行媒体可继续。旅行删除／关联失效则清掉标题、路线与媒体并保留失效状态，绝不自动换成全部相册。若要播放全相册，须在原设备控制中明确选择；返回家庭看板也会清除旅行范围。

电视标题、路线、照片和视频共同受最长15秒显示租约及约2秒轮询约束。断网、隐藏到后台或身份失效会隐藏内容并停播；服务器拒绝后续未授权读取，但不能收回已交付像素或浏览器冻结画面。真实电视浏览器兼容和用户本人场景尚未验收。
