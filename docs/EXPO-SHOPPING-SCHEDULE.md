# Expo 采购截止日与优先级

本页描述开发分支中的主流程增量，尚未构建发布或完成真实浏览器验收。前端基线为 `20e4959969dbb3a9bc6595ecd004e3df91baed80`；字段合同已与后端作者 `7fca1ff886e385d3d6e3a07ed9e786b41b52a3a8` 对齐，后端代码未混入本前端作者分支。两者须经审查后一起集成、构建与验收。AI 采购草案由另一作者交付。

## 使用方式

- 在采购清单新增或编辑物品，可直接填写「采购截止日期（可选）」并选择低／普通／高优先级。日期留空即未设置，普通是旧记录与新记录的默认优先级；不会把旅行出发日当作采购截止。
- 在旅行编辑的「准备清单与采购」使用相同控件。预览会列出负责人、截止日、优先级与预算，再由本人明确保存；采购预算未知与零保持区别。晚于返程的有效日期可以保留，服务端预览提示仍显示供核对。
- 清单和旅行详情显示高／低优先级、未设日期及未完成项的逾期／今天截止状态，日期判断沿用北京时间。排序依次为未完成、最近截止、同日高／普通／低，条件相同保留原次序；未设日期排在有日期之后。完成项不显示逾期。
- 从旅行详情进入「调整日期」，采购默认全部保持原截止。只有未完成、有日期且本地管理的采购可选；已完成、无日期及云来源分别显示实际原因。明确选中后，先核对前后日期，再确认改期。金额、优先级、负责人、图片和原采购身份保持。

沿用现有 Paper 输入框、三级选择和浅灰区块；日期与优先级在宽度足够时并排、窄屏换行，不增加页面或新的 UI 依赖。真实 390／1280 宽布局和点击测量仍由后续浏览器验证确认。

## 兼容与数据传递

`ListItem` 和两种 `Purchase` 类型允许旧字段省略。运行时读取和新表单出站统一解释为 `due: ""`、`priority: "normal"`；非空日期须是 2000—2100 年的有效 `YYYY-MM-DD`，优先级仅接受 `low|normal|high`。`null`、布尔值、无效日期或枚举不会被当作默认值。

普通采购通过原 `/items/shopping` POST／PATCH 保存，PATCH 继续带原 revision。旅行 `initialPlanningDraft`、预览出站、v1/v2 严格解析与 JSON 导入预览完整传递两字段。编辑已关联旅行或行程分段时以 live shopping 实体为准：明确空 `due` 覆盖旧计划日期，`normal` 覆盖旧优先级；不使用 `live.due || plan.due` 恢复旧日期，也不改变 workflowKey 或关联实体编号。

改期快照的 `capabilities.shoppingDue` 接受严格 boolean，兼容旧服务的 `false` 与新服务的 `true`。旧服务显示暂不支持采购截止联动。可选采购必须有一致的前后日期及空 reason；与能力、完成／无日期原因冲突的响应会拒绝读取。原 snapshot、预览令牌、成员核对、版本冲突和幂等回执恢复流程继续使用，不创建额外采购任务或云发布。

保存不确定时保留原界面的恢复路径：普通采购先关闭并刷新核对，不能连续重发新增；旅行保存沿用原操作编号；改期通过原操作回执核对，不再平移一次。冲突时保留草稿，读取最新并确认后才能重新预览。读取旧记录不会因此写库或执行迁移。

## 优先级选中语义修复

组合版本 `74369cfa197292d07c47ad2b632900b17fb0b252` 的本地真实浏览器 R2 已通过普通采购、AI 本地草案与明确采购改期三条流程；第四条离线流程在进入离线前发现：原优先级分段控件虽然视觉选中正确，却未在当前 Paper／React Native Web 组合中输出 `aria-checked`。这个失败不能当作离线草稿已验收，也不能通过删除选中状态断言解决。

采购编辑与旅行采购编辑现在复用现有 `SelectionRow` 单选控件，保持「低／普通／高」及原可访问标签、48 像素点击高度与可换行的紧凑布局。三项属于一个具名 `radiogroup`，视觉状态、原生 `accessibilityState` 和 Web `aria-checked`／`aria-disabled` 使用相同值；沿用已有空格与方向键行为。保存结果不确定时仍保留已选优先级，禁用操作不会改变草稿或再次提交。其他分段控件、保存接口和浏览器断言未改。

本次定向组件测试共 21 项通过：新增两项先在旧实现上实际失败，再在修复后通过；覆盖点击／空格切换的互斥选中、原生状态与禁用行为，并加强旅行编号标签及未知保存后的状态保留检查。测试执行实际 `ItemEditor` 和 `SelectionRow`，Paper／原生宿主仍是替身，因此不代表真实 DOM、屏幕阅读器或手机原生设备验收。本次修复还须经非作者审查、新前端导出及原真实浏览器断言复验，原失败证据保留。
