# 我的旅行费用（Expo）

本页描述独立候选界面，尚未构建正式导出、运行组合浏览器或部署。接口按 `JOURNEY-FINANCE.md` 的五个本人接口接线；后端合入前不会有可用的服务器归集能力。

## 使用

1. 打开一趟已经完善并保存的旅行，点击「我的旅行费用」。旧旅行没有对应工作流时，先沿原流程完善并保存。
2. 「选择实际付款」后，可搜索本人已有账本付款。选择一笔有效人民币消费，填写「归集金额」，依次「预览归集」「确认归集」。确认前不保存归集。
3. 成功后直接读取当前列表；「仅本人已归集」和「需核对」分别显示，统计覆盖全部分页。共享预算单独显示，不据本人部分记录计算家庭剩余预算，不累加订单、采购实付、旅行手填已付或储蓄。
4. 退款或原付款关系变化后，点击「调整归集」重新核对金额，或「解除归集」→「预览解除」→「确认解除」。不会改写原旅行、付款或采购。查看原付款按原 ID 读取既有对账接口；「返回旅行费用」保留原列表与搜索页。
5. 财务页的「我的旅行费用」可管理全部本人历史；原付款详情也有「这笔付款的旅行归集」。已删除旅行或付款不会借旧快照恢复标题，仍可从历史解除原关联。

## 失败和身份

- 确认 POST 前固定请求编号。当前浏览器的 `sessionStorage` 仅保存身份摘要、原编号和原不透明预览 token；不保存金额草稿、账单、标题、CSRF 或账户信息，不使用 `localStorage`。无法保存该最小恢复记录时拒绝发出确认。
- 丢响应、5xx、确认后的身份读取失败均保留原请求。刷新会 GET 原操作回执；`found=false` 不表示未提交，也不触发自动确认。只有明确点击「重试原请求」才重发完全相同的请求体。
- 只有确认 POST 自身的已解析业务拒绝可解除未知状态。409 保留当前金额草稿，要求读取最新版本再预览；身份核验的 409 不是业务拒绝。
- 回执已确认但列表读取失败显示「已保存，资料暂未刷新」，刷新只发 GET。历史回执不保证归集仍有效，界面以当前列表为准。
- 离线、窗口失焦、页面隐藏、应用后台及失去路由焦点都会隐藏费用并撤销在途读取资格。同身份回来重新读取，内存草稿暂时保留；身份变化清空敏感内容并隔离恢复记录。所有读取与写入复用 `PlaceFence` 的前后 `/me` 核验，整个操作最多 20 秒，迟到响应不安装。
- 草稿和未明请求接入应用现有导航门禁，使用独立的旅行费用提示，不复用采购提示。离开未提交草稿需明确放弃；未明请求先核对。

## 定向验证与后续

`node --test tests/test_expo_journey_finance.mjs` 检查金额/接口边界及实际 TSX 的合成 transport、会话存储、失效/恢复行为。它不证明真实 Flask、SQLite、浏览器布局或云账号已通过。两组 TypeScript 检查使用既有依赖只读运行，不安装依赖、不导出 Expo。

后续由固定组合后端与正式 Expo 导出执行真实 HTTPS/Flask/SQLite 三场景，另验证 73→75 两新增表的迁移及保全。该候选不修改数据库、Docker、发布工具或任何远端服务。

自动化入口：`journey-finance-panel`、`journey-finance-hidden`、`journey-finance-summary`、`journey-finance-preview`、`journey-finance-unknown`、`journey-finance-original-payment`；原 ID 卡片为 `journey-payment-<id>` 和 `journey-allocation-<id>`。
