# Expo 旅行导入接线（候选）

基于 `2c2079889d1f6fa2bdd5e8aa37b40e96e1c4c9b1`，实现契约见
[旅行导入方案](EXPO-TRIP-IMPORT-PLAN.md)。本提交负责接线；独立模型、面板和浏览器测试由其他分支提供，尚未组合验收或发布。

旅行列表在「计划旅行」旁增加「导入旅行」。它打开局部 `TripImportPanel`，不持有文件内容或预览凭证。
面板通过 `onPendingChange` 汇报草稿、读文件、保存与未知结果状态；独立 `trip-import` 导航锁由
`TripsScreen` 经 `MapWorkspace`／`AssistantScreen`（若为嵌套入口）传到 `HouseholdApp`。
旧面板或旧身份的回调不能释放新面板的锁。路由失焦时保留仍待处理的导入面板，显式返回由面板负责确认。

`onSaved({journeyId,tripId})` 是异步交接。父层重新执行 `/me → 旅行详情 → /me`，
核验角色、家庭、成员、auth version、CSRF 及返回的旅行标识；成功后才切换到详情和释放导航锁。
窗口失焦、离线、隐藏、pagehide、原生 AppState 非 active 或卸载会中止该读请求并使迟到结果失效。
父层读取失败将错误交还导入面板，后者必须保留已确认的回执，并仅提供重新读取旅行，不能再次提交创建。

接线不写业务数据、不写云日历、不保存私人 JSON 到共享状态。全套类型检查、真实临时浏览器及四宽截图
应在独立分支审查后对同一组合源码执行；不能以本文件或源码提交代替实现验收。
