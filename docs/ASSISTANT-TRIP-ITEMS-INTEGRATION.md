# 旅行简报中的准备事项、采购与分工

状态：开发中，未合入运行版本、未上线。基线为 `886234bf0590b297cb1c33fa2b6d6c83aff3e670`。本批推进完整家庭旅行协作场景中的清单生成与分工；其他地图、日历、改期及真实账号验收仍保留原范围，不因本批测试通过而宣称场景 A 完成。

## 用户结果与接缝

用户输入旅行日期、目的地、总预算及准备或采购需求后，在同一份可编辑简报中核对事项、负责人、截止日期、数量和采购预算，再进入已有旅行预览与明确保存。保存后的任务和采购关联同一趟旅行，刷新或重启后可读取，原操作重试不重复创建。

沿用 `POST /api/assistant/journey-brief`。模型只接收本人这次文字；输出作为建议，由服务端验证后映射当前家庭的有效成员。未知或重名负责人留待选择。模型不能决定真实对象编号、预览令牌、付款、预订或云发布状态。

简报新增 `checklist`、`shopping` 与顶层 `warnings`，具体字段见[简报合同](ASSISTANT-JOURNEY-BRIEF.md)。明确总预算与单项采购预算分别校验；金额为精确整数分，未知保持 `null`。任务的明确日期与相对出发天数互斥，缺截止信息须补齐。原文、未知与有歧义信息保留供核对。采购截止日期本批仅保留备注及明确提示，结构化截止与改期联动仍是后续任务。

没有新业务表、外部平台写入或额外依赖。准备与采购草案进入原 `/api/journeys/preview`，丢弃桥接预览令牌后继续编辑；只有用户在既有保存流程确认才写入。家庭、成员、编辑代次及未知保存结果的原编号保护继续生效。
