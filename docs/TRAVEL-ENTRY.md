# 新建旅行统一入口

本变更位于 `codex/product-travel-entry`，基于提交 `65362fce3296b00d8bf05a6e54b9c89565cfc53c`。这是待独立审查、合入的分支实现；本文不表示已经部署。

## 使用流程

首页的快速记录、旅行卡加号与空态，旅行页的「规划一趟旅行」「开始计划」，以及原管理页的新增旅行，都进入同一个旅行向导：

1. 填写旅行名称、目的地和日期。
2. 点击「预览准备与日程」，核对准备清单、负责人、采购和日程。
3. 如有修改，重新预览；只有当前预览有效时才能确认。
4. 确认后打开旅行详情，生成的准备、采购和日程也能在各自页面找到。

关闭向导或预览不会保存旅行。生成的是本地家庭数据；这一步不会订票、订房或自动发布到云端。后续流程见 [用户手册](USER-GUIDE.md)、[旅行执行页](JOURNEY-EXECUTION.md) 和 [旅行细项](TRAVEL-DETAILS-PLAN.md)。

## 草稿、失败与兼容

- 已打开的旅行草稿或确认页会保留。再次请求新建时提示先完成或关闭，不会静默替换输入。需要另一份草稿时，请先明确关闭当前对话框。
- 开始向导前核对当前成员会话；等待期间的重复请求共用一个入口流程。关闭、切换页面、成员或家庭后，旧响应不能打开或替换后来的表单。
- 会话读取失败会显示重新开始入口，不会创建旅行。旅行组件未加载时提示刷新，不会退回只能保存旅行摘要的旧新增表单。
- 已保存的旧旅行仍保留原编辑入口与 ID；已有旅行的联动编辑继续使用原预览、确认和冲突保护。
- 演示模式仅本地预览，确认不可用；电视不提供新建旅行操作。

最终会话读取与下一次浏览器操作不是一个原子步骤：仅 Cookie 在最后一次读取后变化，要等后续会话检查才能识别。关闭页面也不能撤回已经发送的保存请求。

## 开发接缝与文件所有权

| 文件 | 本轮职责 |
| --- | --- |
| [static/app.js](../static/app.js) | 无 ID 的 `editItem('trips')` 统一调用旅行向导；已有 ID 保持原编辑逻辑。 |
| [static/product-shell.js](../static/product-shell.js) | 旅行页新增按钮使用统一 `data-action="add" data-kind="trips"` 接缝。 |
| [static/journey-ui.js](../static/journey-ui.js) | `JourneyUI.create()` 的草稿保留、会话核对、节点与请求代次保护。 |
| [新入口浏览器检查](../tests/browser_travel_entry_check.py) | 真实临时 Flask、SQLite、Edge 的入口及竞态验收。 |

`JourneyUI.create()` 返回 Promise：成功打开新向导返回 `true`；保留现有草稿、无操作权限、身份变化或加载失败返回 `false`。调用者应等待该 Promise；它不负责提交旅行。资料库、旅行执行页、预览 API、确认 API 和数据库结构均沿用既有实现。

两个旧保护脚本的准备步骤现在通过可见关闭按钮结束原对话框，再创建下一份测试草稿；原迟到响应和禁用旧确认断言保留。不要为测试重新引入可静默覆盖草稿的第二个创建接口。
