# 视频 71→73 Linux 合成迁移演练

本工具仅准备隔离演练，尚未执行 Linux／Docker，不能当作生产迁移或上线证明。不修改已有打包 profile；发布包允许范围仍由另一个已审工具控制。

`prepare` 从固定 Git 导出 db378666 的完整所需 Python 和 deploy 辅助代码、两篇恢复文档及两份夹具来源，并另行导出历史 `8d3e6376a606155ff66a0388e43d04cb7562fe9f` 的全部根 Python 模块。当前候选只能在 db378 基线上新增本工具、测试、本文。每个输入和生成程序都有 SHA，输出独占且复验。容器不需要 Git、pytest，也不复制宿主凭据或实际数据库。

演练按顺序执行十个独立容器阶段：

1. 校验传入的不可变新应用镜像 ID、实际 Python／requirements 字节及 UID 10001。
2. 在该镜像的依赖环境中运行已冻结历史 app 源码，经真实登录、邀请、兑换、待办及成员角色 API 生成两户三库 71/9；增加既有合成财务、路线、私人日程、媒体、电视许可、提醒和确认回执哨兵。不是删表拼装旧库，也不声称使用历史镜像。
3. 复制一个独立的 71/9 失败场景组，真实完整备份主场景三库并调用已审迁移器。
4. 直接从 `/app/app.py` 调用新镜像的 `create_app()`，初始化所有注册家庭；不启动服务器端口、云 worker 或 decoder。
5. 停止该进程后核对旧 71 表的所有 schema、列、行、序列与平台 9 表、新增空两表及触发器、settings 和 marker，全无豁免。
6. 用现有部署文档恢复程序将完整 71/9 备份恢复至全新独立目录并核对。
7. 对另一组三库真实备份后，让第二户数据库只读。UID 10001 下迁移真实发生 SQLite 写入失败，必须观测第一户 73／第二户 71，拒绝重放原 attempt；随后恢复完整三库至新目录并核对。没有替换迁移函数或伪造成功返回。
8. 新两表写入原测试的非空合成不透明字节和播放进度；这不是有效视频、加密或播放验收。
9. 再次真实启动新 app，验证全部非空 73/9 状态保持。
10. 完整备份并恢复非空 73/9，逐库核对回执、旧表和新增内容。

恢复只替换文档程序的目标根路径，保留原恢复算法。为了严格比较，合成会话保持原值；恢复后不启动服务，不代替生产恢复时的会话失效和服务切换流程。失败库、全部三库备份、原始 stdout/stderr、命令、阶段和摘要均留在独占输出目录；不覆盖重试。

## 操作合同

入口 `python -B deploy/media_video_migration_linux_probe.py`：

| 子命令 | 参数 | 边界 |
|---|---|---|
| `prepare` | `--repo --commit --output-dir` | 本地读取干净固定 Git，生成完整输入，不调用 Docker |
| `verify` | `--bundle --input-sha256` | 只读校验输入及正在执行的工具字节 |
| `run` | `--bundle --input-sha256 --image-id --output-dir` | 另行授权后仅 Linux root 调用本机 Unix Docker；镜像必须为完整 sha256 ID |

可直接从已准备目录的 `release/deploy/media_video_migration_linux_probe.py` 调用 `run`。源码与程序只读挂载；仅新建的合成 data、proof 可写。容器 network none、根只读、非 root、cap-drop、禁止提权、1 CPU、384 MiB 同额 swap 上限（不使用 swap）、128 pids、128 MiB noexec/nosuid/nodev 临时目录。每阶段只删除本次创建的容器，不运行 Compose、不挂载任何生产目录，不以环境继承方式传入秘密。

Windows 离线检查只验证准备／篡改／调用隔离合同及真实本地 Python、Flask、SQLite 的闭合阶段。其运行布局将 runtime 与准备源码放在同一目录，并按该目录全部根模块记录身份；这不冒充 Linux `/app` 的镜像文件验证。真实 Unix 权限导致的部分失败与镜像启动仍必须在后续 Linux 运行中实际通过；本工具不以 skip 计作通过，也不重跑旧 Windows 33 项矩阵。
