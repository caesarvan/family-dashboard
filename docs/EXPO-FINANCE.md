## 家庭用户流程

- **共同资金**：查看和手工核对荷包余额、日常预算与支出、旅行准备金、年度旅行预算、长期储蓄、周转目标、近期付款及出资比例。独立展示所选月份逐笔明确共享的消费和退款汇总。本人账单不会自动写入共同余额。
- **我的账本**：按实际存在的月份浏览本人全部记录；输入月份或搜索标题、编号、分类、商品明细，每页 25 条。月度汇总来自服务端全月记录，与搜索结果和当前页数分开。
- **交易详情**：查看原始金额、来源、状态、编号、商品原文以及来源批次。明确核对分类、方向和共享范围；只有付款中的消费与退款允许进入共同汇总，标题、编号与账户不共享。
- **订单、付款与退款**：读取真实候选，选择两笔记录，输入分配金额，预览影响，明确确认。重复关系清楚标明排除和保留的记录。历史关系支持明确撤销，不删除原始流水，不修改云端支付记录。
- **月预算**：为指定月份、币种和分类新增或更新预算。“全部”为同币种总预算，分类预算不与总预算相加；退款按自身日期影响预算，已导入记录未必覆盖所有消费。
- **导入账单**：进入独立导入面板。确认成功后按服务端 `resultMonths` 定位实际月份，跨月显示各月入口；不会根据预览行猜测入账月份。

资产、投资持仓、来源报告和高级财务仍通过明确的经典财务入口管理，未宣称本增量已迁移这些界面。平台文件支持与真实样本限制见 [导入说明](FINANCE-IMPORT.md)，持仓见 [投资导入](INVESTMENT-IMPORT.md)。

## 第一次使用

在手机或电脑登录成员账户，进入「更多 → 家庭资金」。共同资金与个人账本分开展示；账单默认只进入本人账本，导入不会自动改荷包余额。电视不提供个人财务操作。

1. 点「导入账单」，选择来源及支付账单／订单类型，再点「选择账单文件」。支持 CSV、TXT 和无宏 XLSX，最大 2 MiB；也可以使用页面提供的模板。
2. 如果文件有多张工作表或可用的金额列，在弹出的选项中明确选择并重新预览。当前不支持任意日期、标题、币种等字段映射；无法识别的文件须先按已支持格式整理。
3. 在「核对预览」查看新增、重复、冲突、错误数量及每笔金额。重复不再次入账，冲突保留旧值；只要有错误行，本次整份文件不能确认，修正文件后重新选择。
4. 核对后点「确认导入 · 仅本人」，结果页显示实际新增和重复／冲突数量。点「查看已导入账本」进入实际入账月份；跨月文件显示各月入口。全重复或全冲突时会明确显示未新增。
5. 在「我的账本」搜索或打开「查看详情」，先核对来源、分类和方向。需要计入共同消费时明确勾选共享；只共享允许的金额汇总，个人账户与流水明细继续仅本人可见。
6. 需要关联订单、付款或退款时，可在「查找订单或付款」输入标题／编号并点「查找关联」，再选「核对这组记录」→「预览关联」→「确认关联」。发现关系不对可在历史关系里「撤销关联」并确认；该操作不会删除原始流水。
7. 在「月预算」点「新增预算」，核对月份、币种、分类与金额后保存。共同荷包、旅行准备金等人工基线通过「共同资金 → 核对资金」单独维护。

更换文件或选择后旧预览立即失效，必须重新核对。保存连接中断时，留在页面点「核对保存结果」只读回原请求；暂未找到回执可能只是原请求仍在处理，不代表没有保存。若页面提供同一请求重试，仍使用原文件、原预览和原编号；不要用新文件冒充该次恢复。离开导入页不会撤回已经发送的保存，页面内未确认的文件和恢复状态会被清除。

账本提示数据已变化时点「刷新到最新账本」；编辑出现版本冲突时先读取最新记录，核对后再次确认。后台或断网时个人内容会隐藏，回到前台并联网后重新核对身份；这不会删除服务端账本。

## HTTP、金额与版本

接口以 [FINANCE-API](FINANCE-API.md) 为权威。主页面使用 `overview`、`transactions`、`shared`、`reconciliation` 读取；交易 PATCH、预算 PUT、共同资金 PUT 和关联预览／确认／撤销均沿用现有 API。

账本金额、预算和候选金额必须为服务端安全整数分，格式化通过 `BigInt` 仅拆分整数和小数位，不进行浮点汇总、隐式换汇或跨币种相加。手工输入为十进制原币字符串，最多两位小数；账本与月预算 API 沿用原币字符串写入。

共同资金遵循 [基础财务 API](API.md)：`/state.finance` 的八个金额字段均为整数分，`PUT /api/finance` 整份替换，必须发送完整八字段和 `revision`。表单显示原币小数，提交时用整数运算转换为分；未编辑字段保留原整数值，不省略 `travelAnnualBudget` 或 `upcomingPayments`。共同出资比例是独立的 `0..100` 整数，不按金额乘除 100。

连续翻页和搜索携带原 `snapshot`。遇到 `409 ledger_changed` 隐藏旧账本结果并要求明确刷新，不拼接不同版本页面。首次读取和明确刷新不携带旧快照。交易、预算和共同资金提交携带原 `revision`，冲突保留输入并要求用户读取最新版本、重新核对，不能自动覆盖。

交易来源 `provenance.status=recorded` 显示实际批次 ID、文件名／粘贴文本、格式、工作表、物理行范围和首次入账时间。`unknown` 明确说明历史未记录；不按入账时间猜测批次，也不生成原附件下载链接。商品 URL 仅以惰性文本显示。

导入由 `POST /api/finance-hub/imports/preview` 与 `/confirm` 完成；每次明确确认保留原 `requestId`，未知结果通过 `GET /api/finance-hub/imports/results/<requestId>` 核对。回执与交易、批次在同一事务提交，重启后仍可读取同一历史结果。相同编号与原负载／令牌重试不会重复入账；改内容或令牌为 409。GET 404 后仍保留该编号，即使随后重试遇到预览过期 400，也不能据此清除原请求或断言先前未执行。

回执中的 `confirmedAt`、`resultMonths`、数量和可为空的 `batchId` 是确认时事实；以后删改交易不会回写该历史回执，查看当前账本仍须读取交易 API。新记录首次来源保存在原交易 JSON，重复和冲突保留第一次来源；原文件、令牌和内部摘要不会作为回执返回。新增 `hub_import_receipts` 为第六张财务中枢表，完整户内结构由 53 变为 54，平台注册库仍为两表；迁移和包含既有回执的恢复见 [回执发布指导](FINANCE-RECEIPTS-RELEASE.md)。

## 身份与失败恢复

页面实例按完整 `household.identityKey` 建立；私有读取和写入结果通过 `PhotoReadFence` 在业务请求前后请求 `/me`，比较成员、家庭、角色、`auth_version` 和 CSRF。另检查页面焦点、挂载、在线状态、AppState、document 可见性与 epoch。离线或后台立即隐藏私有内容，恢复后重新核对；身份变化清除草稿与结果，旧异步结果不能重新显示。

每次持久写入先保存内存中的操作意图。收到成功响应也需读取真实记录核对；连接断开或无法确定响应时先 GET 读回，不盲目重发 PATCH／PUT／确认／撤销。未读回前禁用新的写入，保留“刷新核对结果”入口。当前状态匹配仅表述为“当前状态与本次操作一致”，不把相似状态推断为唯一历史执行证据。关联确认保留原预览令牌，但未知结果不会自动重放。

若当前详情对应的记录已由另一设备删除，详情 GET 404 后会再次核对完整身份，清除旧详情、编辑与候选，安装真实账本并返回列表，避免重复刷新同一失效 ID。未知写入恢复时发现记录缺失，只说明当前记录不存在，不能据此断言之前未执行，也不会自动重建。

退出页面或换身份不撤回已经发送的写入；服务端的成员权限、CSRF、版本、事务和幂等仍为最终边界。浏览器关闭后以内存草稿恢复为保证范围之外，导入持久回执由独立面板和后端负责。
