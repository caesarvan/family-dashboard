# Expo 家庭助理

实际上线状态见 [交接](HANDOFF.md) 与 [Expo 交付](EXPO-RELEASE.md)。本模块使用 React Native／Paper，颜色与形状继承统一 Expo 主题；路由由应用集成，不加载旧助理 DOM。

## 使用

1. 输入请求，例如“待办：明天预约保洁；确认酒店”或“采购：收纳袋；转换插头”，点“整理并预览”。默认使用服务端本地整理；已配置 AI 时可明确勾选 AI，并独立选择是否发送近期日程与待办标题。
2. 查看真实服务端说明、每项类型、负责人、日期或数量，取消不需要的项目，再点“确认保存 N 项”。只创建服务端支持的本地待办或采购，不自动发布到云清单、记账或下单。
3. 收到回执后显示实际保存的项目，可进入清单查看。修改请求文字后须重新预览，不能把旧草案当成新请求执行。

“搜索：关键词”使用现有本地搜索，支持每页 20 条，包含当前可见的日程／清单／旅行与照片、地点文字，**不含尚未合入的库存搜索**，不向模型发送搜索内容。只展示文字结果，不缓存图片或坐标；离线、离开前台会清除结果，前台每 10 秒重新读取，失败不会恢复旧结果。旅行简报等完整工具仍可显式进入经典助理。

## 真实接口与结果不明

`GET /api/assistant/brief` 读取模型配置可用性；`POST /api/assistant/plan` 发送 `{prompt,useModel,includeHouseholdContext}`，预览不执行业务写入。确认使用 `POST /api/assistant/plans/<planId>/apply` 的 `{selected:[index...]}`，以**原服务端计划 ID**实现幂等；没有另造 requestId 或假回执。

现有后端没有只读 plan／receipt GET。apply 超时、5xx、网络断开或成功响应结构不完整时，页面保留并锁定原 `planId` 与 `selected`，不会自动重发，也不能换选项／生成新计划。先点“读取最新清单”（真实 GET state 与上下文刷新）；这只证明当前清单已读取，**不能据标题推断本次计划是否执行**。用户核对后，可明确点“继续原确认”，发送完全相同的 ID 与载荷：服务端已完成则返回原回执，未执行才完成原确认。再次断线仍使用同一份意图。

页面每次 I/O 前后用真实 `/api/me` 核对成员、家庭、auth_version 与 CSRF 会话。身份变化清草案，离开屏幕后忽略迟到结果；草案／未明回执仅在本页内存，离开不会自动执行或持久保存。共享应用的完整 identityKey 重挂载由集成人接入。模型生成失败保留输入，旧预览不能继续确认；用户可主动改为本地整理，不自动换 provider 或重调模型。

## 验证

```powershell
cd frontend

cd ..
python -B -X utf8 -m pytest tests/test_expo_assistant_flow.py -q -s
```

专项用当前 TypeScript flow 与真实临时 Flask／SQLite／成员 Cookie／CSRF，合成数据验证预览不执行、选择性确认、回执、提交前与提交后丢响应、畸形成功回执、同 ID 同载荷继续、身份／新会话／离页迟到清理、本地搜索分页及后台隐藏。只替换丢响应和页面生命周期，不替换业务 API，不调用外部模型或生产。它不等同真实 Expo 导出浏览器或原生设备验收；界面布局、共享路由接线和组合浏览器另外记录。
