## 查找已有旅行（2026-09-18 已上线）

输入「找一下冰岛旅行」「搜索 冰岛旅行」「查找：冰岛旅行」后点「整理并预览」，使用现有本地搜索，不误入新建旅行简报。三种搜索前缀均支持有／无冒号；仍按原接口对关键词作字面匹配，不自行删掉“旅行”等词。即使先前勾选 AI，本次搜索也不发送给模型，页面显示「本次只查找已有记录，不会发送给 AI。」真正的旅行规划和「待办：」「采购：」分流保持。

旅行结果点「查看旅行」进入当前详情。只传该结果的旅行实体 ID，既有 TripsScreen 重新读取行程列表和详情；旧旅行则重新读取当前共享资料，删除或权限变化显示实际错误。搜索标题、日期或嵌套行程内容不能直接成为编辑草稿。

点「返回助理」后保留本页原输入和搜索页位置，通过当前身份复核后重新搜索，不恢复旧结果对象。分段、改期、资料和导入的未完成状态继续沿用现有导航保护；换身份清空，前台／联网恢复仍先核对。没有新增路由、API、权限、存储或云操作。

## 原有旅行规划入口

在助理输入包含“旅行／行程／旅游／出发日期／返程日期”的文字，点「整理并预览」可在新版打开旅行简报；明确的「待办：」「采购：」「搜索：」始终优先，不会因为标题含“旅行”而改变请求类型。「规划一次旅行」入口可以从空白开始手工填写。

旅行简报只把本次原文发送给用户明确选择的 AI，不附带普通助理中选择的近期记录。首次提取由该次点击触发，失败后不会自动重试。补齐未知日期、总预算、目的地和成员后，服务端预览校验，随后进入可编辑旅行计划；必须再次预览并明确确认，才能保存行程、准备和采购。界面中的负责人是本地分工，不代表已指派到云清单。

此入口把简报和新建旅行草稿保留在同一个页面内存中，不放入 URL、浏览器持久存储或跨用户全局缓存。离线或离开前台时隐藏旅行内容，恢复时重新核对家庭、成员、认证版本及 CSRF。身份变化清空草稿。关闭简报返回原始请求；保存旅行后可返回助理。刷新、退出登录或离开路由可能丢失未保存草稿，结果未知时继续按原旅行预览和幂等键核对，不重新创建。

此阶段不自动创建地图地点，不确认到访，不自动写云日历或清单，也未扩大已验收外部平台范围。详细交互与白名单见 [旅行简报](EXPO-JOURNEY-BRIEF.md)，原有保存与失败恢复见 [旅行页面](EXPO-TRIPS.md)。

## 使用

1. 输入请求，例如“待办：明天预约保洁；确认酒店”或“采购：收纳袋；转换插头”，点“整理并预览”。默认使用服务端本地整理；已配置 AI 时可明确勾选 AI，并独立选择是否发送近期日程与待办标题。
2. 查看真实服务端说明、每项类型、负责人、日期或数量，取消不需要的项目，再点“确认保存 N 项”。只创建服务端支持的本地待办或采购，不自动发布到云清单、记账或下单。
3. 收到回执后显示实际保存的项目，可进入清单查看。修改请求文字后须重新预览，不能把旧草案当成新请求执行。

“搜索：关键词”使用现有本地搜索，支持每页 20 条，包含当前可见的日程／清单／旅行、家庭物品以及照片和地点文字，不向模型发送搜索内容。结果不缓存图片或坐标；物品可打开详情，本批已补齐旅行详情入口。离线、离开前台会清除结果，前台每 10 秒重新读取，失败不会恢复旧结果。本批范围见上节，固定安装版本以集中验收记录为准。

## 真实接口与结果不明

`GET /api/assistant/brief` 读取模型配置可用性；`POST /api/assistant/plan` 发送 `{prompt,useModel,includeHouseholdContext}`，预览不执行业务写入。确认使用 `POST /api/assistant/plans/<planId>/apply` 的 `{selected:[index...]}`，以**原服务端计划 ID**实现幂等；没有另造 requestId 或假回执。

现有后端没有只读 plan／receipt GET。apply 超时、5xx、网络断开或成功响应结构不完整时，页面保留并锁定原 `planId` 与 `selected`，不会自动重发，也不能换选项／生成新计划。先点“读取最新清单”（真实 GET state 与上下文刷新）；这只证明当前清单已读取，**不能据标题推断本次计划是否执行**。用户核对后，可明确点“继续原确认”，发送完全相同的 ID 与载荷：服务端已完成则返回原回执，未执行才完成原确认。再次断线仍使用同一份意图。

页面每次 I/O 前后用真实 `/api/me` 核对成员、家庭、auth_version 与 CSRF 会话。身份变化清草案，离开屏幕后忽略迟到结果；草案／未明回执仅在本页内存，离开不会自动执行或持久保存。共享应用已按完整 identityKey 重挂载。模型生成失败保留输入，旧预览不能继续确认；用户可主动改为本地整理，不自动换 provider 或重调模型。
