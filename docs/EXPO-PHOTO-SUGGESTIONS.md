# Expo 照片旅行建议（候选）

本人已保存照片的详情增加「查看旅行建议」，复用现有
[来源时间建议 API](MEDIA-JOURNEY-SUGGESTIONS.md)。当前为独立界面候选，尚未组合浏览器验收或发布。

## 使用

1. 在「相册 → 我的照片」打开照片详情。先保存或取消尚未保存的照片说明、共享、旅行及电视设置。
2. 点击「查看旅行建议」，核对当前旅行标题、起止日期，以及按该旅行时区计算的来源日期。
3. 选择一项，再点击「确认关联所选旅行」。当前已关联项会标明，不会重复提交。

日期相符不能证明拍摄地点或实际到访。确认仅更新旅行关联，不新增共享、电视许可或云端写入。
来源时间未知、当前没有日期匹配时，可以继续使用原手动旅行选择框；不会拿本地导入时间猜来源日期。
最多显示前 20 项；有更多匹配时明确提示，其他旅行仍可手动选择。

## 草稿与失败恢复

- 建议不会夹带说明或共享草稿。尚未保存的电视勾选或许可确认也会阻止建议；「取消未保存的修改」只撤销当前本地草稿，不向服务器写入。
- 读取建议、确认以及确认后的核对共用照片详情原有 busy／写锁，期间不可编辑、关闭或重复确认。
- 照片或旅行发生版本冲突时，先「核对当前旅行关联」，再重新查看建议并明确选择。
- 网络中断、服务器错误、无法核对的保存响应，或成功后的详情／图库读取失败，均只提供「核对当前旅行关联」。不会自动重新 PATCH。
- 当前关联是读取时的状态，不是上一操作的执行回执。核对失败仍维持只读恢复入口，不显示保存成功。
- 切换照片、筛选、草稿或重新读取详情会丢弃旧建议。窗口失焦、后台、离线、离开页面时隐藏私有内容并失效在途结果；同一身份的普通未保存草稿仅留在内存，恢复后先重新核对身份和照片。身份变化或明确放弃详情时清除草稿。
- 404／410 清除对应照片详情；伙伴共享照片没有此建议入口。

## 组件与请求边界

`PhotoJourneySuggestions` 是详情内的局部视图，接收 `busy/dirty/blocked`、
`load/confirm/cancelDraft` 回调；不自行读写网络或持有父草稿。
`PhotosScreen` 负责当前照片、完整角色／家庭／成员／auth version／CSRF 围栏、写锁和恢复状态。
`photos.ts` 仅补本人可见的可选 `sourceCreatedAt/sourceTimeState` 类型；伙伴和电视投影不因此增加字段。

纯模型 `photoJourneySuggestions.ts` 由独立分支提供：`readPhotoJourneySuggestions` 校验真实 DTO，
`photoSuggestionBody` 生成精确的 `revision/journeyId/expectedJourneyRevision/expectedTripRevision` 四字段。
前端不重算时区日期、不拼入 caption、visibility、grants 或 consent。

新增建议请求使用固定同源 `/api/me`、本人照片及其 `/journey-suggestions` 路径，
`no-store`、禁止重定向、20 秒超时和最多 1,000,000 字节 JSON。GET 与 PATCH 均在发布结果前后核对真实 `/me`；PATCH 使用刚核对的 CSRF。
PATCH 的明确错误也经过后置身份核对，成功后再读取详情与图库。
旧相册、选片和手动保存接口沿用原流程；无新依赖、后端、路由或存储。

## 验证范围

定向严格 TypeScript 检查包含局部组件、真实 PhotosScreen、photos 类型与独立模型；
使用现有物理依赖的只读映射，没有复制依赖、生成应用或改其他分支。
最终固定头、原件与结果由交付记录绑定。独立模型的真实 API／Node 测试由模型作者报告，不能计作界面浏览器通过。
后续组合验收需实际核对四宽 320／390／1280／1920、浅深色、44px 新控件、三版本冲突、未知结果、电视草稿与后台／身份迟到。
当前不宣称真实 Google 资料、原生设备或实体电视已验收；新建议传输以 Expo Web 同源部署为目标。
