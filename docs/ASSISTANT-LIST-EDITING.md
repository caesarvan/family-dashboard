# 助理清单：确认前调整与原结果核对

本轮实现契约，基线 `0b69b3996a989a444b1d6787d902f8a24985dc40`；尚未发布。目标是日常待办和采购的完整路径：描述需求 → 核对并调整 → 明确保存 → 原清单及首页核对。复用现有家庭事项和 `assistant_plans`，不增加数据库表。

## 产品行为

- 原有清单草案默认紧凑显示；每项提供“调整”，可改名称、负责人、截止日、备注，采购另含数量、人民币预算和优先级。调整是本页草稿，不改变任何已保存事项。
- 日期必须保留到采购实体；采购预算采用整数分，空值是未设置，零是明确零预算。不采纳模型未获支持的预算等隐藏字段；用户明确编辑的字段才通过下述确认接口保存。
- 勾选事项后一次“确认保存 N 项”。确认前显示家庭共享说明；负责人仅表示分工。服务端在同一事务内验证所有选中项，成功后一次保存；没有半批成功、云写、下单、扣款或库存变化。
- 确认开始即冻结计划 ID、选择与修改内容。结果不明时先读原回执，不能创建另一份计划或换用另一份请求。恢复得到已保存回执时只显示结果，不再 POST。
- 页面刷新只保留成员身份及原计划 ID 的最小恢复标识，不能将提示词、标题、金额、CSRF 或令牌写入浏览器存储。先核验当前身份，再读取原计划。已保存可恢复回执；未保存且原修改已丢失时明确说明，重新核对同一原计划后才能确认，不自动重发。
- 离线/后台隐藏私人草案和回执；恢复前台重新核对身份。身份变化、撤权清除旧内容及旧恢复标识；迟到响应不得回显。
- 首页采购按现有截止/优先级规则排序并显示负责人、日期和优先级，仍编辑原事项。

## 接口

`POST /api/assistant/plan` 保持现有兼容返回，采购也保留已解析的 `due`。模型字段仍沿白名单，预算不从模型直接写入。

`POST /api/assistant/plans/<id>/apply`：

```json
{
  "selected": [0],
  "overrides": [{"index": 0, "data": {
    "title": "旅行转换插头", "owner": "shared", "due": "2026-10-01",
    "note": "核对插座型号", "quantity": "2 件", "budget": 15990, "priority": "high"
  }}]
}
```

- `selected`：1–12 个互不重复整数索引。`overrides` 可省略，最多12项，只能覆盖已选索引；重复索引、未知键、布尔索引或无效值拒绝400。省略的覆盖字段保持原草案；空字符串和 null 分别按原领域规则处理。
- 所有种类允许修改 `title/owner/due/note`；采购另允许 `quantity/budget/priority`。禁止改变 kind、ID、done、actual、照片、来源、旅行关联、依赖或云目的地。
- 调用现有 `validate` 和成员有效性检查；始终 `done=false`。事务中的真实成员/家庭权限重核、批量上限和任务依赖门禁保持。
- 首次确认把规范化的确认载荷/选择绑定到既有计划数据 JSON，与实体及原回执原子持久化。同一载荷重试返回原回执；改变已确认载荷返回409，不追加事项。规范化比较不依赖 JSON 键顺序；先做类型/白名单检查。旧已完成记录没有确认载荷时保持原回执兼容，不再写入。
- 返回保持 `{ok:true,destination:"household",created:[{id,kind,title}]}`，标题来自实际保存字段。

`GET /api/assistant/plans/<id>`：只允许该计划本人，其他成员/其他家庭404，匿名401，电视403；不接受查询参数。返回：

```json
{"id":"32位计划ID","status":"pending","plan":{"id":"同一ID","mode":"local","summary":"…","actions":[],"matches":[]},"receipt":null}
```

- 状态为 `pending/applied/expired`，原 pending 24小时到期；applied仍返回原回执，遵守既有7天清理期限。`plan` 只投影公开契约字段，不能暴露内部确认载荷、身份上下文或原始 provider 数据；`receipt` 仅 applied 有值。
- applied 的 `plan.actions` 展示实际已确认字段，选中项与原回执一致；不把未确认原草案当成已保存内容。pending 只证明本次读取时尚无回执，不证明较早的在途请求永远不会提交。
- 读取在真实会话事务中执行，提交读事务后再次核验会话；此接口不产生实体、不发布、不进行模型调用。未知、被清理或无权的计划均404，不推断原来是否执行成功。

## 验证与协作

API、UI、浏览器分别在独立 `codex/assistant-list-*` 分支/worktree，根只负责契约、组合、发布与refs。关键验证包括真实持久化字段、整数金额/空值、修改失败零实体写、同ID幂等与变更拒绝、失去保存响应后的GET/刷新恢复、撤权/跨户与迟到响应隔离、首页截止显示、390/1280宽度界面。模型测试与本地规则测试分别标注；本轮不得冒称真实账户/实体设备验收。
