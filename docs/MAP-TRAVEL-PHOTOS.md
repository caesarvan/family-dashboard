# 从地图回看旅行照片

地图选中有关联旅行的地点后，点击「查看这次旅行的照片」。页面显示这次旅行中已确认保存、当前成员有权查看的照片；默认「我能查看的」，也可切换本人或家人共享范围。每页 24 张，可以查看照片说明和关联行程。没有可见照片时明确显示空结果。

「返回地图」恢复原状态、年份、记录成员、旅行、可见范围、页码和选中 ID，但重新请求服务端地点数据。如果地点已删除、不再共享或已不在这一页，旧地点详情不会重新出现。浏览器后退也遵循这一重新读取流程。整页刷新或离开地图／相册两页后，临时返回状态丢弃。

此入口只读；照片编辑、导入和电视许可仍在普通相册入口操作。没有自动关联、拍摄日期推断、自动到访、共享或电视授权。照片与地点通过同一个旅行 workflow ID 关联；这不证明照片摄于这个地点。它不提供旅行专属 TV 播放列表、视频播放或自动回忆推荐。

## 接缝

`JourneyMap.mount(node, options)` 新增：

- `openPhotos(journeyId, view)`：按钮点击时先 GET 当前地点，再核对当前成员；取得其当前 `place.journey.id` 后调用。这里是 workflow ID，不是 `tripId`。
- `initialView`：`{filters:{scope,status,year,owner,journeyId},offset,selected}`。只保存查询字段和 ID，不携带地点 DTO、坐标、名称、照片或草稿；首次挂载即重新读取 `/api/me`、地点列表和选项。
- `onIdentityChanged()`：模块检测到当前身份不匹配时通知宿主清除返回上下文。

`HouseholdMedia.mount(node, options)` 新增 `initialJourneyId`、`returnToMap()` 和 `onIdentityChanged()`。有效 journey ID 与返回函数同时提供时进入只读旅行相册；默认 `scope=visible`，旅行筛选固定为该 workflow ID。复用 `GET /api/media/items?scope=visible&journeyId=…&limit=24&offset=0`、现有详情和同源预览接口。不读取导入记录、账户和设备选项；普通 mount 的原编辑、导入和授权行为保持。

`ProductShell` 在内存中保存当前成员/家庭/auth_version/CSRF 与上述 ID、查询字段。身份变化、模块身份复核失败、登录页或离开两页立即清除；没有写入 URL、history state 或 localStorage。返回只传查询状态给新的地图实例，销毁旧相册实例。跨页后迟到的照片响应不能重新挂载或填充 DOM。

## 失败和权限

后端仍独立决定当前家庭、成员、私密／共享、来源授权和可见照片范围；地图可见不会赋予照片权限。相册返回不受读取中的 busy 锁限制，网络失败也可以退回地图，但离线时地图保持空白并提示重新读取。

只读旅行相册遇到离线事件或读取失败会清除旧照片列表、详情及预览；重新联网后重新核身份和读取。地图的只读列表遇到离线事件也清除已显示地点，恢复后重新读取。已有地图编辑草稿及未知写入回执继续走原编辑流程，网络事件不废弃进行中的编辑事务。成员/家庭变化立即清空旧实例；异步响应受实例、请求代次及成员复核保护。

正常在线相册沿用约 15 秒的可见状态复核，并可手动刷新；服务端撤权会拒绝之后的读取。已经交付浏览器的像素无法收回，不能宣称瞬间远程擦除或实体电视已验收。

## 验证

`python tests/browser_map_travel_photos_check.py` 使用临时真实 Flask factory、SQLite、加密照片引擎及 Edge。照片由现有测试 helper 通过真实 staged→confirm→关联 API 准备，原始图片是合成图片；不调用 Google 或模型。

专项覆盖 workflow/trip ID 区分、本人/共享/另一家庭和未确认照片过滤、照片分页、地图五项筛选与第二页选中恢复、浏览器后退、撤共享前后两处复核、断网清理/联网重读、迟到响应、真实 cookie 切换及已配对 TV 拒绝此成员入口。同时运行原相册浏览器契约测试和地图真实集成测试。原件与截图写入忽略的 `test-results/`，通过数量和实际运行范围见候选交付记录。

本候选只修改三个既有 JS、增加专项和本文；复用现有 CSS，无 schema、后端、依赖或加载清单变化。测试使用本地浏览器和合成数据，未部署、未访问生产、未代表真实 Google 重选或实体电视验收。
