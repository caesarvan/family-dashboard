# 电视旅行回顾：75 → 77 表迁移

新增 `media_playback_journeys` 保存每台电视的旅行与路线选择，新增 `media_playback_operations` 保存开始播放的幂等回执。平台仍为 9 表；既有播放和播放进度表不变。完整接口约定见 `TV-TRIP-PLAYBACK.md`（在独立契约分支，组合候选需包含该文档）。

## 执行与恢复

`deploy/check_tv_trip_migration.py` 提供 `begin`、`migrate`、`check_stopped` 和 `verify_rollback`，使用现有完整库组备份与恢复校验。执行前必须停止所有生产写入者；该工具不会替调用者停服务或恢复数据库。

迁移只接受全部家庭为 75 表、平台为 9 表的完整登记库组。备份、源文件身份、迁移计划和初始化器字节先校验；每户在独立事务中运行真实 `media_trip_playback.init_schema`。初始化器不得自行提交。仅允许新增两张空表及其两个主键索引，旧表、索引、触发器、数据、设置与序列全部保留。

迁移跨多个 SQLite 文件，不承诺跨文件原子性。第二户失败时保留失败回执和完整备份，禁止重放该次迁移。按部署文档恢复整个库组到新目录，使用 `verify_rollback` 核对旧 75/9 状态后，再决定服务恢复。不能只恢复失败的家庭。

迁移后的 `deploy/tv_trip_release_data.py` 校验非空 77/9 库组。旅行删除留下 `journey_id = NULL` 的选择记录，避免电视回退到全部相册；设备撤销后操作回执仍可保留。恢复核验包含这些记录，不能把它们当作可丢弃的缓存。
