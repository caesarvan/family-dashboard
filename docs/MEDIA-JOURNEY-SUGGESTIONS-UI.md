# 按照片时间推荐关联旅行

在普通相册打开本人已保存照片，详情中点击「按照片时间推荐 → 查看推荐」。页面按后端返回的旅行时区展示照片日期、旅行日期及候选旅行；旧旅行使用默认时区时明确标注。日期交叠只是线索，不证明照片摄于该旅行或地点。

点击某条「确认关联这次旅行」才修改照片关联。当前已关联项显示禁用的「已关联这次旅行」。确认不更改照片说明、共享范围、到访状态或电视许可，也不调用模型、地理编码或 Google。本人可继续使用原手动旅行下拉框；有未保存的照片编辑时，需先保存或重新读取，再确认推荐，避免误以为推荐按钮会保存其它字段。

旧照片没有已记录的来源创建时间时，明确提示无法按日期推荐，请手动核对。界面不使用导入 `createdAt` 补造拍摄日期。候选最多 20 条，`hasMore` 时提示还有其他匹配旅行，可通过手动关联核对；不编造后续页或自行获取更多候选。

## 接口与失败

复用 [后端契约](MEDIA-JOURNEY-SUGGESTIONS.md)：先 GET 当前照片，再 GET `/api/media/items/<id>/journey-suggestions`，使用 `photoRevision`、`currentJourneyId` 与当前照片核对；读取无 query 参数。仅本人 ready 照片显示入口；共享他人照片、TV、演示及地图只读旅行相册不提供此写入入口。

推荐确认的 PATCH body 精确为：

```json
{"revision":3,"journeyId":"111111111111111111111111","expectedJourneyRevision":2,"expectedTripRevision":4}
```

照片、workflow 与 trip 版本由后端在同一事务校验。409 后清除旧候选，提示重新读取照片和推荐，必须再次明确点击确认。写入结果未知时也只提供重新读取，不自动重发 PATCH；读回已关联会禁用该候选。普通手动关联保持原 `revision/caption/visibility/journeyId` 契约。

选择其他照片、修改手动编辑字段或筛选、离线、照片版本变化与身份切换会清除旧推荐。读取期间绑定编辑对象、请求代次及真实成员复核；过期响应不能恢复候选。403/404/410 清理不可再访问的详情。候选标题、时区和日期均作为转义文本，照片仅使用原同源预览接口；来源文件名、provider ID 和账号数据不参与推荐显示。

## 文件与验证

只修改 `static/household-media.js` 和局部详情 CSS，增加独立浏览器测试及本文。推荐区由 `renderSuggestions` 插入原详情，不替换普通导入和手工编辑逻辑。无 schema、后端、依赖或静态加载顺序变化。

`python tests/browser_media_journey_suggestions_check.py` 使用真实 Edge 与合成 HTTP 契约，覆盖明确读取/确认、转义、时区、未知时间、手动编辑失效、409、已提交响应丢失、20 条上限、共享只读、410、离线及身份切换。它不替代真实 API/SQLite 组合验证；最终组合目录、固定 head 和实际结果由候选交付记录绑定。测试原件与截图位于忽略的 `test-results/`，不使用真实账号、Google、模型或生产数据。
