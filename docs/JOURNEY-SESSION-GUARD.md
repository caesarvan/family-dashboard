# 旅行保存的事务内会话检查

本增量尚未部署，实际安装版本以 [README](../README.md) 为准。

旅行确认请求会先验证 HTTP 会话，再验证预览，并可能等待云账户锁或 SQLite 写锁。若会话在等待期间已被撤销，只在请求开始验证不足以决定后面的写入权限。

`POST /api/journeys/apply` 现在取得 `BEGIN IMMEDIATE` 后，使用当前请求的真实 Cookie 和同一数据库连接调用 `member_sessions.current`，再次核对成员、认证版本及家庭。检查位于所有新建、更新和已完成操作回放之前。失败返回 401，并回滚本次事务；不创建旅行、关联任务、采购、日程、审计或新回执。

此检查不回滚已完成的业务操作。若保存事务先取得写锁并通过校验，稍后发起的撤销会等待该事务；保存可以先完成。原 30 分钟预览有效期和幂等规则保持，没有新增跨会话回执查询接口、数据表或云端操作。

`tests/test_journey_transaction_session.py` 通过真实第二个 SQLite 连接，在请求开始认证通过、预览签名解码后撤销会话或提高用户认证版本，验证新建、更新和回放三个路径均拒绝，五张业务及审计表逐行保持。测试不替换成员校验或业务数据库。修复前新建场景实际返回 201，复现了缺口；修复后的最终测试结果应以组合验收记录为准。
