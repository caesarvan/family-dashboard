# Expo 旅行路线

本文件描述候选前端，不代表已经部署。入口为「旅行 → 旅行详情 → 旅行路线」。继续使用现有 Expo、React Native Paper、浅灰卡片和胶囊按钮，不增加地图服务或依赖。

## 使用

1. 在「我的路线」新建路线。没有地点时，点「前往旅行地点添加」；从地点页返回后回到本趟旅行的路线列表。
2. 填写路线名称，选择这趟旅行当前有权访问的地点，使用上移、下移和移除调整顺序。同一地点可多次添加，最多 100 站。取消编辑不保存。
3. 默认「仅我自己」。选择「家庭共享」后，地图和顺序列表按公共投影显示；核对名称和坐标共享范围后保存。私人地点不能因为加入路线而自动共享，须在地点管理中单独设置。另一个成员从「家庭共享」只读查看；只有路线作者能编辑或明确确认删除。
4. 保存后查看完整路线。编号对应下方站点列表；同一坐标合并显示站号，点击可轮换选中对应站。反经线处拆线，隐藏坐标和不可用站点处断开，不能过滤缺口后跨站连线。虚线表示大致位置。直线只是顺序示意，不是导航、实际经过路线、距离或到访证明。
5. 点「查看旅行照片」进入现有旅行回顾的照片页，点「返回旅行路线」重新核对同一路线。照片仍按原旅行关联和照片许可读取，不推断拍摄于某站，也不授予电视许可。

当前地点失去授权、移出旅行或删除时，路线保留匿名缺口。编辑时可明确移除或保留原槽；重排不改原槽编号。私有路线改为共享前须移除不可用槽。原数据版本变化后无法确定旧槽对应关系时，须移除旧槽或取消后重新打开，不能悄悄替换为另一地点。

## 身份、保存与恢复

- 接口见 [路线 API](JOURNEY-ROUTES.md)。路线列表按「我的／家庭共享」各页 24 条读取；详情读取完整有界站点，地图不以地点选择页代替完整路线。地点选择每页 24 条，已选地点独立重新授权读取。
- 每次读取／写入使用现有 `PlaceFence`，前后核对 `/me` 的完整身份，包括家庭、成员及认证版本；HTTP 拒绝仅在两次身份核对后才可确定。切身份或撤权清草稿和原操作。后台、失焦、断网隐藏展示并丢弃已读投影；同身份内存仅保留草稿文字、地点 ID／版本、原缺口索引和未知操作内容，返回重新取当前数据。不写 URL、localStorage、日志或其他持久缓存。
- PUT／DELETE 绑定当前 `revision` 与不透明 `sourceVersion`，保存同时绑定旅程与地点版本。409 保留草稿，先读取最新内容，再明确「按当前地点核对草稿」，不自动覆盖。
- 每次新的明确提交使用一个 32 位十六进制 `requestId`。回复丢失或最终身份核对失败时，保留原请求并锁定新保存，只能「核对原操作」。仅经前后身份核对确认操作 GET 为 404 后，才提供「按原内容重试」，沿用完全相同的编号和内容；后续拒绝不能推翻更早的未知提交。
- 原样重试经身份核对返回 409 `source_changed`／`revision_conflict` 时，可进一步核对同 ID 路线或地点的当前授权 revision。只有它**严格大于**原请求期望版本、随后原回执仍为 404、并且整个核对的身份未变，才提示「原内容的版本已过期；这次重试未保存」，提供「保留草稿并重新核对」。这一步不提交，也不生成新编号；用户核对草稿后再次明确保存才创建新请求。核对中出现成功回执时优先恢复当前结果。
- 上述判断依赖路线／地点保留墓碑、同 ID 不重建、版本只递增的现有合同，不称原编号已取消或封存。旅程本身可能由旧预览重建，旅程 revision 不能单独证明失效。版本相等／更小、只有 sourceVersion 不同、对象不可见、一般 409、`request_conflict`／`limit_reached` 或身份核对失败都不解锁。不能证实的未知请求继续保留原编号；统一操作中心不在本批范围。
- 操作回执先确认原操作完成，再读取当前授权投影。路线后来删除、换旅行或原旅行被删除，不会回放旧地点坐标，也不会把已确认操作变回未知。当前页面只呈现仍属本趟旅行的投影。
- 原操作只在当前页面同身份内存保留；重新载入浏览器不承诺恢复尚未复制的编号，不会自动重新提交。未知状态页提供可复制原操作编号。

## 实现与验证边界

`journeyRoutes.ts` 负责严格解码、请求／回执、草稿及几何；`JourneyRoutesPanel.tsx` 负责用户流程。`TripsScreen.tsx` 接入口与地点页往返，`TripRecapPanel.tsx` 只增加初始照片页和返回文字参数。`WorldMap` 的路线模式是可选参数，原地点地图与选点行为保留；非网页仍提供完整可访问列表。

专项 `frontend/tests/journeyRoutes.test.mjs` 执行实际组件与库，使用合成传输边界，覆盖保存排序、重复站、共享核对、另一成员只读、缺口、反经线、冲突重核、回执恢复、迟到响应、失焦／后台及身份清除。可通过 `JOURNEY_ROUTES_WIRE_FIXTURE` 指向 API 作者保存的合成 Flask JSON 做额外交叉解码，正常构建不依赖另一 worktree。

作者本轮已执行 20 项专项（19 项常规及 1 项实际 DTO 接缝），零失败／跳过；原始第一轮两项合成 fixture 断言错误保留，修正为不同坐标及正确 mine 范围后通过。两组 TypeScript 检查与命令／源码散列另存忽略的 `test-results`。本地复用已有 node_modules junction，仅为开发验证，不称独立安装或正式 Expo 构建。真实组合浏览器、Linux、本人资料、实体设备与生产均由后续批次独立验收。

后续恢复修订补充 6 项实际组件边界：严格较大地点／路线版本、相等／较小版本与仅旅程变化拒绝解锁、普通及不同请求冲突拒绝解锁、期间出现成功回执优先、期间身份变化清空。原 20 项通过证据保留，不将新增专项混称为实际浏览器或生产验证。
