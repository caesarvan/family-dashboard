# Expo 旅行简报

本次准备／采购／成员分工草案为前端候选，尚未组合验收或上线。它扩展现有简报，不改旅行保存、改期或数据库合同，不增加依赖。后端由独立任务扩展同一 [简报 API](ASSISTANT-JOURNEY-BRIEF.md)，最终组合与真实浏览器由集成人验证。

原基础简报于 2026-09-17 07:38:17（北京时间）发布，07:39:46 正常 TLS 读回通过；该历史版本的身份与组合验收见 [旅行协作验收](EXPO-TRAVEL-ACCEPTANCE.md#expo-travel-release)，当前发布入口见 [README](../README.md)。历史验收不代替本次新增草案流程。

## 使用

1. 在助理输入旅行文字并点击「整理并预览」，或打开「规划一次旅行」填写原始需求、直接补齐基本安排。只有明确勾选「使用 AI 整理这段文字」才请求模型；只发送这次原文，不附带家庭记录、成员标识或旧草稿。
2. 手工入口中如需从原文提取字段，点击「整理旅行简报」；助理已整理的简报可直接核对。补齐旅行名称、总日期、国内／境外、人民币家庭总预算、出行成员和各站停留。未知预算保持空白，继续前须明确；0 只表示明确的零预算，不自动换汇。
3. 后续修改文字时，点击「按当前文字重新整理」才重新请求。成功才替换下方简报；失败保留新原文与旧简报。编辑中的请求即使迟到也不覆盖新输入，不自动再次调用 AI。
4. 有准备或采购内容时，相应卡片自动展开。核对每行标题、负责人、截止日期或数量／预算，可添加和移除；未确定的负责人、准备截止和采购数量须补齐后继续。没有提取到准备事项时，仍可使用原国内／境外默认清单；明确移除全部自填准备后不会自动补回模板。
5. 准备截止可用固定日期，或「随出发日期调整」的整数天数（-3 表示出发前三天，0 表示当天）。修改出发日会重新计算相对截止，固定日期保持原日；切换截止方式会清空另一种输入，须重新核对。采购预算空白表示未知，0 是明确零预算，人民币金额精确到分。采购截止要求仅保留备注及整理提示，本批没有采购截止字段或改期联动。
6. 「核对并继续编辑」只调用旅行预览检查日期、停留、金额和成员。返回的规范化新计划保留已核对准备与采购，进入原旅行编辑页；仍可修改，然后重新预览并明确确认保存。简报预览令牌立即丢弃，不保存旅行、预订、付款或云日历。

负责人选项来自当前家庭成员；原文中的“我”、共同负责或唯一精确姓名由服务端解析，无法确认时必须手选。两位成员同名时显示「姓名（我）」和「姓名（另一位成员）」。多个同名非本人无法仅靠现有姓名区分，保持待核对；可明确选择一起或本人，也可移除此行后稍后分工，不展示内部 ID 或用列表序号猜人。当前 Expo 没有显示名称编辑入口，本批不新增该功能。

例如：「2027-10-01 至 2027-10-07 去冰岛；我在出发前三天核对护照；小林买两只转换插头，预算 200 元」。整理后分别核对准备、分工和采购；若小林未加入家庭或存在重名，则先明确负责人。保留原始需求，模型或整理提示中的文字只作为草案数据，不能执行转账、付款或其他指令。

保存响应丢失时，旅行编辑页的「核对原保存」沿用原预览和操作标识安全重试；它可能完成尚未成功的保存，并非只读查询。刷新或离开页面不保留草稿，须先核对已有旅行，不能直接新建一份替代未知结果。

界面采用 [当前 Expo 官网风格](EXPO-SITE-STYLE.md)：Paper 控件、白底、黑色胶囊按钮和浅灰 SectionCard；基本安排始终可编辑，目的地、准备与采购可折叠，窄屏字段自动纵向排列，不拆成强制三步向导，不增加查询或草案执行确认层。

## 接口与安全边界

`JourneyBriefPanel` 默认导出，参数为 `{user: Member, people: Person[], initialPrompt?: string, initialUseModel?: boolean, prepareOnOpen?: boolean, onPrepared: (draft: Draft) => void, onCancel: () => void}`。`Draft` 使用 [trips.ts](../frontend/src/lib/trips.ts) 的既有类型。父组件以完整身份隔离内存状态，不将草稿写入 URL 或 localStorage。

`prepareOnOpen` 只用于助理中用户已经明确点击整理的入口，并携带当时的 `initialUseModel` 选择。面板首次身份核对后只执行一次；StrictMode、前台恢复或网络恢复不重复请求。手工规划入口不启用它。提取或核对期间可以继续编辑，旧响应随编辑代次失效；取消按钮等待请求结束，父组件离开或销毁仍立即使旧响应失效。

`journeyBrief.ts` 对响应和提交均重新投影白名单：原文不超过 2000 字，目的地最多 20 个，准备与采购各最多 100 行，年份 2000–2100，单次最多 367 天；预算为整数分且不高于 100000000000。旧响应没有 items 时兼容默认准备模板。新行的服务端 `key/title/assigneeText/owner/note/sourceText` 逐项验证，原文片段必须确实出现在本次输入中；采购另含 `quantity/budgetCents`，准备另含互斥的 `due/dueOffsetDays`。无法核对到当前成员的 owner 只保留待选择状态，提交前再次校验当前候选。

简报中的准备相对天数为 -730 至 366，未知截止不能落入原 preview 的默认 -7 天。向 Plan 只传固定 `due` 或相对 `dueOffsetDays`；规范化 preview 则正常同时返回两者，须验证与旅行出发日计算一致。新增行使用独立递增键，删除中间行再新增不会覆盖保留行。采购只投影既有 Purchase 的 `key/title/owner/quantity/budget/note`，不带入到货、已买、实付、云身份或模型执行字段。

返回 Draft 不含 journeyId、tripId、revision、previewToken、云身份或操作授权；保存／预留金额始终初始化为 0。准备、采购和 v1 日期级停留以允许字段进入原编辑器，原幂等保存和未知结果恢复流程不变。

请求前后经 `/me` 核对成员、家庭、认证版本、CSRF 和当前代次，错误响应也先核对身份再显示。请求期间编辑任何准备／采购字段都会使旧响应失效；成员 ID 或显示名变化也不能把旧结果交给编辑器。后台、路由失焦和离线隐藏原文及简报，恢复后只重验身份；身份变化清除内存输入。没有新增服务器草稿保存或本地持久化，刷新后不保证恢复。

## 验证范围

`tests/test_expo_journey_brief.mjs` 使用合成数据验证未知／零预算、精确金额、日期与成员白名单、条数与重复键、默认模板兼容、相对日期跨月／跨年／闰日、两次白名单投影和规范化截止一致性。`frontend/tests/journeyBriefItems.test.mjs` 执行实际 Panel／编辑组件及身份 fence，使用明确标注的合成 HTTP 值验证自动展开、分工消歧、删除后新增、带入旧编辑器、迟到成功／失败、成员变化与后台／离线隐藏；不是实际浏览器或后端验收。

本次作者验证为纯函数 20 项、组件 7 项分轮通过，两组 TypeScript 通过；首次组件检查因测试器遍历 undefined 时误回到根节点而失败，已修复测试器并完整重跑组件 7 项，无产品逻辑规避。另只读交叉核对了后端真实临时 Flask 的本地／模型替代／未定负责人三份简报响应和一份规范化 preview plan；原件明确省略签名令牌，plan 测试使用合成 `canApply:true` 外壳，不称完整真实预览响应验收。

开发依赖复用 junction，不声称独立安装或正式构建。同源 fresh Expo、手机／桌面真实浏览器、实际模型、本人操作与生产上线须由后续独立组合分别记录。
