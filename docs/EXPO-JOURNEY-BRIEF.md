# Expo 旅行简报

本页描述源码候选；组合构建与验收见 [旅行协作验收](EXPO-TRAVEL-ACCEPTANCE.md)，实际线上身份见 [README](../README.md)。沿用 [原简报 API](ASSISTANT-JOURNEY-BRIEF.md) 和 `/api/journeys/preview`，复用既有后端接口；本轮同时补强保存事务内的会话校验，不新增 schema、环境配置或依赖。

## 使用

1. 在助理打开「规划一次旅行」，填写原始需求，或直接填写下方基本安排。只有明确勾选「使用 AI 整理这段文字」才请求模型；只发送这次原文，不附带家庭记录、成员标识或旧草稿。
2. 点击「整理旅行简报」，补齐旅行名称、总日期、国内／境外、人民币家庭总预算、出行成员和各站停留。未知预算保持空白，继续前须明确；0 只表示明确的零预算，不自动换汇。
3. 后续修改文字时，点击「按当前文字重新整理」才重新请求。成功才替换下方简报；失败保留新原文与旧简报。编辑中的请求即使迟到也不覆盖新输入，不自动再次调用 AI。
4. 「核对并继续编辑」只调用旅行预览检查日期、停留、金额和成员。返回的规范化新计划进入旅行编辑页，可以修改准备、负责人、采购预算，然后重新预览并明确确认保存。简报预览令牌立即丢弃，不保存旅行、预订、付款或云日历。

界面采用 [当前 Expo 官网风格](EXPO-SITE-STYLE.md)：Paper 控件、白底、黑色胶囊按钮和浅灰 SectionCard；基本安排始终可编辑，目的地可折叠，窄屏字段自动纵向排列，不拆成强制三步向导。

## 接口与安全边界

`JourneyBriefPanel` 默认导出，参数为 `{user: Member, people: Person[], initialPrompt?: string, initialUseModel?: boolean, prepareOnOpen?: boolean, onPrepared: (draft: Draft) => void, onCancel: () => void}`。`Draft` 使用 [trips.ts](../frontend/src/lib/trips.ts) 的既有类型。父组件以完整身份隔离内存状态，不将草稿写入 URL 或 localStorage。

`prepareOnOpen` 只用于助理中用户已经明确点击整理的入口，并携带当时的 `initialUseModel` 选择。面板首次身份核对后只执行一次；StrictMode、前台恢复或网络恢复不重复请求。手工规划入口不启用它。提取或核对期间可以继续编辑，旧响应随编辑代次失效；取消按钮等待请求结束，父组件离开或销毁仍立即使旧响应失效。

`journeyBrief.ts` 对响应和提交均重新投影白名单：原文不超过 2000 字，目的地最多 20 个，年份 2000–2100，单次最多 367 天；预算为整数分且不高于 100000000000。成员只接受传入当前家庭列表中明确勾选的 ID，不从模型获取。归一化后的默认准备事项和 v1 日期级停留可以带入编辑，但只保留允许字段；返回 Draft 不含 journeyId、tripId、revision、previewToken、云身份或操作授权。保存／预留金额初始化为 0，不能从模型猜测已付款。

请求前后经 `/me` 核对成员、家庭、认证版本、CSRF 和当前代次，错误响应也先核对身份再显示。后台、路由失焦和离线隐藏原文及简报，恢复后只重验身份；身份变化清除内存输入。没有新增服务器草稿保存或本地持久化，刷新后不保证恢复。

## 验证范围

`node --test tests/test_expo_journey_brief.mjs` 使用合成数据验证未知／零预算、精确金额、真实日期与停留边界、20 项上限、成员白名单、模型恶意身份字段、新建 Draft 投影，以及成功／失败请求的身份和代次检查。完整 TypeScript、组合真实浏览器、四宽视觉、真实模型质量与生产部署分别由集成人记录；本模块的 helper 测试不能代替这些验收。
