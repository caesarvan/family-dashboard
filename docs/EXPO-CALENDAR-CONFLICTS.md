# Expo 日程时间重叠提示

本 UI 已于 2026-09-20 08:47:27（北京时间）激活，08:49:19 独立生产只读审计通过。正式构建、真实临时浏览器和生产证据见[使用与集中验收](CALENDAR-CONFLICTS-ACCEPTANCE.md#calendar-conflicts-release)；真实云账户写入、实体电视及本人完整 A–D 场景仍未验收。

## 最短使用路径

首页的日程卡片在存在重叠时显示「N 组时间重叠 · 查看」，点击进入日程；沿用已有「今日／本周／前后 3 天」和日程侧重。日程页可以翻到另一段时间，重叠区始终计算当前整段范围，不因点击其中一天而缩小。

展开一组，查看双方完整标题、起止日期时间、负责人和地点，以及当前范围内每天具体重叠的时间。本地安排点击「调整安排」打开已有编辑框，保持原 ID 和 revision；保存并刷新后重新计算，已消除的重叠自动从列表移除。编辑框关闭或保存不会重置日程页当前范围与所选日期。旅行关联安排沿用已有旅行调整入口。

同步日程显示「同步日程 · 只读，请在原应用调整」，不提供复制或创建替代安排。这里不调用云接口，也不改变云日程写权限。

## 计数与交互

- 核心计算由 `calendar.ts` 的 `calendarConflicts(events, days, focus)` 提供，UI 不另写重叠算法。只计算所选成员与共同安排，排除全天、首尾相接和无效时长。
- 同一对安排在当前范围内计一组，即使跨日也不重复计组。三个同时发生的安排可能产生三组；这是两两时间交叠数量，不是人数、忙碌总时长或双方必须调整的工作冲突。
- 重叠卡片放在原日程列表下方，默认只显示前三组，按需再显示三组，避免密集的一周重叠挤走原日程。每组单次展开即可查看全文和操作；折叠行的标题摘要最多两行。切换成员侧重或日期范围会收起旧展开项，身份切换沿现有 HouseholdApp identity key 卸载旧内容。
- 首页入口代表当前整段范围，即使首页点选某一天也不改变入口计数。没有重叠时隐藏入口和重叠卡片。
- 白底／浅灰卡片、细分隔线、主题正文色、44px 操作目标及现有 React Native Paper 组件；两种宽度使用同一纵向详情结构，长标题自然换行。

## 保存与身份边界

重叠区只有读取现有 state 的投影，没有新异步请求、持久化草稿或缓存。打开本地编辑前按原 ID 在当前 state 重新取原记录，再交给既有 `props.onEdit`；不把裁剪后的重叠时间写回，也不新建副本。原 ItemEditor 和 HouseholdProvider 的 CSRF、身份检查、revision、409 保留输入及结果不明时锁定保存的行为保持不变。

显示内容以最近一次成功读取的家庭数据为准，离线时仍由既有应用离线状态提示。这里只提示时间关系，不判断安排是否互斥，也不保证第三方修改已实时同步。
