## 产品方向

目标是家庭生活的统一入口：把日程、准备事项、采购、资金和出行变成能相互衔接的工作流。价值应以“减少多少次重复录入、漏办事项和家庭协调成本”衡量。漂亮的概览只是入口；每条建议都需要来源、下一步操作、执行状态和失败后的处理方式。

最早的用户是共同生活、往返两个住处的两位成员。产品化后，每个家庭拥有独立空间；家庭内共享计划，个人账本和账户信息仍按成员隔离。个人数据不能因为接入了助理、搜索或新页面而扩大可见范围。

## 正在落地的产品判断

1. **统一工作台与搜索。** 功能从首页模态窗口扩展为可浏览的页面，手机以最常用入口为主；搜索只索引本家庭已共享实体。
2. **先预览，再执行。** 旅行计划、账单导入和助理任务都呈现将要创建的内容；执行有持久结果，网络重试不再创建一套副本。
3. **数据质量进入界面。** 未估值、缺币种、未知收支、未核对余额、部分覆盖和待授权分别显示。不存在的金额不能以 0 填满图表。
4. **同步状态是功能的一部分。** 已连接、已选来源、最近成功、等待授权、重试和冲突要可区分；错误时保留最近可用内容。
5. **隐私伴随数据流。** 上传、导入、搜索、备份、AI 上下文、家庭切换和电视展示都执行同一边界。
6. **邀请制验证真实价值。** 当前服务器先承载有限家庭。把自动注册开放给互联网之前，先验证恢复、资源配额和家庭隔离。

## 外部能力核验

- 微信已查到的账单下载文档是[商户号维度](https://pay.wechatpay.cn/doc/v3/merchant/4013071218)。不能据此声称可读取普通个人微信支付账单。
- 支付宝已查到的是[商家中心与对账能力](https://help.alipay.com/enterprise/knowledgeDetail.htm?knowledgeId=201603401890)。家庭荷包或个人账单自动 API 尚未验证。
- 淘宝[开放平台授权文档](https://developer.alibaba.com/docs/doc.htm?articleId=102635&docType=1)描述商家授权；不能当作个人买家全量订单授权证据。拼多多个人订单接入能力仍待核验。
- Microsoft [创建日程](https://learn.microsoft.com/en-us/graph/api/calendar-post-events?view=graph-rest-1.0)需要日历写权限，并提供 transactionId。Google [创建日程](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert)支持指定事件 ID。写入授权与既有只读绑定分开处理。
- 模型接入使用 OpenAI [文本生成](https://developers.openai.com/api/docs/guides/text)和 Responses API。未配置模型时界面明确显示本地规划；不能把本地规则结果标为模型回答。
