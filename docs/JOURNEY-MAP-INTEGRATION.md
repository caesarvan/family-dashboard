# 地图应用接入与个人导出

本候选在已审地点 API `05f885b` 上接入现有 Flask 工厂、个人 ZIP、导航和静态加载；地图 UI 与底图仍是独立候选依赖。Git 提交、组合测试和正式部署分别验收，不能把独立接线测试称为已上线地图。

## 应用与数据

`app.py` 在旅行、旅行资料模块之后注册 `register_journey_places`。默认家庭与通过现有 WSGI 创建的子家庭使用相同工厂，各自在自己的数据库中增加地点表。全新应用现在有 44 张户内表，平台仍为 2 张；五个新方法／路径模板保持成员、家庭、CSRF 和地点自身的事务校验。

`Dockerfile` 显式加入 `journey_places.py`；静态目录仍统一复制。图形使用独立的本地 GeoJSON 底图，运行时不要求外部地图服务。**已有 43 表生产库必须使用另行审查的 43→44 发布流程，不能直接重启新工厂或使用旧 SOURCE 43→43 控制器升级。** 本候选不修改历史部署门禁，也不执行生产迁移。

原地点专项 fixture 改为实际生产工厂注册；原“未接线”测试改为验证五个已注册路由和 44 张表。原权限、并发、幂等、到访确认和父旅行解绑测试继续执行。

## 导航与编辑草稿

电脑侧栏及手机“更多”增加足迹地图，旅行页面提供同一入口。`#map` 为独立页面，电视仍使用原大屏布局；演示页面只说明登录入口，不请求或写入真实地点。

`journey-map.js` 在 `product-shell.js` 之前加载。页面调用 `JourneyMap.mount(container,{openJourney})`；点击关联旅行调用既有 `JourneyUI.open`，关闭旅行对话框后仍在地图页面。

看板轮询、主题或其他模块引起整体重新渲染时，同一成员／家庭／会话下的地图容器在一个同步调用内保留并重新附着，保留草稿、焦点和文本选区。离开地图卸载模块；成员、家庭、auth_version、CSRF 或展示角色变化及返回登录页时立即清空地图上下文。模块自己的请求代次与 `/api/me` 校验仍负责丢弃已失效结果。离开页面不会撤回已经发出的服务器操作。

## 地点数据副本

个人导出摘要增加 `personal.journeyPlaces` 与 `shared.journeyPlaces` 计数。ZIP 的 `data.json` 中：

- `personal.journeyPlaces` 包含本人所有未删除地点，包括本人已共享地点；坐标保留本人精确值，不重复放入 shared。
- 用户明确勾选共同记录时，`shared.journeyPlaces` 仅包含同户其他成员明确共享的地点；坐标使用与 API 相同的隐藏、0.1 度粗化或精确投影。
- 不导出他人私密地点、软删除行、创建 requestId/payload digest 或内部字段。完整数据库备份另外保存防重复回执。
- 父旅行删除后仍保留的本人地点可导出，journeyId 为空，原到访声明保持；这不是服务端核实到访的证明。

导出在数据库快照事务中重新核对当前成员会话与家庭，已撤销会话不能仅凭请求开始前的身份通过。返回保持 API 的 `Cache-Control: no-store`。ZIP 是数据副本，仍不能直接作为 SQLite 恢复文件；地图坐标与其他个人资料一样需要由用户保管。

## 验证边界

独立接线阶段执行真实 Flask、临时 SQLite、真实成员登录和 ZIP 解包验证；没有真实家庭资料或外站请求。地点 API、接线／导出、已有数据导出与会话导出测试首次为 100 通过、4 失败；四项均因新测试错误预期 `private, no-store`，而现有应用统一响应钩子实际设置 `no-store`。改为核对禁止存储且无 public 指令后，六项接线／导出测试全通过；原失败保留，不把重复执行相加。

应用接线还需与固定 UI／底图候选合并后进行真实页面和新 API 的组合验证，并接受非作者审查。独立 UI 的合成接口测试不能替代该组合验证；生产迁移、真实设备和其他地图／媒体联动也另行验收。
