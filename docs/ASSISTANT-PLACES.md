# 助理地点搜索与原地图详情

源码候选，未发布。沿用现有地点、旅行和相册接口；不新增实体、路由、表或权限，不调用模型或外部地图服务。

## 使用

1. 打开「家庭助理」，输入 `搜索：地点名称`（也可搜索国家、城市或关联旅行名称），点「整理并预览」。这是本地只读查询。
2. 在地点结果点「在地图查看」。地图按原 ID 重新核权并读取当前详情；搜索标题、版本或坐标不会成为详情的数据来源。
3. 当前有可见关联旅行时，可打开原旅行或旅行相册，再返回地图。共享地点不会额外共享照片；地点的精确／大致／隐藏坐标仍由服务端投影。
4. 点「返回地点搜索」回到原问题、查询词和页码，并重新读取该页。原地点不可见时也能返回，不自动切换到另一个地点。

本人可以编辑原地点，使用详情最新 revision；伙伴保持只读。不会把照片、日期或地图点击自动当成到访证明。

## 实现边界

- `AssistantEntry` 在原返回状态中保留 query／offset，仅向 `MapWorkspace` 传递经过检查的 24 位地点 ID。所有状态只在当前页面内存中保存。
- `MapWorkspace` 按当前完整身份键重建，复用原旅行／相册嵌套返回链。无需新增 HouseholdApp 路由或 ScreenProps 导航字段。
- `MapScreen` 对当前页外的目标调用原 `GET /api/journey-places/<id>`，通过 `PlaceFence` 前后核对成员身份；当前页数据不再决定丢弃原 ID。世界概览可额外显示这一个已核权详情点，分页及总数仍指原列表。主动应用／重置筛选或翻页会清除当前选择，地图只展示新列表页；普通刷新和搜索入口保留原 ID，重新核权后显示详情。
- 重新读取、权限轮询、隐藏页面、离线和身份切换沿原围栏处理；撤权或删除清除旧详情与坐标。身份变化不能接受旧请求的迟到响应。离线时隐藏内容，恢复后重新读取，未核对的详情不显示。
- 助理地点匹配在最终授权事务重新读取当前行、可见范围、标题、关联旅行及 revision，丢弃第一快照中的旧地点结果后重新计算匹配数和分页。`/api/assistant/search` 与本地搜索计划使用同一逻辑。搜索不读取坐标列，也不建立新的地点副本。
- 已保存搜索快照不是后续读取、编辑或照片授权。旅行和相册入口分别沿原接口再次核权。

## 本地验证

`tests/test_assistant_places.py` 的 10 项真实临时 Flask／SQLite 检查覆盖 GET／本地搜索计划在两次快照间撤共享、删除、改名，当前关联／revision 投影，最终会话撤销，分页及原地点读取，两家庭与私人记录隔离、搜索只读。外网被禁用。

`frontend/tests/assistantPlaces.test.mjs` 的 9 项执行真实 AssistantEntry／MapWorkspace／MapScreen／PlaceFence，覆盖搜索第二页、地图分页外原 ID、原 revision 编辑、伙伴只读、旅行／相册导航参数和返回链、撤权、离线恢复、身份变化晚响应及解除关联。HTTP DTO、宿主控件、地图图层与旅行／相册面板为合成替身；这些检查不是浏览器、实际地图绘制或旅行相册端到端验收。

同轮另外 21 项原资料／照片搜索相邻 Node 检查及两组 TypeScript 检查通过。详细命令、PID、退出码和源码前后哈希保留在作者忽略目录 `test-results/assistant-places-r1/`。本批没有重新构建 Expo、运行浏览器、访问真实账户、SSH 或执行生产变更；组合后的真实浏览器验收另行进行。

增量回归另外执行 5 项真实 TSX 检查，覆盖主动筛选／重置／前后翻页清选和普通刷新保留页外原 ID；并复核原搜索第二页与嵌套返回场景。原缺陷和首次合成控件定位空格错误的失败原件分别保留，不重写原 9 项结论。
