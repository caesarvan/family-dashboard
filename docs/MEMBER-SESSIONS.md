# 成员登录设备与会话撤销

状态：**已于 2026-09-15 07:58:24 整体合入并发布**。该次首次发布镜像 `sha256:6251c9bfe9eab14c70da7ef4d07836e08ff5195c9a60f73983ac6438572bf639`，完整源码与验收见 [README](../README.md) 和 [验收记录](VALIDATION.md)。

本次最终存储修订修复了验证期间发现的无 Cookie 缺库恢复入口及有缓存时创建空数据库的问题。此前失败或被拒的候选不作为本次通过证据；本次范围仅为成员会话连接与家庭入口，见下文存储边界。

## 用户操作与范围

成员在「设置 → 登录设备」查看自己的浏览器会话，确认后退出一台或其他全部浏览器。当前浏览器仍可从设置页退出登录。这里的“设备”指一次浏览器登录，浏览器名称是 User-Agent 的有限分类，不能证明是哪一台物理设备、设备位置或使用者。

每个家庭和成员的会话分别管理。退出其他浏览器不会解除 Microsoft／Google 账号绑定，不删除财务、日程或待办，也不撤销电视配对。电视沿用原独立只读凭据；它不能查看或管理成员会话。

本轮针对两个已用虚构账号复现的问题：退出后复制的旧 Cookie 仍被接受，以及迟到的真实登录响应恢复较早成员身份。测试中的 Cookie 都由临时 Flask 实际签发，没有使用真实凭据或访问生产。产品目标是让服务器拒绝已撤销的登录，并在可关联的浏览器认证流程中检查代次；不能只隐藏界面里的旧结果。

## 接口

全部接口使用当前家庭、当前成员会话确定身份，不接受 owner 来选择其他成员。匿名或失效会话返回 401，电视返回 403；写操作要求 JSON 与 `X-CSRF-Token`，提供 `Origin` 时必须同源，缺省 `Origin` 沿用允许规则，详见 [基础约定](API.md#1-通用约定)。响应禁止缓存。

### GET `/api/sessions`

仅返回本人当前有效的会话。示例中的名称、编号和时间均为虚构数据：

```json
{
  "sessions": [
    {
      "id": "aaaaaaaaaaaaaaaaaaaaaaaa",
      "device": "Edge · Windows",
      "createdAt": "2026-09-15T00:00:00+00:00",
      "lastSeenAt": "2026-09-15T01:00:00+00:00",
      "expiresAt": "2026-10-15T00:00:00+00:00",
      "current": true
    }
  ],
  "lastSeenIntervalSeconds": 300
}
```

时间是带时区的 ISO 8601 字符串。最近使用时间最多每五分钟持久化一次，不是实时在线状态。公开 `id` 仅用于选定撤销目标，不能代替签名 Cookie 登录。

不返回 CSRF、签名 Cookie、凭据散列、浏览器关联标识、原始 User-Agent、IP 或第三方令牌。

### DELETE `/api/sessions/<id>`

请求体为 `{}`。目标不存在或不属于当前成员时返回 404，不泄露其他成员是否存在该会话。成功响应：

```json
{"ok": true, "current": false}
```

`current:true` 表示当前会话也被撤销，客户端必须回到登录流程。撤销先在服务器提交，再返回成功；复制的同一 Cookie 在后续请求中也必须失效。它不会中断已经开始执行的其他业务请求，不能当成撤销已完成的外部操作。

### POST `/api/sessions/revoke-others`

请求体为 `{}`，保留本次有效会话，退出本人的其他会话：

```json
{"ok": true, "revoked": 2}
```

数量只表示本次实际撤销的会话。界面需先显示确认，再发送请求并重新读取列表。迟到的成功或失败不能替换另一成员、新家庭或已关闭的对话框。

## 登录、退出与改密

新增登录要通过密码或已绑定第三方账号的真实授权流程。服务端在验证开始时登记浏览器认证代次，在最终签发时重新检查，成功后替换同一浏览器原会话；其他浏览器可继续登录。错误密码不应退出已有会话。

新会话从登录或改密成功开始计算固定期限，默认 30 天；普通读取和最近使用时间更新不续期，OAuth 写入随机标识而重签 Cookie 也不延长数据库里的会话期限。每个成员最多保留 16 个有效会话，超限时撤销最早的会话，仍保留所需的撤销记录。

改密继续使用数据库当前 `auth_version`，撤销该成员旧会话，并为当前浏览器生成新的 CSRF 和会话。退出当前会话、撤销其他会话及切换家庭都要与服务端撤销协同，不能只删除浏览器 Cookie。

正常界面先通过 `/api/me` 获取匿名浏览器关联标识。没有经过该步骤、也没有可关联 Cookie 的首次并发直接 API 登录，不能可靠判断是否来自同一浏览器；不把它宣称为全部身份乱序保护。迟到 Cookie 可能令浏览器需要重新登录，但不得恢复已被替换的成员身份。已登录的普通读取继续不刷新身份 Cookie。

每次显式 OAuth 登录、绑定或写权限升级都会登记新的浏览器认证代次，取消同一浏览器较早尚未完成的认证。交换令牌前和最终保存账户／签发登录事务内均复核发起会话和代次，不能仅信网络等待前的 `g.actor`。新授权被拒不会退出仍有效的成员、删除已有绑定或取消另一浏览器的授权；旧 bind 回调不能晚覆盖新的写权限令牌。

家庭切换只可凭当前仍有效的原家庭会话撤销该浏览器登录。已撤销的旧成员 Cookie 不能用于退出后来登录的成员。仅有匿名浏览器凭据时，只有该浏览器没有有效成员会话，才可取消其仍在进行的匿名 OAuth。会话撤销作用于后续请求及本轮新增复核的认证完成过程，不会回滚已经通过鉴权并开始处理的普通业务请求，也不保证阻止这些请求的迟到响应交付。

## 旧会话迁移与存储

本次新增每户 `member_sessions` 和 `member_session_browsers`，以及 `cloud_oauth_states.auth_context`。每户只保存一次旧会话接受截止时间，重启不能向后移动它。

此前合法 Cookie 可按原 Flask 签名、签发日期、最长有效期、用户身份和版本受控登记，以避免发布时强制所有人退出。新版本 Cookie 标记缺少对应服务端行时，必须拒绝，不能自动重建。

迁移前的旧程序没有保存服务端退出记录，因此不能从签名本身判断某个旧副本是否曾在浏览器里退出。兼容迁移不等于追溯撤销旧程序时期的全部凭据。需要立即让所有旧副本失效时，应使用明确的全成员会话失效操作并要求重新登录；本次兼容登记不执行这个全体退出操作。

同一个旧 CSRF 可能存在多个历史签发日期的 Cookie。撤销记录至少保留到固定旧会话截止时间加最长有效期，不能按首次观察的较早版本到期就删除，否则较晚签发的旧副本可能重新登记。过期、坏签名或已经撤销的凭据不能成为新有效会话。

会话表与浏览器代次只进入管理员完整数据库备份。个人 ZIP 导出仍按业务字段白名单生成，不能包含认证表、会话 Cookie 或散列。测试使用真实临时 ZIP 对照两位虚构成员的 Cookie、CSRF 和散列验证这一边界。

### 家庭数据库暂不可用

新家庭的首次创建由核心初始化建立数据库；成员会话模块 `MemberSessions.db` 使用 `mode=rw` 只打开已有文件，不能因数据库暂时不可用而建立一个空库。已有子家庭缓存也不能代替入口处对存储是否存在的检查；对该会话连接，即使检查与连接之间文件被移走，也由连接层拒绝自动建库。

这一保证限于会话模块连接和本次家庭入口缺库场景。既有 `app.py`、`CloudAccounts` 及其他业务模块的 SQLite 连接没有在本轮全面改造，不能据此宣称任意业务处理阶段的文件删除竞态均已覆盖。发布和恢复仍须先停止写入进程，不能在服务运行时移动数据库文件。

没有会话 Cookie 的浏览器可以返回家庭入口，不必加载原家庭数据库。有会话 Cookie 且原家庭数据库不可用时，切换请求返回 503，保留原路由和 Cookie，不宣称已完成服务端退出。运维人员应按完整备份恢复指导修复数据并处理旧会话；不能用重新初始化空库来恢复访问。

## 发布、回滚与恢复

本功能必须整体发布后端、OAuth 接缝、前端入口和新静态资源，不能只更新界面。发布前保留完整迁移前备份，停止 app／sync 写入后，串行初始化全部家庭，再启动新服务。

新增 OAuth 上下文字段后，旧版本按九列位置插入 `cloud_oauth_states` 的语句不再兼容。不能仅把镜像标签退回 7b 并让旧进程接管新库；需要匹配的迁移前完整恢复组，或经过独立验证的兼容适配。旧版进行中的 OAuth 授权可能需要重新开始，已绑定账号的令牌和来源不应因此被删除。

完整备份保存的是备份时刻的撤销状态。恢复较早备份可能重新带回后来已撤销的会话，因此必须在恢复后、恢复访问前，明确执行成员会话失效策略并要求重新登录；不能声称数据库恢复自动保留了备份后的退出操作。此项属于实际恢复操作的一部分，本轮只准备指导，不执行生产恢复或主动修改真实成员版本。

### 恢复后使旧成员登录失效

此步骤仅用于已经决定执行的备份恢复。先保持 app、sync 停止，保留恢复前残存卷与配置，按 [完整恢复指导](DEPLOYMENT.md#62-根据完整-manifest-恢复一户或整个平台) 完成文件和摘要核对。仅处理本次恢复的家庭数据库；单户恢复不修改其他家庭。若恢复了整个平台，按平台注册表列出的家庭逐户处理，不只处理原家庭。

在每个已核对的家庭数据库中检查 `users.auth_version`、两张会话表及 `cloud_oauth_states` 是否存在。新会话版本可在一次事务内执行以下 SQL，执行前应再次确认打开的就是本次恢复目标：

```sql
BEGIN IMMEDIATE;
UPDATE users SET auth_version = auth_version + 1;
UPDATE member_sessions
  SET revoked_at = CAST(strftime('%s', 'now') AS REAL)
  WHERE revoked_at IS NULL;
UPDATE member_session_browsers SET generation = generation + 1;
DELETE FROM cloud_oauth_states;
COMMIT;
```

若恢复的是迁移前数据库，没有两张 `member_session*` 表，只省略这两条表更新；仍更新成员版本并清除进行中的 OAuth 发起状态。不要删除已绑定的 `cloud_accounts`、来源或电视凭据。不要删除旧会话撤销记录和迁移截止设置来“清理登录”，否则会破坏旧凭据保留期。

提交后核对成员版本已递增、有效旧会话数与 OAuth 发起状态数为零，执行 `PRAGMA quick_check`。逐户记录通过状态与数量，不把凭据、账户或财务明细写入维护日志。任何一户失败时继续保持服务停止，修复该户并完成全部目标核对后，再按恢复指导启动 app/web；sync 须待发布队列与远端状态核对后启动。原成员随后重新登录，进行中的 Microsoft／Google 授权重新发起。

上面是恢复操作指导，不是已执行的生产恢复证明；它不会撤销备份后已经发生的第三方业务操作。
