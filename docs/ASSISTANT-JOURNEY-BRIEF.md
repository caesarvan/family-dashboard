# 助理旅行简报与向导桥接

状态：**已于 2026-09-15 06:50:21 随组合版本发布**。完整 Windows／Linux 与 13 组浏览器结果见 [VALIDATION](VALIDATION.md)；本页后半保留的独立 revision 专项数只表示其历史源码范围。真实模型抽取质量与真实云发布仍未验收。

本次新增候选：简报中的准备事项、采购和负责人沿用本端点与原旅行预览／确认流程，无新路由、表或模型上下文。此增量尚待独立审查与组合发布，下述清单合同不代表已经上线。

## 用户流程

旅行工作台 →「用文字整理旅行需求」→ 家庭助理保留原始文字 → 三步简报（出行范围、目的地停留、预算成员）→ 核对后带入可编辑旅行向导 → 原有旅行预览 → 本人明确确认保存。

普通助理中的「规划一次旅行」「分步填写旅行简报」也进入同一流程。直接提交包含“旅行/行程/旅游/出发日期/返程日期”的自由描述会进入旅行简报；明确的 `待办：`、`采购：`、`搜索：` 指令继续走原流程。通过旅行工作台进入时，无需依赖关键词。

- 无模型可以完整填写三步表单，不需要 JSON。已明确标注的确切字段可预填；未识别的自由描述保留在“原始需求”中，不能声称实现通用离线自然语言解析。
- AI 仅在配置存在且本人明确选中“使用 AI”时调用，只发送这次文字，不发送共享记录、财务、账户、成员标识或历史对话。失败保留输入，可点击不调用 AI 的入口继续。
- 返回助理保留原始输入、简报及当前步骤。“按当前文字重新整理”会重新提取当前文字，成功且身份核验通过后才替换旧简报；失败保留新文字与旧简报。“继续已保留的旅行简报”恢复手工编辑内容和所在步骤，不重新请求简报或模型。向导中仍使用原有未保存变更保护。草稿只存于本页内存，刷新、重新登录或离开页面后不保证恢复；没有新增服务器草稿表。
- 简报导入的是 **v1 日期级计划**。需要航班两端当地时间、IANA 时区、住宿退房日期等信息时，在原有向导启用 v2 细项后填写。没有自动创建航班、酒店预订或已付款记录。
- 总预算未知时保持空白，需要明确后才能进入向导。0 必须由用户明确填写。既有向导生成准备事项属于待核对建议，不能当作已核实签证或入境政策。

## HTTP 合同

`POST /api/assistant/journey-brief`

沿用 member、CSRF、Origin 和当前家庭路由边界。与原助理计划共享每小时 30 次请求限额。返回值不含预览令牌、工作流编号或创建授权；此端点不写 `entities`、`assistant_plans`、`journey_workflows`、发布队列。

请求：

```json
{"prompt":"旅行名称：东京与巴黎\n出发日期：2027-10-01\n返程日期：2027-10-12\n旅行类型：境外\n总预算：2万元\n日本/东京 2027-10-01 至 2027-10-06\n法国/巴黎 2027-10-06 至 2027-10-12","useModel":false}
```

`prompt` 为 0–2000 字字符串；空文字仅供手工填写入口使用。`useModel` 是严格布尔值，默认 false。模型调用要求非空文字。其他字段不参与简报或授权。

响应示例（未填信息保持空白）：

```json
{
  "mode":"local",
  "brief":{
    "title":"", "start":"", "end":"",
    "budgetCents":null, "international":null,
    "destinations":[], "note":"今年想去日本，两万左右",
    "checklist":[], "shopping":[]
  },
  "missingFields":["title","start","end","budgetCents","international","destinations"],
  "warnings":[],
  "notice":"本地仅提取明确标注的字段；自由描述和未确定信息请在下面逐项补齐。"
}
```

字段限制：

| 字段 | 规则 |
| --- | --- |
| title | 字符串，最多100字，可暂空 |
| start/end | 空字符串或真实 `YYYY-MM-DD`，年份2000–2100 |
| budgetCents | `null` 或 0–100000000000 的整数分，拒绝 bool/float |
| international | `null` 或布尔值；用户在表单确认国内/境外 |
| destinations | 最多20项，每项只保留 country/city/arrival/departure |
| country/city | 字符串，分别最多60/80字，可暂空 |
| arrival/departure | 同日期规则，含结束日；跨字段关系由现有旅行预览校验 |
| note | 最多2000字；实际返回用户原始需求，不带入模型臆造的预订或报价 |

`missingFields` 使用 `destinations[0].city`、`checklist[0].owner`、`checklist[0].due`、`shopping[0].quantity` 等路径列出待补字段；不是完整计划的 `canApply`。任务绝对日期与相对天数都未知时使用 `.due` 路径。采购预算未知允许为 null，不要求伪填 0。`warnings` 为固定中文提示字符串数组，默认空数组，不含家庭候选资料。完整旅行日期范围、成员资格、停留范围和金额由 `/api/journeys/preview` 再验证。

错误：400 输入/本地明确标注格式无效；401 未登录；403 TV、CSRF 或 Origin 边界；429 请求频率；503 模型未配置；502 模型网络或白名单字段格式无效。502/503 不自动再次调用模型，也不自动保存旅行。

## 本地提取与模型边界

本地识别换行或分号分隔的 `旅行名称：...`、`出发日期：YYYY-MM-DD`、`返程日期：YYYY-MM-DD`、`旅行类型：国内/境外`、`总预算：2万元`，以及 `国家/城市 YYYY-MM-DD 至 YYYY-MM-DD`。同一国家可以出现多个城市。未识别的内容仍作为原始需求供本人填写。

模型输出经严格类型/长度/日期白名单校验，然后检查原始文字：

- 输出日期未在原文以完整 ISO 日期或完整中文年月日出现，就留空；“今年”、单独“12日”、天数不会自动变成具体日期。
- 输出国家/城市未在原文出现，就留空；翻译、别名和模型建议的新目的地需手工确认填写。
- 预算须匹配原文明确的数字预算值；约数、人均金额、明确外币等不直接成为人民币家庭总预算，不自动进行汇率换算。含不同口径费用的需求只有明确写出且无冲突的人民币家庭总额才可预填；其他表达留空，供本人填写确认。中文数词或未识别表达须手工填写。
- 未明确国内/境外时保持待选择。金额和日期出现于原文只是保守的来源检查，仍不是对复杂语义正确性的保证；AI 标记与最终人工核对始终保留。
- 不接受模型或文字中的 owner/memberIds/id/remoteId/previewToken/publish/paid/saved/action。新增事项只接受原文负责人称呼 `assigneeText`，返回的 `owner` 由服务端在重新授权后解析；出行成员仍由当前家庭表单明确选择。旅行 note 使用原始需求。

## 准备事项、采购与负责人（新增候选）

返回的 `brief.checklist`、`brief.shopping` 始终为数组，各最多 100 项，缺省为空。旧模型不返回清单仍可使用。无清单时，进入原旅行预览应省略 `plan.checklist`，保留旧默认模板；不要把空数组误传为清除模板。

每行均返回以下字段，模型提供的同名 key／owner 不具有授权效力：

| 字段 | 合同 |
| --- | --- |
| key | 服务端按该数组顺序生成 `brief-task-1`／`brief-purchase-1`，从 1 起；模型 key 丢弃 |
| title | 1–100 字事项名称，可为需要本人核对的建议 |
| assigneeText | 0–80 字原文称呼；无指定分工为空字符串，不发送成员列表给模型 |
| owner | 当前有效成员 ID、`shared` 或 null；shared 为共同负责，未知／重名为 null，不能静默选择某一人 |
| note / sourceText | 0–500 字；从本项原文完整句重建，不采信模型的预订／已付备注；找不到适用原句则空并提示。完整未识别文字仍在 brief.note |
| checklist.due | 空字符串或 2000–2100 年的真实 ISO 日期 |
| checklist.dueOffsetDays | null 或 -730～366 的整数；负为出发前、正为出发后、0 为出发当天；与非空 due 互斥 |
| shopping.quantity | 0–30 字；未知为空，进入原预览前手工补齐 |
| shopping.budgetCents | null 或 0～100000000000 的整数分，拒绝 bool／float；仅本项明确人民币整项预算 |

模型只收到 `{"request": prompt}`。服务端在模型请求结束后进入原 `authorized(context_snapshot)` 事务，从 `users JOIN household_memberships` 的 active 成员重新核对：原文“我”指当前登录成员；“共同／一起／我们”指 shared；唯一精确显示名指该成员；不存在、重名、已退出成员、不能证明来自本项原句的称呼均保持 null。无指定分工可默认 shared，并在可编辑草案展示；模型不得通过真实 ID 直接指定负责人。出行成员和事项负责人是不同概念，未出行的当前有效成员仍可负责准备。

引用匹配只去掉 `sourceText` 首尾的空白及原文分句符（换行、`;`、`；`、`。`），不删除句内分隔符或拼接多句。模型漏填负责人时，从已匹配原句的明确负责人标注或动作主语保守恢复原文称呼，再用上述当前成员规则核对；多个称呼、未知或重名仍为 null。无适用原句也留 null，不能因模型漏填就把明确的“我”或其他负责人改为共同负责。

本地模式支持每个事项独占换行／分号分隔的一句，使用 `|` 分隔字段，例如：

```text
准备：核对护照 | 负责人：我 | 出发前：3天
准备：打印行程 | 负责人：小林 | 截止日期：2027-09-30
采购：转换插头 | 负责人：小林 | 数量：两只 | 预算：200元
采购：行李牌 | 负责人：共同 | 数量：1个 | 截止：出发前3天
```

本地字段可用“截止日期／截止”、明确“出发前／后 N 天”或“出发当天”；支持 `出发前三天` 等小范围中文整数表达，未识别的相对日期保持空。不把分号后的独立“负责人”行猜接到上一事项；应使用上面的 `|` 格式。重复的同名字段拒绝，未知字段和其他未识别描述保留在原文备注中；本地模式不调用模型。

金额、日期和分工必须由**本项完整原句**支持。服务端将模型引用扩回原始分句，防止截掉“约／不超过／美元”等限定；事项名称必须能与原句对应。一个模型建议引用其他事项或只引用金额时，不据此填入金额、日期或负责人。日期必须明确；相对天数不预先换算为绝对日期。缺截止时保持 `due=""`、`dueOffsetDays=null`，须在表单补齐，不自动使用原向导缺省的 -7 天。

以 `|` 或逗号分隔、带明确标签的预算／数量／负责人／截止字段分别核对限定词：`预算：约200元` 仍为 null，但不擦掉独立明确的负责人和数量；`预约接送` 中的“约”不表示约数。整项动作或未归类的补充文字含否定、换人、冲突或不确定表达时仍保守留待核对，不能靠只截取某个字段绕过原意。

旅行总预算只采信明确的“总预算”，与采购金额分别核对；采购的约数、上限、外币、单价、人均、冲突或未知金额均留 null，不换汇、不按数量乘算、不累加成旅行总额。字面来源检查不是复杂语义正确性的证明，事项始终可编辑并须本人核对。采购本批**没有结构化截止字段**；原文有截止要求时保留在 note/sourceText，同时返回警告，不宣称已随改期联动。

进入 `/api/journeys/preview` 时只映射既有字段：checklist 的 key/title/owner/note 和已补齐的 due 或 dueOffsetDays；shopping 的 key/title/owner/note/quantity，并将 budgetCents 映射为 budget。assigneeText/sourceText/warnings 不是执行授权；不要把它们作为成员 ID 或动作传入。绝对 due 分支省略 dueOffsetDays，未知负责人不得默认给某人。原 preview 重新检查当前有效成员和计划内容，只有原 apply 的明确确认才保存实体；重放原幂等编号不会重复创建，也不会创建云发布队列。

## JavaScript 接缝

`HomeAssistant.openJourney()`：从旅行工作台进入已有助理并聚焦旅行需求，标明“整理旅行简报”。异步打开完成前如页面或身份上下文已替换，不能更改新页面的规划类型。明确的待办、采购或搜索指令始终优先于旅行入口的默认规划类型；输入改变时提交按钮同步显示实际处理类型。

`JourneyUI.openDraft(plan, {expectedContext, sourceForm, isCurrent})`：仅供已登录、非 TV/非 demo 的助理简报桥接；`expectedContext` 含内存中的 identity/CSRF，`sourceForm` 必须是仍连接的 `assistant-journey-form`，`isCurrent` 是调用方的当前操作检查函数。此对象不能序列化存储或发给模型。

桥接拒绝已有 `journey-form`/`journey-review-form`，捕获源表单快照与旅行请求代次，前后读取 `/api/me` 核验同家庭/成员/CSRF。只取 title/start/end/international/budget/memberIds/note/destinations，重建稳定的 `brief-stop-1` 等 key，向 `/api/journeys/preview` 提交**无目标编号**的新计划；得到规范化 plan 后丢弃该次签名预览并打开可编辑向导。用户之后重新预览并明确确认，才使用既有 apply 的幂等事务保存。

新操作、编辑源字段、关闭/返回或进入另一个表单，都会使旧成功和错误失效。503/400/409 等预览错误留在原简报，不覆盖草稿。身份/家庭改变则清理当前旧简报展示。无法撤回已发出的请求；本桥接在确认前只调用读接口和不创建业务实体的预览。
