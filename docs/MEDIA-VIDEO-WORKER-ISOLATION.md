# 视频 worker 的隔离服务接线

可信部署配置 `MEDIA_VIDEO_SOCKET` 指定私有 Unix socket 时，视频 worker 只调用独立解码服务。应用配置优先于环境变量；请求与 Google 元数据不能选择 socket、工具或路径。明确配置了隔离服务后，即使本地提供 FFmpeg 工具，也不会在连接失败、超时或视频错误时回退到持有账户凭据的 worker 内解码。

调用传入原下载 bytes、MIME 和固定 900 秒期限，接收完整 `VideoPreview`。现有下载授权、原选择清单核对、1200 秒视频任务 lease、结果提交前再次核权和原 ID／配额／确认回执保持。成功后释放下载对象，再加密并提交缓存；等待期间取消导入，迟到的成功结果不能保存。

服务失败仍使用现有 `video_tools_unavailable`、`video_timeout` 等固定错误。协议的忙拒绝和超时都使用 `timeout`，本接线不据此自动重试或猜测原因。用户可按导入结果重新选择；不会输出 socket 路径、内部异常或源文件名。

未设置 socket 时保留显式工具路径的本地开发／测试方式。生产启用必须另行提供经过验证的隔离 decoder 容器、私有 socket volume、内存及临时目录限制；本提交没有修改 Compose，也不表示生产服务已经启用。

接线测试使用真实临时 Flask、队列和 SQLite，解码调用为明确的测试替身，覆盖配置优先级、失败不回退、固定错误、源缓冲释放及取消后不保存。它们不代表 Linux Unix socket、真实 FFmpeg 或完整容器资源验收；服务协议与真实 Linux 测试分别记录。
