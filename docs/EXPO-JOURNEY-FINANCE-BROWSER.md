# 本人旅行费用：浏览器验收

本工具为候选，尚未执行。运行须使用经独立审查的完整 API/UI 组合源码，以及该提交的全量 Expo 构建。它复用现有本地 HTTPS、Flask、SQLite 和 Edge 夹具，仅用合成旅行、账单、订单和退款，不连接真实财务、云账号或电视。

三条实际交互路径分别覆盖：

1. 390px：从已保存旅行选择原付款，预览后归集，核对只计本人所选金额、订单及采购/手填已付不重复相加；打开原付款并返回，重启仍保留。之后明确关联跨月退款，原归集显示需核对，调整原关联后恢复。
2. 1280px：服务器真实确认成功后丢弃响应；刷新页面后通过原请求查询恢复。核对一次确认、一个归集和一个操作回执，业务源表不变。
3. 390px：离线隐藏私密草稿，原身份联网恢复；延迟真实读取响应，再实际切换成员，验证旧金额与来源不显示，新成员看不到原关联或回执。

每场景使用独立临时数据库，输出实际 API 操作、合成 SQLite 保全快照、前后源码/导出摘要、两张可见视口截图及清理结果。截图不能证明所有纵向滚动位置或实体设备。跨旅行并发限额、删除后解除、其它家庭与电视拒绝、导出权限由真实 API 专项补充；不把这些未运行的计划写成已通过。

从组合 worktree 运行 `tests/browser_expo_journey_finance_check.py`，参数与既有财务浏览器工具一致：`--source-root`、`--expected-head`、`--bundle`、`--expected-build-evidence`、`--temp-root`；使用 Python `-B -X utf8`。可用 `--case` 精确补验受影响场景，结果必须保留该次选择范围，不累加成一次全量执行。原件保存在新建 `test-results/journey-finance-<UTC>/`，不提交 Git。
