## 1. 手机与电脑登录

1. 用浏览器打开家庭看板，在“家庭成员”中选择自己，再输入自己的家庭密码，点击“进入家庭看板”。
2. 首次使用第三方登录前，先完成家庭密码登录，再绑定自己的 Microsoft 或 Google 账户。绑定成功后，登录页可使用“使用 Microsoft 登录”或“使用 Google 登录”。
3. 电脑从侧栏切换页面；手机底部提供常用入口，“更多”中可以找到采购、旅行、家庭财务、连接中心与设置。
4. 如需修改名称或密码，进入“设置 → 我的账户”。使用公共电脑后，在设置页“退出登录”。

“设置 → 登录设备”已发布并保留。该页面只列出本人的有效浏览器登录；可先确认，再退出指定的其他会话或其他全部会话。当前浏览器继续保持登录，Microsoft／Google 绑定与电视配对保持；退出当前浏览器仍使用设置页底部按钮。时间按当前浏览器时区显示，“上次使用”约每五分钟更新，并非实时在线标记。设备名称只概括浏览器和系统。完整边界见 [成员登录设备](MEMBER-SESSIONS.md)。

你和伴侣应分别使用自己的成员身份。电视使用独立配对，不需要在电视输入家庭密码。“看看演示”使用示例数据，演示里的修改不会保存到真实家庭。

## 2. 看今天，也看整周

进入“日程”，或查看“今日概览”中的日程卡片：

| 视图按钮 | 显示范围 |
| --- | --- |
| 今日 | 默认查看当天安排 |
| 本周 | 查看所在周，比较每天的安排数量与时长 |
| 前后 3 天 | 以当前查看日期为中心，显示前后三天，共七天 |

左右箭头移动日期范围，“回到今天”回到当前日期。点击某一天或“查看全部”可展开完整日程；标题和地点按原日历内容显示。

时长统计合并重叠时间，全天事项单独计数，不计入小时数。它反映已选日历的安排，不代表没有同步的工作量也已纳入。

在看板手动新增的安排可以在看板编辑；从 Microsoft / Google 同步的日程，请在原日历应用修改。若 iPhone 的 Apple 日历中实际使用 Google 或 Outlook 账户，连接对应账户即可；纯 iCloud 日历与 Apple 提醒事项尚未实时接入。

## 3. 共同待办

打开“共同待办”，点击“添加待办”，填写名称、负责人、截止日期等。点击任务前的勾选框完成任务；在“已完成”或“全部”中可以找到并恢复。

新建时若出现“保存到”，先核对选择的是“家庭看板本地待办”还是已连接的云清单。直接保存到云清单的任务可同步新建、完成和恢复；云任务的标题、备注等其他修改请回到 Microsoft To Do / Google Tasks。

本地待办、旅行准备事项和助理生成的待办，不会因为绑定了账户就自动复制到云端。已有本地待办可通过“同步本地待办”明确选择、预览并确认发布；操作路径见第 10 节，真实账号写入仍需本人授权与验收。

## 4. 采购预算与图片

1. 进入“采购 → 添加采购”，填写“物品名称”“数量”和“负责人”。
2. “预计总价”填整项采购预算，不是单价；不确定时留空，系统会显示待填写。
3. 点击“添加图片”上传参考图，最多三张，支持 JPG、PNG、WebP。保存后图片与伴侣及已配对电视共享。
4. 买到后填写“实际总价”，勾选“已买到”。可切换“待采购”“已买到”“全部”查找记录。

预计预算与实付分开统计；实付在已买到后纳入采购汇总。采购估价不会自动变成家庭实际支出，公共资金仍需另外核对。上传失败时先查看表单错误并重试，确认保存成功后再关闭。

### 4.1 用本人付款核对采购实付

1. 在“采购”列表找到物品，点击“核对实付”。也可以从“家庭财务 → 账单与投资 → 账单与订单”的记录行点击“关联采购”。
2. 选择一笔本人的人民币消费付款和一件共享采购。若从订单进入，只显示该订单已核对关联的付款；没有付款时，先点“核对这笔订单的付款”。订单金额本身不证明已经付款。
3. 填写“整项实际总价 · 人民币元”，另行勾选是否“已买到”。该金额会**替换整项实付**，不是加到原值上；付款发生不等于物品已经收到。单笔付款分给采购的金额合计不能超过已核对退款后的净额。
4. 点击“预览共享变化”，核对当前与确认后的实付、买到状态和共享范围；勾选确认说明，再点击“确认这次变化”。预览不会保存，只有最后确认才修改采购。

共享范围只有采购实付和买到状态。付款标题、账户、交易编号及本人关联历史不会因此给伴侣或电视查看；公共余额、私人账本／月预算和旅行“已付款”也不会自动变化。采购实付仍在“已买到”后纳入原采购汇总。此入口不在电视和演示模式启用。

之后可在“本人的已关联记录”更新核对或解除关联。更新沿用原付款；要换付款，先明确解除，再建立新关联。解除默认保留采购当前值；“安全恢复核对前的采购值”只允许在最近一次确认写入后没有被修改时恢复该次确认前值，后来有人修改则拒绝。遇到版本变化，使用“保留草稿，读取最新”，核对后重新预览；不得把失败当作已保存。确认请求发出后，关闭页面不等于取消写入。

付款更正、退款关系变化或来源删除会提示重新核对，不会悄悄重算采购。删除原采购后，旧确认不会把它建回来。规则和数据副本边界见 [采购实付说明](SHOPPING-SETTLEMENT.md) 与 [本人导出](PORTABILITY.md#采购实付关联与回执)。

## 5. 把旅行变成准备清单

旅行详情已支持局部刷新、负责人筛选与发布状态操作，见 [旅行执行说明](JOURNEY-EXECUTION.md)，发布状态以 README 为准。

1. 打开“旅行 → 规划一趟旅行”，在旅行工作台选择“规划下一程”。
2. 填写旅行名称、日期、城市及预算，点击“预览准备与日程 →”。
3. 在“核对旅行联动”检查准备事项、负责人、采购与日程；按实际需要删改。内容变动后先点“更新预览”。
4. 点击“确认生成计划”，才会一起保存旅行、准备待办、采购和本地日程。
5. 之后从“查看行程 → 调整计划”修改；核对预览，再“确认更新计划”。旅行准备和采购可分别勾选完成，图片与实付在采购详情补充。

旅行总预算、“已付款”和“已预留、尚未支付”是不同口径，采购准备属于旅行预算范围，不要重复相加。准备清单只是可修改的计划，不代表预订、签证或付款已经完成。

旅行详情的“同步到云日历”可选择本人绑定的日历，先“预览待发布日程”，再“确认并加入发布队列”。缺少写权限时需本人点击“开启日历写入”并在服务商页面授权。排队成功不等于已发布，应查看“发布进度”；出现云端冲突时使用“对比并处理”。这条路径已上线，真实账号写入仍需本人完成授权与验收。详见 [云日历发布说明](CALENDAR-PUBLISH.md)。

“导出日历 .ics”只是下载文件。删除本地旅行不会自动删除云端事项。

### 5.1 旅行细项 v2：航班、住宿与活动

本节旅行 v2 已随 2026-09-15 02:33:28 版本发布，临时环境浏览器和 Linux 候选测试通过；正式账号新增云写与实体设备另行验收，见 [交接记录](HANDOFF.md)。

在“规划下一程”或“调整计划”中点击“启用旅行细项”。原有日期级分段继续保留，升级只有预览确认后才保存。服务尚不支持时会显示提示并保留草稿，不向旧服务提交新格式。

- **先核对时区。** 填写“家庭参考时区”，并为每个目的地明确选择 IANA 时区，例如 `Asia/Tokyo`、`Pacific/Honolulu`。系统不会只按国家替你推断时区。
- **航班。** 点“+ 航班”，分别填写出发/抵达机场、城市、当地日期时间与各自时区，可补航班号。跨日期线时抵达当地日期可能早于出发日期，预览按真实时刻核对；详情并排显示两端当地时间、必要的家庭时间及真实时长。
- **住宿。** 点“+ 住宿”，填写名称、时区、入住日与退房日。退房日不计住宿晚数，界面显示晚数；未知入住/退房时间留空，不会假定为零点。确知时间时可以补填。
- **活动。** 点“+ 活动”，选择明确起止时刻或“仅知道日期”。日期模式仍需活动当地时区，结束日期不含当天。已有日期级分段也可以显式转换为具体细项，填写并预览后保存，保留原关联 ID。
- **预订状态。** “已订”是本人手工确认，会固定日期；不代表系统核验了订单。“已取消”保留日程与关联并显示取消标记，不向航空公司或酒店执行取消。移除整项则按预览提示保留独立记录，不自动删除云端内容。

整体改期先修改上方出发日期，再展开“整体迁期”，勾选允许移动的项目，点击“按规则迁期所选项目”。只移动已明确允许 `shift_with_trip`、未预订且未取消的项目，按当地日历日期平移并保留钟点；固定、已订和取消项目保持原时间。界面列出每项迁期前后日期与保留项，仍须预览、确认才保存。仅修改旅行总日期不会替你改订航班或酒店。

夏令时切换可能让一个当地时刻不存在或出现两次。不存在时须修改时间；重复时从服务器给出的 UTC 偏移中选择一次，再重新预览。住宿的入住/退房也适用，不会默认猜测其中一次。

预览会提示超出总日期、衔接与需要重新核对的云日历绑定。单独编辑过的日程会显示保留说明；两边同时修改同一字段时，逐项选择保留当前日程或使用旅行草稿，再“更新预览”。时间、时区及其行程说明作为一组处理。选择保留当前日程后，详情显示实际保存时间并提示它与旅行草稿可能不同。

网络失败保留表单。遇到版本 409 时，使用“查看最新版本，保留草稿”，核对后再明确重新预览；不会静默覆盖另一端。演示空间只提供虚构数据和预览，确认保存按钮禁用。旅行新生成的日程与待办仍各自需要云发布预览确认，真实账户写入尚未验收。

### 5.2 编辑准备与采购后返回旅行

本节能力已于 2026-09-15 03:58:15 发布；当前范围与证据见 [交接说明](HANDOFF.md)。

从“旅行计划”打开具体旅行，在“出发准备”点击“编辑”，或在“采购准备”点击“图片 / 详情”。原表单顶部提供“← 返回这次旅行”。保存或明确取消后，会重新读取同一旅行的进度、采购预算与实付，并回到原事项所在区域；可以连续处理下一件采购。原事项已被移除或解除关联时，返回原区域并提示，不会创建替代事项。

直接返回会检查文字、勾选以及采购图片是否改动；仅上传或删除图片也算未保存。上传或保存进行中须等待结果，未保存时先保存或使用原表单“取消”。遇到版本冲突或保存失败，原编辑器及草稿保留；保存成功但读回失败时只显示中性错误页，点击“重新读取这次旅行”核对，不会再次提交保存。

从家庭助理进入旅行时，原有“返回本周待处理”优先：编辑保存或取消后回到助理，避免两个返回入口争抢。返回前会核对当前成员、家庭与会话；切换身份后清除旧旅行上下文，迟到的旧请求不会覆盖新打开的旅行。上下文仅存在本页内存，不跨浏览器刷新恢复。

旅行预算卡片按同一口径区分以下情况，原旅行列表也使用对应标签。金额示例均为虚构：

| 总预算 / 已付款 / 预留未付 | 显示与含义 |
| --- | --- |
| ¥500 / ¥100 / ¥200 | “还需准备 ¥200”：总预算减去已付与预留。 |
| ¥500 / ¥200 / ¥400 | “已付 + 预留超额 ¥100”：预留安排超过剩余预算，尚不代表实际超支。 |
| ¥500 / ¥700 / ¥300 | “已付款超预算 ¥200”：已付已超过总预算；另说明已付与预留合计超额 ¥500，其中 ¥300 尚未付款。 |

采购预算与采购实付是旅行预算内的分项，仍单独核对，不再次加到旅行已付或预留，也不自动写入公共资金、个人账本或投资。

独立验收脚本为 `tests/browser_journey_return_budget_check.py`；它只使用临时 Flask、SQLite、虚构图片和 Edge 本地页面，报告为 `test-results/journey-return-budget-verification.json`。这些结果不代表公网或真实云账号验收。

### 5.3 结构化计划导入与草稿保护

现有入口为“旅行 → 规划下一程 → 已有行程？导入结构化计划”。可选择本机 JSON 文件，或将 JSON 粘贴到文本框，然后点击“读取计划”。导入支持原日期级 v1 与包含当地时间、时区的 v2 计划；仍须在原旅行表单核对目的地、金额与日期，再点击“预览准备与日程”，最后明确确认才创建准备待办、采购及本地日程。导入预览不会自动发布到 Microsoft 或 Google，也不会采用外部文件中的预览签名、操作凭据或目标旅行编号。

本节保护已于 2026-09-15 04:58:08 完成前后端联合验证并发布。点击“更新预览”或“以最新版本重新预览草稿”后，确认按钮会立即禁用；新的预览成功返回后才能确认。若重新预览失败，请保留草稿并重试，旧确认不会恢复可用。

导入文件读取、普通预览、更新预览、启用细项、查看最新版本与按最新版本重预览，都绑定原表单、当前请求、登录身份及输入内容。在等待时关闭、新建另一份草稿、继续修改本页内容或改选文件，迟到的成功与错误不会覆盖新内容。格式、大小、服务暂时不可用和版本冲突会保留仍有效的原草稿供修正；刷新页面仍会丢失未保存草稿。

“确认生成 / 更新计划”在发送前核对身份；已经发送的提交仍可能在服务器完成，关闭窗口或进入新草稿不会撤销它。提交后的状态回读和打开详情也绑定原界面，迟到结果不接管另一份草稿或其确认页；仍停留原表单时，失败重试沿用同一预览凭据及幂等键，避免因响应丢失再次创建。若已离开原表单，请从旅行工作台核对已保存的结果，再决定下一步。

专项脚本为 `tests/browser_journey_import_guard_check.py`（31 项导入）、`tests/browser_journey_draft_guard_check.py`（32 项相邻草稿 / 提交）与 `tests/browser_journey_confirm_guard_check.py`（5 项重新预览确认），报告分别为 `test-results/journey-import-guard-verification.json`、`test-results/journey-draft-guard-verification.json`、`test-results/journey-confirm-guard-verification.json`。新增 5 项在真实本地 HTTP 响应挂起期间核对旧确认禁用、503 保留与重试、新凭证仅保存一次；它未替换原 32 项草稿检查。它们使用临时 Flask、SQLite、虚构数据与本机 Edge，直接断言后端实际默认 `SESSION_REFRESH_EACH_REQUEST=False`，没有测试配置覆盖。该默认值已随前后端一起发布，源码散列记录在报告中；后续移植须保留两部分，不能仅凭前端检查声称会话切换安全。原始 Cookie 回退复现与前端隔离测试报告作为历史证据保留。演示仅供审阅，电视不提供导入编辑入口；这些结果不代表公网或真实云端写入验收。

### 5.4 下载旅行计划示例

本节功能已于 2026-09-15 05:47:43 发布。在“旅行 → 规划下一程 → 已有行程？导入结构化计划”中，可以选择“v1 · 日期级行程”或“v2 · 航班、住宿与活动”，将虚构示例下载为本机 JSON 文件。下载保留当前表单和粘贴内容，不创建旅行；“填入示例”仍可快速填入原有日期级示例。

### 5.5 用文字整理多国多城旅行

本节流程已于 2026-09-15 06:50:21 发布，不需要手写 JSON。

1. 在旅行工作台点击“用文字整理旅行需求”，或在“家庭助理 → 继续规划”选择“规划一次旅行”。写下国家、城市、日期和总预算，再点击“整理旅行简报”。例如“想去日本的东京、京都，再去法国巴黎，日期还没定”也能开始；未明确的信息会留给你补齐。
2. **出行范围：** 填写旅行名称、确切出发与返程日期，并确认国内或境外。不会把“今年”“十二天”自动当作已确认日期。
3. **目的地与停留：** 按顺序填写每站国家、城市、抵达与离开日期，用“+ 下一站”添加城市。同日转场可有日期重叠，但交通安排仍需自己核对。
4. **预算与成员：** 填写明确的人民币家庭总预算，选择出行成员，核对备注并勾选确认。预算未知时留在简报中，明确后才能继续；人均、约数或外币金额不会自动换算为家庭总额。
5. 点击“核对并带入旅行向导 →”。这里仍是可编辑草稿；继续核对准备事项、负责人、采购与日程，点击“预览准备与日程”，最后“确认生成计划”才保存本地旅行和关联事项。

没有配置模型时，可点击“分步填写旅行简报（不调用 AI）”，完整填写同一套三步表单。本地只预填识别到的明确字段，自由描述仍在“原始需求（保留）”中。配置模型后，也只有本人勾选“使用 AI”才发送本次文字；旅行简报不发送共享记录、个人财务或历史对话。AI 整理结果是待核对建议，不能当作已订酒店、航班或已核实价格。

点击“← 返回助理，保留简报”后有两种继续方式：“按当前文字重新整理”使用当前输入，成功后替换旧简报，失败保留新文字和旧简报；“继续已保留的旅行简报”恢复已填写内容和所在步骤，不重新调用模型。即使从旅行入口进入，明确输入“待办：”“采购：”或“搜索：”仍按原清单或搜索流程处理，提交按钮会随输入显示处理类型。

草稿保留在当前页面内存中，刷新、关页或切换身份后不保证恢复。已有另一份旅行草稿正在编辑时，桥接不会覆盖它。网络或预览校验失败时留在原简报修正；新输入、页面或身份变化会使旧响应失效。简报先生成日期级 v1 草稿；需要航班两端时区、住宿退房和定时活动时，在向导中按 5.1 启用旅行细项。创建本地旅行不会自动发布到云日历或主清单。完整边界见 [旅行简报说明](ASSISTANT-JOURNEY-BRIEF.md)；真实模型与云写入尚未验收。

### 6.2 投资持仓整理表：导入、更新与导出

这条流程用于核对本人整理的持仓快照，不连接银行、券商或实时行情。它与“导入数据”中的支付账单、购物订单分开；不要把交易流水直接当作持仓整理表。

1. 打开“家庭财务 → 账单与投资 → 投资账户”，点击“导入 / 更新持仓”。填写来源名称，例如“我的基金账户”；同一来源后续更新继续使用完全相同的名称。
2. 选择本机 CSV、TXT 或 XLSX 文件，再点击“读取并预览”。文件不超过 2 MB、最多 300 项持仓；CSV 可自动识别 UTF-8 / GB18030，也可手选编码。第一次可先“下载虚构示例”，替换示例内容后再选文件，下载本身不会写入持仓。
3. XLSX 的工作表名称留空时，先进入“选择持仓工作表”。这一步只有名称列表，不代表表内记录有效。选择实际持仓表，点击“预览这张表”；空表、说明页、公式或格式错误须按提示修正或换表。已知准确表名也可直接填写，不会自动合并多张表。
4. 在“核对这次持仓变化”比较新增、更新和保持原样的数量，以及每项的当前记录与本次文件。核对名称、机构、资产类型、币种、数量、总成本、总估值和日期；金额按原币种的单位填写，例如 `100.00`，不填整数分或自动换算后的金额。有行错误时不能确认。缺少的文件行会保留原持仓，不等于删除；已有持仓估值留空、日期倒退或疑似重复时先处理提示，不静默覆盖。
5. 勾选“我已核对本人的持仓、金额和更新日期”，再点击“确认更新 · 仅本人”。选择文件、工作表和查看差异都不会更新投资记录；确认后才保存。
6. 成功页显示本次新增、更新和保持数量。点击“返回投资账户”，系统重新读取本人的持仓与按币种汇总，核对保存结果；成功提示不代表银行账户或行情已同步。

**更新已有手工记录：** 先填写来源名称，再点“导出现有持仓”。导出包含该来源和尚未关联来源的本人记录，已归属其他来源的持仓会排除。先删除不属于本次账户的行，再修改金额、日期等；保留系统生成的 `holdingKey`、`recordId` 和文本保护列，重新导入同一来源，才能明确关联原记录。导出及删除文件中的行都不会删除服务器持仓。完整列说明与限制见 [投资持仓导入说明](INVESTMENT-IMPORT.md)。

“返回文件”可修正文件与来源；“重新预览”会立即禁用旧确认，新的差异返回后重新勾选。版本冲突要求重新预览；网络错误后的确认重试沿用原预览凭据，不自动另建一笔。若已关闭窗口，先返回投资账户核对是否保存；关闭窗口不会取消已经发出的确认。切换成员、家庭或原窗口后，旧响应不会接管新页面；无法核对身份时关闭旧文件和预览。原始附件不持久保存，导入记录和导出文件仅本人可见，不进入伴侣或电视的共享财务，也不修改公共荷包或共享资产基线。

### 6.3 确认导入后，直接查看实际月份

确认账单后会显示“导入确认已完成”。如果文件对应一个月份，页面直接打开该月；跨月文件提供各个月份的按钮。重复导入或编号冲突保留原记录时，以实际保存的月份为准。当前月没有账单而其他月有记录时，也可以从月份入口查看，无须再导入一遍。

回执说明确认当时的结果，后来修改或删除的记录以当前账本为准。已显示确认完成但读回暂时失败时，点“重新读取账本”，只重新查看已保存结果，不再次确认。未收到成功响应时先保留原文件和预览，按页面提示核对，关闭窗口不表示服务端没有保存。详见 [账单导入](FINANCE-IMPORT.md)。

### 6.4 只更新我的消费观察

已有财产基线时，在“我的资产与消费观察 → 更新财务来源”选择“仅更新消费观察”，选择本人准备好的更新包。核对报告生成时间、覆盖日期、月份变化和移出窗口项，再勾选确认。它只更新本人的报告观察，资产、负债、收入、共享小计和账本保持原样；报告不等于核对实付。新家庭还没有财产基线时，先完成财产来源核对。本机已准备消费观察更新包，尚未上传或确认导入，也未开启自动上传，详见 [消费观察说明](SPENDING-OBSERVATIONS.md)。

5 分钟是提示阈值，不是同步时效承诺；下次计划时间不证明后台此刻运行。该页面只检查日历／清单及发布记录，不将财务文件或投资估值纳入“正常”来源数量。电视和演示不读取成员详情。

## 家庭例行计划

待办、采购或家庭助理中的“例行计划”可安排保洁、家庭例会和日用品补充。填写内容、负责人、起始日期和每日／每周／每月间隔；采购还可填写数量与整项预算。先核对未来三期和本次将生成的事项，再勾选并确认。系统没有预置计划，未确认创建前不会自动加事项。

完成本期后，系统按原节奏接续一个下一期。修改计划只影响后续生成；已经生成的事项可在原编辑页单独修改。暂停保留现有事项；恢复继续原节奏；“跳过本期”也会保留现有事项，请按预览中的说明处理。删除本期后会显示缺失，系统不会自动恢复它。归档后如需重启，应新建计划。

助理汇总到期和异常计划；每一期采购保留模板预算，实付和照片重新填写。云清单发布逐期使用原预览确认流程。完整规则见 [例行计划](ROUTINES.md)。

例行事项的使用顺序：

1. 确认创建后，从计划详情打开当前事项，在原编辑器调整、上传采购图片或标记完成，再返回原计划核对。更改当前标题或截止日只改本期，未来仍按模板和原节奏生成。
2. 完成本期后，后台下一轮只生成一个下一期；不补齐遗漏历史。31 日起始的月计划在短月取月底，下个长月仍取 31 日。
3. 修改模板或规则只影响未来；暂停不删除当前项，恢复已完成计划才继续推进。归档后保留历史，不能恢复归档。
4. 删除当前项会显示缺失，不自动补建。需要继续时明确预览“跳过本期并保留现有事项”；跳过不代表完成，旧项仍保持原状态。
5. 遇到日期／版本冲突先保留草稿并重新读取；不要重复点击或换一套确认来掩盖不确定结果。达到 2500 条事项或日期上限会显示问题，整理后再核对，不自动删历史。
6. “发布本期待办”只作用于这一条，进入原云发布页后仍须授权、预览和确认；下一期不会自动发布。共享数据副本只有勾选共同记录才包含计划与历史。
