# Expo 旅行页面

本模块提供 React Native / Paper 的旅行列表、详情、创建、编辑、准备清单与采购完成操作。`frontend/src/screens/TripsScreen.tsx` 同时提供默认导出和命名 `TripsScreen`，接收 `ScreenProps`；日期、金额与计划转换位于 `frontend/src/lib/trips.ts`。这里只交付模块，路由与 `HouseholdApp` 的接入由独立集成变更完成。不是发布或实体设备验收记录。

## 页面接缝

- 由已有 `HouseholdProvider`、`PaperProvider` 和外层滚动容器包裹，组件本身不重复创建纵向滚动容器。
- 可选 `tripRequest: {key:number,id?:string}`：新 key 打开新建；id 为实体 `trip.id`，重新读取后进入编辑。不能用工作流 `journey.id` 代替。已有未结束编辑时不接受另一新建请求，不会静默销毁草稿。
- `onEdit('tasks'|'shopping', item)` 打开现有 Paper 单项编辑器；完成动作使用 `useHousehold().mutate`，成功后刷新家庭状态和旅行详情。
- 父组件应按完整 session identity（含 CSRF、auth_version）重新挂载所有屏幕。组件同时检测角色、户、成员、auth_version，并对额外读取执行 `/me → 数据 → /me`，确认 CSRF 与身份均未变化。组件卸载、选择变化后的迟到结果不更新界面。
- 标准 Paper 主题，没有旧绿蓝色、HTML 拼串或独立 CSS；输入框 8px、确认对话框 12px。界面通过真实标题、地点和备注呈现详情，不省略关键文本。

## 实际 API 与保存流程

1. `/journeys` 与 `/journeys/<workflowId>` 提供最新工作流；基础旅行同时来自家庭 state。打开基础记录时重新请求 state，避免拿旧列表记录直接编辑。
2. 新建日期级旅行使用现有 v1：总日期包含返程当天，生成北京时间全天事件。省略 checklist 时由服务端生成国内 5 项／境外 7 项建议；用户可明确切换成自定义清单。预算、已付和准备金以字符串输入，严格转换为整数分，最大 100,000,000,000 分。
3. 编辑保留目的地、任务、采购及分段的稳定 key。既有 v2 计划保留原版本、参考时区和全部复杂分段，不降级。表单准备与采购取最新关联实体可编辑字段，保留成员此前单独修改的标题、截止、数量和预算。开始编辑时记录实体 revision 集合，预览前重新检查；后端 apply 仍负责签名预览所含的全部 entity revision CAS。
4. `POST /journeys/preview` 带完整 plan；工作流更新带 journeyId/revision，基础记录升级带 tripId/tripRevision。升级只明确认领该旅行原有本地准备，不将云任务改成本地，也不删除独立采购。
5. 用户查看新增／更新／移出数量、准备截止及提醒后，明确确认 `POST /journeys/apply`。同一预览持有一个安全随机 idempotencyKey。未知结果锁定草稿，显式“核对原保存”重送完全相同 payload，服务器回执可确认原操作而不重复创建。成功响应必须包含 24 位 hex id/tripId、正安全整数 revision 和布尔 replayed；已知编辑目标还需匹配。畸形成功响应也视为结果未知，不清空草稿或误报保存。
6. 已知版本冲突保留草稿，要求核对最新记录后再编辑，不自动基于新 revision 覆盖。未知结果之后即使得到过期／冲突，也不会改成已知未写入；只允许用户明确关闭并核对列表，不自动生成新预览。原预览最多 30 分钟；凭证仅留在当前组件内存，不写 URL、日志或持久存储。重新加载／离开页面后须先核对列表再新建，这不是跨浏览器会话的操作回执恢复系统。

准备或采购完成提交现有 `/items/<kind>/<id>` PATCH 的 `revision` 和明确 `done`。失败重新读取并要求核对，不对未知写入自动翻转。只读来源不提供完成入口。所有写入使用 `mutate` 的当前成员和 CSRF 复核；TV 不发旅行数据请求。

## 范围与保留入口

新页面可编辑基本安排、目的地、准备与采购项目及 v1 日期级分段；可查看实际已关联本地行程。现有 v2 航班／住宿／时区的复杂编辑、事件三方冲突逐项选择、旅行资料、地图、云发布状态和操作继续使用明确标注的经典页面。这里不将静态 `calendar.cloud` 字段解释成实际云发布状态，也不推断照片关联、到访、共享或 TV 许可。

财务展示只取旅行计划预算及关联采购汇总。采购预算和实付不与旅行已付重复相加，不写任何财务支出。人民币口径来自现有接口，不新增货币换算。旧基础记录升级后才有完整工作流清单；高级能力没有被宣称全部迁移。

## 定向验证

- `node --test tests/test_expo_trips.mjs`：11 项，整数分、日期／闰年／排他日历结束、v2 与实体字段保留、基础记录认领、操作编号、回执格式、成员／TV／户／CSRF／迟到读取。
- `python -m pytest -q tests/test_expo_trips_api.py`：4 项。通过 Node 运行真实 TypeScript 转换器，将虚构表单送入真实 Flask、认证和临时 SQLite；验证创建／原回执重放、已完成准备保留、预览后的冲突，以及他人／TV 不可提交该预览。
- `cd frontend; node node_modules/typescript/bin/tsc --noEmit`：本分支全前端类型检查。

不访问真实云服务、成员数据或生产。上述是 helper 与 API 桥接，不等于已完成接线路由后的真实浏览器、原生设备或部署验证；组合浏览器验收由后续冻结候选单独记录。
