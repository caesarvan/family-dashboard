# React Native 首页与日程

两个屏幕默认导出 `(props: ScreenProps)` 组件，依赖 `frontend/src/lib/types.ts` 的统一契约，不另请求 API、保存会话或复制权限状态。只读 `state` 的家庭安全投影，使用根层传入的真实编辑、完成和模式保存回调。电视不会渲染这两个成员屏幕。

## 页面

- `HomeScreen.tsx`：简短欢迎、添加待办、今日／本周／前后 3 天和成员侧重、安排／到期待办／待采购数量。日程、共同资金、待办、采购、旅行按原 `layout.order/hidden` 显示，默认日程及共同资金优先。待办最多 4 条、接下来的安排最多 3 条、采购最多 3 条、旅行 1 条；更多进入对应工作页。不会从私有财务构造摘要。共同资金未核对时为“待核对”，不伪造零余额。
- `CalendarScreen.tsx`：范围持久化，日期前后导航，七天忙碌分布与所选日全部安排；保留完整标题和地点。选择本地日程直接调用原 `onEdit('events', event)`，任何 `sync` 日程明确只读。新增也直接打开根层编辑器，无旧页中转。
- 所有控件使用 React Native 与 react-native-paper；颜色来自 PaperProvider，卡片／空态／页标题使用设计模块 `ui/components`。Shell 负责纵向滚动、限宽、安全区域，两屏外层只用 View；周分布单独横向滚动。

## 日期和写入边界

`lib/calendar.ts` 是无 IO 的 typed helper：北京时间日期、周一开始的本周、前后各三日、全天结束日期不包含当天；无效／倒置时间不计入安排。跨日时段按当天裁剪，侧重成员与共同安排合并重叠后计算忙碌分钟，全天另计，不把伴侣忙碌时间混进侧重成员。范围总项数按实体去重；七天每格是当天安排数量。

首页到期待办包含截至范围末日的未完成项（包括逾期）；未设日期待办继续显示在有限列表。完成操作带原实体给 `onToggle`，由统一根层执行 revision、CSRF、新鲜身份校验与状态刷新；组件不乐观改状态。执行期间禁用重复操作，错误只显示固定安全提示。身份变化清除局部错误／待处理指示，旧请求结果不更新新成员提示。模式保存同样等待 `setMode`，失败不制造成功视图。

## 检查

`node tests/test_expo_calendar.mjs` 可在支持 TypeScript 类型擦除的 Node 24 执行。覆盖真实日期边界、全天 exclusive end、跨日、重叠合并／家庭成员区别、无效日期、源数据不可变与同步来源只读。

组合时执行 TypeScript 检查及真实临时 Flask／Expo Web 浏览器操作，分别记录依赖组合与服务端操作范围。组件提交本身不是新 Shell 接线、原生手机设备或生产部署验收。
