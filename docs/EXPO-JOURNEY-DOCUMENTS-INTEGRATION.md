# Expo 旅行资料接入

本轮开发候选，尚未部署。该分支以 `ab35be37a06931135d05f2ef886eda98a2db10d3` 为基线，只负责新版入口和导航保护；资料模型与界面由同轮独立分支提供，须组合后验证。

## 入口与返回

- 旅行详情的「旅行资料」打开当前已保存旅行的资料夹，返回时重新读取原旅行。
- 「更多 → 我的旅行资料」打开本人资料库，包含旅行已删除后保留的未关联文件。
- 从地图打开旅行、从助理创建旅行后，复用同一个资料面板；外层保留原地图筛选或助理流程。高级分段仍保留经典入口。
- 路由内只传 `journeyId` 和返回路径，不在 URL 或父组件缓存私人文件、下载地址或资料元数据；每次打开由资料面板核对当前身份并读取。

## 接缝与导航保护

新 `JourneyDocumentsPanel` 接受 `{journeyId?, onBack, onPendingChange?}`。省略 journeyId 为本人资料库；`onPendingChange(boolean)` 覆盖编辑草稿、在途操作和未知提交结果。面板明确放弃或完成后先解除自己的锁，再调用返回。

`ScreenProps.onDocumentsPending` 传递到 HouseholdApp，使用独立 `documents` 来源标识；旧设备、首页布局、外观、旅行改期的清理回调不能解除资料锁。回调同时核对当前完整成员身份和活动路由，真正的身份切换由成员工作区重新挂载清除旧状态。

TripsScreen 只接受当前资料面板的 pending 回调，并在存在资料操作时拒绝另一个旅行请求。地图和助理外层在资料操作尚未处理时保留内存面板；私有视图的前后台／离线隐藏和重新核对由资料组件负责。全局站内导航、浏览器离开提醒沿用原导航保护。

## 验证边界

本接线不改变 API、数据库、文件共享规则或云集成；旧旅行原有凭证保持。应在合入实际模型与面板后执行完整 TypeScript、Expo 构建和临时浏览器验证，覆盖旅行／本人全库两个入口、地图／助理返回、草稿离开保护、身份变化及未知上传恢复。仅提交本接线不能证明上述流程通过，更不代表已发布或本人真实文件已验收。
