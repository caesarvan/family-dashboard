# Expo 本人站内提醒

本页描述独立前端候选，基线 `456585bc1a4f820ca238b3308f09a8d591628f41`，不是上线回执。配套 API 为独立候选；组合、真实浏览器和生产迁移由集成人另行验收。

## 使用

首页选择「我的提醒」。面板默认显示未读，可切换「全部」，每页 40 项。到期日北京时间 09:00 起，分配给本人或共同处理的未完成事项可以出现提醒；没有手机推送承诺。提醒检查有延迟时显示实际检查状态，不把检查时间称作云同步完成时间。

「标为已读」「1 小时后提醒」「明天 09:00 提醒」只改变本人的提醒状态，绝不完成原待办或修改依赖。暂缓时间根据本次列表的服务端时间计算，明确点击即保存一个固定绝对时间；重复核对不会延长它。过期暂缓依据返回的 `status=unread` 展示，即使旧暂缓时间仍存在。

「打开待办」重新读取当前家庭数据，再按原 ID 查找符合本人接收范围、相同截止日的当前事项，以它的真实 revision 和完整字段调用原编辑入口。返回仍在原提醒筛选／页码；后续刷新可显示编辑后的状态。已完成、删除、改负责人、改截止日须重新读取，不从旧提醒投影构造编辑数据。同步清单沿既有原应用修改限制，明确说明，不冒充云编辑。

电视不挂载个人提醒面板，不读取或显示成员的已读／暂缓状态。

## 保存结果不明时

写入之前，浏览器当前标签页保留一个最小恢复信封。断线或 5xx 后禁用新提醒操作；先点「核对操作结果」。找不到回执（404）也不会自动重写，只有本人明确点击「重试原操作」才重发完全相同的 requestId、动作、任务、occurrence、revision 和绝对暂缓时间。

刷新网页后重新进入「我的提醒」，会先核对当前身份，再恢复原筛选／页码并读取原回执。已确认回执后，即使列表 GET 失败，也只重试读取。明确 400／409 等拒绝会说明未保存、清理已确定拒绝的本次记录并读取最新列表；容量拒绝提供联系管理员整理的说明，不静默删除历史或假报成功。

恢复记录只存在同一网站、同一标签页的 `sessionStorage`。仅存操作标识、原任务 ID、不透明 occurrence、版本、动作、绝对时间和筛选页；不存标题、备注、成员资料、原始会话身份或 CSRF。scope 是完整 `sessionIdentity` 的 SHA-256。身份尚未确认时不清理旧记录；身份确认改变／退出后清理旧 scope。存储不可用时禁止开始写入，提示允许此网站存储。该能力不承诺跨设备、关闭标签页后或原生 App 重启恢复；当前无 `sessionStorage` 的 native 环境不会开始提醒操作，后续持久层需单独设计。

## 接缝与权限

- 使用现有 `PlaceFence`：每次列表、回执、写入和打开原事项都在请求前后读取 `/me`，比较完整身份、成员资格和 CSRF。focus、AppState、可见性、联网状态和代次变化让旧响应失效。
- 挂起／离线立即隐藏旧列表，恢复前台后只重新读回。401／403 或身份变化隐藏私人内容并清理旧恢复 UI；切换成员后不会接收前一个成员的迟到结果。
- `GET /api/task-reminders?filter=unread|all&page=N` 读取 40 条；`POST /api/task-reminders/<id>/actions` 使用明确原 intent；`GET /api/task-reminders/operations/<requestId>` 核对最小回执。
- 回执必须匹配原请求 ID、任务、occurrence、动作、原提醒版本 +1 和暂缓时间，才可显示确认。`task.revision` 只用于原事项编辑，外层 `revision` 只用于提醒操作。
- 不改变后端、数据库、依赖、路由、共享主导航规则或发布白名单。首页局部面板复用既有原事项编辑弹窗；`HouseholdApp` 仅增加已确认身份改变后的旧 scope 清理。
