# Expo 家庭例行计划

本轮独立源码候选，尚未组合浏览器验收或部署。界面沿用 Expo 白灰黑层级、Paper 浅深主题和已保存的内容密度；不改原规则计算、调度器或数据库。

## 日常使用

1. 从「更多 → 家庭例行计划」进入。计划对本家庭成员共享，负责人仅表示分工。列表可筛选待办／采购、包括归档，并搜索当前页；每页最多 40 项。
2. 点「新建例行计划」，填写名称、负责人、按天／周／月的间隔、起始日期及备注。采购另填数量和每期预算：留空表示未知，`0` 表示明确为零，最多两位小数。
3. 点「预览例行计划」。核对规则、服务器给出的三期日期、将生成的事项和提示，再点「确认例行计划操作」。预览本身不写业务数据。
4. 在详情查看当前事项及最近十期。点「完成当前待办」或「标记当前采购已买到」只更新当前事项；后继是否生成以重新读取的真实状态为准，不把完成等同付款。
5. 编辑规则只影响未来。暂停、恢复、跳过和归档都先预览再确认；跳过保留原事项，不删除、不标完成。归档保留事项与历史，不能恢复或继续编辑规则。

日期固定按上海计算。过去的起始日期不会补历史；按月从原起始日计算，短月取月底，下个月仍沿原日。最多 100 项未归档计划，事项容量和 2100 年日期上限由服务器核对。

## 失败与恢复

- 版本或依赖冲突：草稿保留。先「读取最新计划」，再明确采用当前计划或「保留草稿重新核对」，重新预览、确认。保留草稿只带入本人修改的字段，其他字段沿用最新规则。
- 确认响应丢失：保留原预览凭证和操作编号。「核对例行操作结果」只读历史回执；暂未查到不证明未执行。「按原请求重试」才会再次提交同一凭证，不自动换预览或重复生成。
- 只有服务器精确返回“过期且未执行”后，才可结束该未知操作、保留草稿重新预览。身份失败、普通 404／409、网络错误或非法回执都不能用来判定旧请求未写。
- 已查到的回执只表示历史执行结果。界面另读当前计划，不恢复后来归档、修改、删除的内容。
- 当前事项勾选结果不明时，只读回当前计划并由用户核对；不会盲目重复 PATCH。
- 同一身份切后台、断网或失焦时隐藏内容并取消异步，内存保留草稿和未知意图。恢复后先重新核身份；真实身份变化清除旧内容。未保存、正在操作或结果未知时锁住跨页导航；明确放弃只撤掉内存草稿，不能撤回已经发送的写入。

计划只生成本地共享事项，不自动发布 Microsoft／Google、购买商品、记私人财务或许可电视访问管理内容。不要在共享模板填写密码、令牌或私人账户资料。

## 开发接缝

- `RoutinesPanel.tsx` 默认导出，props 为 `{kind?: 'tasks'|'shopping', onBack, onPendingChange?}`。未传 kind 默认展示全部；父级负责入口和导航保护，面板自行读取当前完整身份。
- `routines.ts` 定义受限 DTO、精确金额、日期与完整模板验证、冲突字段重合并、请求路径白名单、30 秒超时、4 MB 响应上限及前后身份核验。
- 读取沿用 `GET /api/routines/context?page=&includeArchived=&planId=`，服务端 40 条一页，聚焦记录可额外一条；不叠加客户端子页。三期日期直接显示服务器结果，不重新实现周期数学。
- `POST /preview` 返回原字段以及 `operationKey`；`POST /confirm` 仍只发 `{previewToken}`。未知恢复用 `GET /operations/<operationKey>`。新契约见 [例行客户端 API](EXPO-ROUTINES-API.md)，原规则见 [ROUTINES](ROUTINES.md)。
- 精确 404 code 是 `routine_receipt_not_found`；精确 410 code 是 `preview_expired_unapplied`。只有 mutation 回调内的实际拒绝且后置 `/me` 通过，才可归类为本次明确拒绝；旧未知请求仍保留，除精确 410。
- 完成当前事项复用 provider `mutate('/items/<kind>/<id>','PATCH',{done:true,revision})`，外层再核完整身份；原接口没有完成回执，失败保守进入只读核对。
- 草稿、签名和未知意图不写 URL、localStorage 或日志。请求只允许同源固定路径、禁止重定向；成员／家庭／认证版本／CSRF 均纳入身份签名。旧 epoch 的成功和失败都不能覆盖新界面。
- 所有新按钮操作高度至少 44px，选择使用具备同步 ARIA 与键盘操作的 `SelectionRow`，长静态文字换行。时间面向家庭用户显示中文上海时间，不在正常列表展示 revision。

## 本分支验证边界

- 独立 Node 模型测试实际 14 项通过，验证金额零／未知、月末日期、成员与 Unicode、分页边界、冲突重合并、响应投影、原操作回执匹配、身份代次、精确拒绝与受限传输。TAP 原件位于本分支忽略的 `test-results/routines-model.tap`。
- 曾用已冻结 API `9c440dde` 的真实临时 Flask／SQLite生成两种计划的六类操作，共 12 组 preview／confirm／receipt／context，并交由当前客户端解析通过。虚构数据临时目录已清理，无网络请求。
- 定向 TypeScript 检查只读映射现有物理依赖，不安装依赖、不建 junction、不修改集成树。完整接线、浏览器视觉与实际部署由集成阶段另验。
- 本分支未执行真实家庭计划、云写入、长期 worker 调度、实体手机或电视验收，也未进行任何生产操作。
