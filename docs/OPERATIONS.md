## 只读检查

成员在“设置 → 登录设备”只查看和撤销本人会话；设备描述不是物理身份。出现缺库时保持文件原貌，不用空库补建。恢复备份后必须先对本次恢复家庭执行 [成员失效与检查](MEMBER-SESSIONS.md#恢复后使旧成员登录失效)，再恢复 app/web，人工核对历史队列后才启动 sync；这是数据库恢复的顺序，普通零迁移更新依下方维护窗口执行且不执行全体退出。

```sh
ssh racknerd
cd /opt/family-dashboard
docker compose ps
docker stats --no-stream
curl --fail --silent --show-error https://home.caesarcharles.world/healthz
systemctl list-timers --all 'family-dashboard-*'
journalctl -u family-dashboard-backup.service -n 20 --no-pager
journalctl -u family-dashboard-renew.service -n 20 --no-pager
docker compose logs --tail=80 app sync web
```

主入口 healthz 只证明原家庭应用和数据库可查询，不能证明其他家庭完整。各家庭分别通过其 `/space/<slug>` 入口登录，在「设置 → 账户与自动同步」逐来源核对最近成功、错误和重新授权提示。任务约 30 秒、日历约 60 秒到期检查，失败后退避；新版最多两户并行调度，实际延迟受家庭数量和远端响应影响。页面约 10 秒读取服务器。

旅行详情的云日历发布页区分等待、待授权、已读回成功、重试和冲突；“已入队”不等于云端已创建。已发布记录也定期检查远端删改；冲突时先预览两边，再选择保留云端停止或明确更新，不能清空 ETag 强制重试。详见 [CALENDAR-PUBLISH](CALENDAR-PUBLISH.md)。

本地待办发布使用独立队列，创建结果不明时仅按关联标识查找，不能清空 `attempted` 强行重发。取消后重新选择原账户、原清单，需要再次预览确认恢复绑定；不同目标或已撤回的主清单权限不能借重连恢复。详见 [TASK-PUBLISH](TASK-PUBLISH.md)。

## 发布维护窗口

03:58:15 已发布的 worker 收到 SIGTERM/SIGINT 后停止调度新家庭及后续同步阶段，等待已经开始的 tick 按既有请求超时和事务完成，不终止执行线程。独立 Linux/PID 1 的合成输入验证不能保证所有生产长请求在 Docker 宽限期内结束；当前线上是否具备此能力，以 [部署版本](DEPLOYMENT.md) 为准。

1. 保留在线完整备份、旧源码／镜像和 `.env`，构建候选。隔离 Linux 测试与新容器 Nginx 配置检查通过前，旧服务继续运行；测试不带生产环境或数据卷。
2. 记录旧 web/sync/app 容器 ID，先停止 web 入口，再停止 sync/app，并检查运行状态、退出码与 OOM。确认没有其他容器或维护进程占用数据卷后，记录包含 default 与全部登记家庭、注册目录的停止后摘要，再用标准库 backup.py 生成完整组；逐库核对路径、大小、SHA-256、内容与户映射，不能只看 backup.json 的库数量。
3. 当前库为 43 张户内表。历史 42→42 示例不可使用；本次一次性 42→43 也不能重复执行。后续零结构更新须另行准备并验证 43→43 全表／行／schema／序号保持的检查；当前没有可直接复用的该算法，不能以旧脚本改数字代替。
4. 将来采用相配且已验证的更新流程时，仍须先单独启动 app 并等待健康，在 web/sync 关闭时再次核对数据库、配置和镜像，成功后才开放 sync/web。开放后可能出现新写入，不能盲目用旧快照覆盖。

任一步失败即停止后续步骤。维护窗口内保留即时备份与数据卷，保持旧写入停止；若新服务已部分启动，先停 web，再停新 sync/app 并保全现场后排障。02:33 以前、不支持 `review_required` 和旅行 v2 的 worker 不能接管这些数据。03:11 版本已支持该语义，但尚无本次停止信号处理；任何旧版本都不能在未核对恢复范围时作为自动兜底。若要回到不兼容的旧版本，按 DEPLOYMENT 第 6.2／6.3 节保全残存卷并选择匹配的源码、镜像及完整数据库恢复组，明确数据回退范围；不能只换镜像、清除核对标记或强行降低数据版本。

## 手动备份与续期

```sh
cd /opt/family-dashboard
./deploy/backup.sh
systemctl start family-dashboard-renew.service
journalctl -u family-dashboard-renew.service -n 30 --no-pager
```

新版备份采用 SQLite backup API，先拍平台注册目录，再备份原家庭和目录快照列出的全部子家庭。命令返回 `manifest` 与 `databases`：平台注册目录存在时，快照库数量应等于该目录内家庭数加 1。全部成功才生成 `/data/backups/manifest-<时间>.json`；保留最近 14 个完整组及引用的全部快照。子家庭快照在对应 `spaces/<id>/backups/`，复制一个 manifest 或只有根 `backups/` 都不构成完整平台备份。

每个库单独一致，不是多个库的全局同一时刻。财务、照片、加密凭证及待发布状态均在其中，主 SECRET_KEY 需配套另行保管。同机备份不能覆盖整机或磁盘丢失。更新前若线上仍用旧脚本，使用本次审查过的多家庭备份程序，不靠旧脚本推断已经覆盖全部家庭。

恢复会改变真实数据，按 DEPLOYMENT 第 6.2 节选择完整 manifest、单户或整个平台范围。运行正常且库完整时先在线备份；app 无法启动、缺库或损坏时选 offline 路径，直接使用既有完整组，不以再次在线备份成功为前提。先停备份 timer/service 和 web 入口，再停 sync/app、确认卷无其他容器写入，再在卷外保全残存数据卷（含 WAL/SHM）及当前 `.env`，然后校验路径/散列/库类型/家庭映射。缺失库须由完整平台注册目录及户库恢复，不能把一个家庭复制到另一个 id，或创建空库绕过身份。物理损坏导致目标校验失败时保持停机并在隔离副本处理，不能删掉目标强行继续；生产覆盖恢复尚未演练。

历史库恢复后，先保持服务停止，逐户完成 [旧成员登录失效与检查](MEMBER-SESSIONS.md#恢复后使旧成员登录失效)；全部恢复目标通过后才启动 app/web。检查各户待写队列和真实来源、处理不应继续的旧动作后再启动 sync，并恢复备份 timer 原状态。不要在人工核对前自动运行历史 pending/active 发布记录。

## 常见排障

| 现象 | 检查 |
|---|---|
| 网站 502 | app 健康、Nginx 上游地址、是否刚重建 app |
| 配置更新仍显示旧证书/行为 | 单文件 bind mount 旧 inode；用新容器校验并重建 web |
| 环境变量修改无效 | restart 不重读 .env，需重建容器 |
| 页面旧内容 | 刷新页面后区分断线、未选来源、同步失败 |
| SmartScreen 显示“组织已阻止此内容” | 记录 `browser_environment_blocked`、截图与未执行范围；停止该环境的公网验收，不关闭策略或改变浏览器/访问路线绕过限制。容器内部检查单列，不能替代公网 UI 验收。 |
| OAuth 失败 | 回调、client secret Value、到期、权限、Google 发布状态 |
| 图片失败 | 格式/尺寸、429 解码忙、额度及请求上限 |
| 保存 409 | 版本冲突，读取新版本后重新修改 |
| 电视不能编辑/读私有数据 | 正常权限边界，在本人手机/电脑管理 |
| 新域名身份失效 | Cookie 随域名隔离，登录/配对即可，不重置账本 |
| 恢复后云凭证失效 | SECRET_KEY 是否配套；令牌可能轮换/撤销，需本人重新授权 |
| 某家庭 503 或入口消失 | 注册目录与对应户库是否同时存在；若确实缺库，走 DEPLOYMENT 6.2 offline / platform 恢复路径，不使用主家庭密码或空库补建 |
| 主家庭同步正常、子家庭停滞 | worker 该户阶段日志、对应锁/数据库与来源；每户分别核验 |
| 备份数量少于家庭数加 1 | 是否仍用单户旧脚本；完整 manifest 是否真正生成，失败组不能算成功 |
| 旅行显示待授权/冲突 | 独立写入 scope、日历 ACL、远端 ETag；使用发布页的授权或冲突预览流程 |
| 工作表等待选择 | XLSX 名称留空先列出名单，HTTP 200 不代表记录已校验；选定有效表后再核对金额 | `inspectSheets:true` 不能确认；宏／外链／坏包是硬错误，不用换表绕过 |
| 助理简报缺日期或预算 | 进入三步表单补齐；约数、人均、外币不直接作为人民币家庭总预算 | 模型 502/503 保留输入与旧简报；明确继续已有简报不重调用模型，不直接写旅行 |
| 金额列等待选择 | 多个／同名金额列须先选物理列位置并重新预览；HTTP 200 的 requiresAmountSelection 不是已校验完成 | 改列或改文件后旧签名不可确认；已入账后换列保留旧记录并报告冲突，不能删旧记录绕过去重 |
| 对账请求已发出但结果不明 | 确认／撤销可能已完成；关页不撤销写入 | 原页面重试同一确认凭据或撤销 revision，服务端幂等；重新进入先读回关联状态，不据超时自动新建关系 |
| 财务导入 400/413/429 | 文件/编码/工作表、2 MiB 文件与 3 MB JSON 上限、解析槽；不能直接跳过预览入账 |

普通零迁移更新先停 web，再停旧 sync/app，完成全户备份验证与初始化前后完整摘要比较；新 app 健康且启动读回仍相等后才开放 sync/web。数据库恢复则还须先使旧会话失效、人工核对历史队列后再开 sync。两者都保留相配 `.env` 与整棵数据卷，不能混用顺序。若已经创建子家庭，不能为了回退前端而直接换回只支持单户的旧镜像；旅行 v2／核对队列同样需要相配的代码和恢复策略。不要把 down -v、重置密码或恢复旧库作为常规排障第一步。

## 家庭例行计划运行与排障

worker 每户按 `task_publish → calendar_publish → cloud_accounts → household_routines` 四阶段执行，最多两个家庭并行；阶段前检查停止标记，已进入的事务允许收尾。例行 tick 不发网络，不调用默认主清单写入器；无计划、未完成、缺失、暂停或容量／日期阻塞时不持续写审计或 meta，也不抢写锁推进。

- 当前事项已完成而新期暂未出现：先在例行页刷新，核对计划是否 active、worker 是否运行、当天日期与容量；不要直接插库或清回执。只有一个后继，不补历史。
- missing：原实体已删除，GET 不复活；成员可明确预览并确认 skip。跳过保留现有事项，不伪称完成。
- capacity_blocked／exhausted：整理原事项或核对日期上限；不能自动删旧数据或放宽 2100 上限。暂停／归档保留当前实体及历史。
- 当前项独立编辑：模板和原 scheduledOn 不随修改改变；更新规则只影响未来。跨版本冲突保留草稿重预览，成功响应丢失时用原 token 查回执。
- 备份与恢复：完整备份包含三张例行表；恢复后先使目标家庭旧会话失效，人工核对 current／历史以及云发布队列，再开放 sync。不要在恢复后直接补齐或自动云发布历史期次。

仅安装空表不会生成事项；用户尚未建立计划时无例行业务。六个既有来源的自然读取与例行规则推进是不同证据，不能据前者认定后者长期运行或每期云写已经验收。历史例行迁移为 37→40，2026-09-15 15:10 的历史消费观察迁移为 40→42；当前 43 表后续无结构变化更新须另行验证 43→43，DEPLOYMENT 第 5.2 节仅保留历史 42→42，不能重放历史迁移或放宽断言。
